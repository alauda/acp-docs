# Alauda OS Support Matrix

This document lists the versions of Kubernetes components included in different Alauda OS images.

## CPU Baseline

ACP-provided Alauda OS images on x86_64 require CPUs that meet the `x86-64-v2` ISA baseline. x86_64 hardware that does not support `x86-64-v2` is outside the supported baseline for these images.

This requirement applies when you create or upgrade cluster nodes with ACP-provided Alauda OS images.

## Downloading Alauda OS \{#downloading-alauda-os}

Download the Alauda OS image for your ACP release from the OS download page in Customer Portal. That page is the authoritative list of the images published for each ACP release; image file names are not reproduced here. The infrastructure provider version, the Alauda OS image version, and the ACP version must match.

An ACP release can publish more than one image — one per architecture, and from ACP v4.4.0 more than one OS variant. Every image published for the same ACP release contains the component versions listed in that release's row below, so select the download by your node architecture and by the artifact format your provider requires. See [Image Format by Provider](#image-format-by-provider).

## Image Format by Provider \{#image-format-by-provider}

An Alauda OS image is published in different formats. Choose the format that matches your infrastructure provider when you download the image and upload it to the target platform:

| Provider | Image format |
| :--- | :--- |
| Huawei DCS | `qcow2` |
| Huawei Cloud Stack (HCS) | `qcow2` |
| VMware vSphere | `ova` |
| Bare metal | Archive of an OCI image layout holding two images |

For the virtual-machine providers, the format does not change the OS content — it only changes the packaging for the target platform. Select the entry on the download page that matches your provider.

Bare metal is packaged differently. Its download is a `.tar` archive of one OCI image layout that holds two images under the same tag, rather than a single bootable OS file. Import both images into the target platform registry and add the Kubernetes version to the image catalog, as described in [OS Images Imported and Image Catalog Populated](../workload_clusters/alauda_os/bare-metal/create_cluster.mdx#os-images-and-image-catalog):

| Image | Used by | Purpose |
| :--- | :--- | :--- |
| OS image (`base-image`) | `elemental-image-catalog` | Reprovisions a registered host with the Kubernetes-specific root filesystem. |
| OS ISO image (`base-image-iso`) | `SeedImage.spec.baseImage` | Builds the live ISO used for initial host installation and registration. |

The ISO that each host boots from is built on site by `elemental-operator` from `base-image-iso`, and is not part of the download. See [Create a Cluster on Bare Metal](../workload_clusters/alauda_os/bare-metal/create_cluster.mdx).
