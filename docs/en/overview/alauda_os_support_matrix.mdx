# Alauda OS Support Matrix

This document lists the versions of Kubernetes components included in different Alauda OS images.

## CPU Baseline

ACP-provided Alauda OS images on x86_64 require CPUs that meet the `x86-64-v2` ISA baseline. x86_64 hardware that does not support `x86-64-v2` is outside the supported baseline for these images.

This requirement applies when you create or upgrade cluster nodes with ACP-provided Alauda OS images.

## Downloading Alauda OS \{#downloading-alauda-os}

Download the Alauda OS image for your ACP release from the OS download page in Customer Portal. That page is the authoritative list of the images published for each ACP release; image file names are not reproduced here. The infrastructure provider version, the Alauda OS image version, and the ACP version must match, except during an upgrade, when nodes also use the images of intermediate Kubernetes versions, as described in [ACP Version and Kubernetes Version](../upgrade/overview.mdx#distribution-version-vs-kubernetes-version).

An ACP release can publish more than one image — one per architecture, and from ACP v4.4.0 more than one OS variant; see [OS Variants](#os-variants). Every image published for the same ACP release contains the component versions listed in that release's row below, so select the download by your node architecture and by the artifact format your provider requires. See [Image Format by Provider](#image-format-by-provider).

## OS Variants \{#os-variants}

The variant of an image is part of its name, for example `m55` in `alaudaos-45.m55.<timestamp>-0`. Alauda OS KO and Alauda OS KU are the Alauda OS K variants.

| Variant | Code in the image name | Bare Metal | Huawei DCS | Huawei Cloud Stack | VMware vSphere |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Alauda OS M55 | `m55` | Supported | Supported | Supported | Supported |
| Alauda OS KO | `ko` | Not supported | Supported | Supported | Supported |
| Alauda OS KU | `ku` | Supported | Supported | Supported | Supported |

- **Huawei DCS**: for a template of an Alauda OS K variant, set `provider.dcs.osType: alaudaos-k`; see [Alauda OS K Templates](../install/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#alauda-os-k).
- **Huawei Cloud Stack and VMware vSphere**: every variant works without a setting.
- **Bare Metal**: the OS of a host is the `os.baremetal.alauda.io/id` label of its registration, `alaudaos.m.55` for Alauda OS M55 and `alaudaos.k.25` for Alauda OS KU. See [OS Image Keys per Architecture and OS](../workload_clusters/alauda_os/bare-metal/prerequisites.mdx#catalog-key-format).

## Mixed Architecture within a Cluster \{#mixed-architecture}

| Provider | Mixed architecture within one cluster |
| :--- | :--- |
| Bare Metal | Supported with Alauda OS KU; not supported with Alauda OS M55 |
| Huawei DCS | Supported |
| Huawei Cloud Stack | Supported |
| VMware vSphere | x86_64 only |

In a cluster that mixes architectures, every VM template or image ConfigMap must set `architecture`; see [VM Template ConfigMap](../workload_clusters/alauda_os/huawei-dcs/prerequisites.mdx#vm-template-configmap) for Huawei DCS and [Image ConfigMap](../workload_clusters/alauda_os/huawei-cloud-stack/prerequisites.mdx#image-configmap) for Huawei Cloud Stack.

## Image Format by Provider \{#image-format-by-provider}

An Alauda OS image is published in different formats. Choose the format that matches your infrastructure provider when you download the image and upload it to the target platform:

| Provider | Image format |
| :--- | :--- |
| Huawei DCS | `qcow2` |
| Huawei Cloud Stack (HCS) | `qcow2` |
| VMware vSphere | `ova` |
| Bare metal | Archive of an OCI image layout holding two images |

For the virtual-machine providers, the format does not change the OS content — it only changes the packaging for the target platform. Select the entry on the download page that matches your provider.

Bare metal is packaged differently. Its download is a `.tar` archive of one OCI image layout that holds two images under the same tag, rather than a single bootable OS file. Import both images into the target platform registry and add the Kubernetes version to the image catalog, as described in [OS Images and Image Catalog](../workload_clusters/alauda_os/bare-metal/prerequisites.mdx#os-images-and-image-catalog):

| Image | Used by | Purpose |
| :--- | :--- | :--- |
| OS image (`base-image`) | `elemental-image-catalog` | Reprovisions a registered host with the Kubernetes-specific root filesystem. |
| OS ISO image (`base-image-iso`) | `SeedImage.spec.baseImage` | Builds the live ISO used for initial host installation and registration. |

The ISO that each host boots from is built on site by `elemental-operator` from `base-image-iso`, and is not part of the download. See [Create a Cluster on Bare Metal](../workload_clusters/alauda_os/bare-metal/create_cluster.mdx).
