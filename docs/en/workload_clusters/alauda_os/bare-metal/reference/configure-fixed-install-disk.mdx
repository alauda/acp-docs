# Choose the System Disk of Bare-Metal Hosts

A host that boots the ISO reports its disks to its `MachineInventory` and waits until its system disk is chosen. [Create a Cluster](../create_cluster.mdx#build-iso) shows how to choose the disk of each host. This page covers who may choose it, how to choose it by a rule instead of host by host, and what to do when a host does not start installing.

## Who May Choose the Disk \{#permission}

The installation formats the disk that you choose. The account that sets the `baremetal.alauda.io/install-target-device` annotation needs `patch` on `machineinventories` and `update` on `machineinventories/installtarget`. If the annotation is rejected for lack of permission, bind the ClusterRole `baremetal-install-target-approver` to the account:

```bash
ac config use-cluster global
ac -n cpaas-system create rolebinding <name> \
  --clusterrole=baremetal-install-target-approver --user=<user>
```

## Choose the Disk by a Rule \{#choose-by-rule}

When the hosts have the same disk layout, a rule in the `MachineRegistration` chooses the disk of every host, and no host waits. In place of `device-selection: inventory`, write a `device-selector` that matches exactly one disk of each host:

```yaml title="MachineRegistration install settings"
spec:
  config:
    elemental:
      install:
        device-selector:
        - {key: Model, operator: In, values: ["SAMSUNG MZ7LH480"]}
        - {key: Size, operator: Lt, values: ["1Ti"]}
        eject-cd: true
        reboot: true
```

Each requirement has a `key`, an `operator`, and `values`, and all requirements must hold:

| Key | Operators | Values |
|---|---|---|
| `Name`, `ID`, `WWN`, `Serial`, `Model`, `Transport` | `In`, `NotIn` | The values to match. |
| `Rotational` | `In` | `"true"` or `"false"`. |
| `Size` | `Gt`, `Lt` | One quantity, such as `1Ti`. |

`install.*` is read when a host registers, so a change applies to the next host that registers; you do not need to build the ISO again.

## Troubleshooting \{#troubleshooting}

| Symptom | Cause and action |
|---|---|
| A host stays `AwaitingTarget`. | Choose its system disk as described in [Create a Cluster](../create_cluster.mdx#build-iso). The installation does not start without it. |
| The `install-target-device` annotation is rejected. | Read the message. If it names a missing permission, see [Who May Choose the Disk](#permission). Otherwise it lists the accepted disk IDs: copy the ID from `status.install.candidates[].id`, and do not use a device path such as `/dev/sda`, or a `wwn:0x…` form. |
| A host does not start the installation after you chose its disk, and `status.install.staleSystemDisks` lists a disk as `Blocked`. | That disk has an earlier Alauda OS installation and other partitions, so the installation stops rather than wipe it; its `reason` says why. Move the data off the disk and wipe it from the host console, or choose that disk as the system disk, then boot the host from the ISO again. |
| A host does not start the installation with a `device-selector`. | The rule matches no disk, or more than one. The log of `elemental-register-install.service` on the host lists the disks it found. Correct the rule; it applies to the next registration, so boot the host from the ISO again. |
| A host is back in `AwaitingTarget`, and `status.install.message` says the install did not complete; the `MachineInventory` has an `InstallInterrupted` event. | The host restarted during the installation, for example after a power loss. Choose its system disk again. |
| A host is back in `AwaitingTarget`, and `status.install.message` says it booted the live ISO again after the install completed. | The ISO is still attached. Eject it and boot the host from disk; the installed system is kept. To install again instead, choose a disk. |
| Registration works in the live ISO, but the installed host has no network after reprovision. | Diagnose the cloud-init and NetworkManager activation of the installed system separately. The network profile that you configured in the live ISO is temporary and does not prove that the persistent reprovision network works. |
