# Create a Cluster on Bare Metal
ACP CLI (ac) renders the cluster objects from one `install-config.yaml`, applies them to the `global` cluster, and the Bare Metal provider builds the cluster from the hosts in your pools. Before that, you register the hosts and collect them into one `MachineInventoryPool` per node group; `ac` does not do either. Every object lives in the `cpaas-system` namespace of the `global` cluster.

## Prerequisites

- You meet the [Bare Metal prerequisites](./prerequisites.mdx).
- `ac` is logged in to the platform as a platform administrator (`ac login https://<platform-address> --name <session-name>`).
- You chose the cluster name. It **must not** be `global` or start with `global-`. Use it as the prefix of the registration and the pools.

| Placeholder | Value |
|---|---|
| `<cluster-name>` | The workload cluster name, later `cluster.clusterName`. |
| `<registry-address>` | The `registry` key of `cpaas-system/public-registry-credential` on the `global` cluster. After `ac config use-cluster global`: `ac -n cpaas-system get secret public-registry-credential -o jsonpath='{.data.registry}' \| base64 -d` |
| `<base-image-iso>` | `<registry-address>/tkestack/baremetal-base-image-iso:<os-image-tag>`, from [OS Images and Image Catalog](./prerequisites.mdx#os-images-and-image-catalog). |
| `<os-id>` | The OS identifier of the image that the registration installs: `alaudaos.m.55` for Alauda OS M55, `alaudaos.k.25` for Alauda OS KU. See [OS Image Keys per Architecture and OS](./prerequisites.mdx#catalog-key-format). |

## Procedure

### 1. Create the Registration and the ISO \{#step-1-machineregistration-seedimage}

Write a `MachineRegistration`, which describes the registration and the first-install configuration, and a `SeedImage`, which builds the ISO from `<base-image-iso>`. Take `<base-image-iso>` from the same OS archive as the `baremetal-base-image` in the image catalog.

```yaml title="01-machineregistration-seedimage.yaml"
apiVersion: elemental.cattle.io/v1beta1
kind: MachineRegistration
metadata:
  name: <cluster-name>-registration
  namespace: cpaas-system
  labels:
    app.kubernetes.io/part-of: cluster-api-provider-baremetal
spec:
  # ${...} placeholders are expanded by elemental-register from SMBIOS data.
  machineName: "<cluster-name>-${System Information/UUID}"
  machineInventoryLabels:
    app.kubernetes.io/part-of: cluster-api-provider-baremetal
    pool.baremetal.alauda.io/eligible: "true"
    elemental.cattle.io/serial-number: "${System Information/Serial Number}"
    # Architecture of the host, reported by elemental-register. Keep the value as is.
    os.baremetal.alauda.io/arch: "${Runtime/Architecture}"
    # OS identifier of the image this registration installs.
    os.baremetal.alauda.io/id: <os-id>
  machineInventoryAnnotations:
    elemental.cattle.io/machine-uuid: "${System Information/UUID}"
  config:
    elemental:
      install:
        # Each host reports its disks and waits until you select its system disk.
        device-selection: inventory
        eject-cd: true
        reboot: true
        snapshotter:
          type: btrfs
          maxSnaps: 4
      registration:
        # Each host uses its hardware TPM when usable, otherwise an emulated one.
        tpm-mode: auto
        emulated-tpm-seed: -1
---
apiVersion: elemental.cattle.io/v1beta1
kind: SeedImage
metadata:
  name: <cluster-name>-registration-iso
  namespace: cpaas-system
  labels:
    app.kubernetes.io/part-of: cluster-api-provider-baremetal
spec:
  type: iso
  baseImage: <base-image-iso>
  registrationRef:
    apiVersion: elemental.cattle.io/v1beta1
    kind: MachineRegistration
    name: <cluster-name>-registration
    namespace: cpaas-system
  targetPlatform: linux/amd64
  size: 20Gi
  cleanupAfterMinutes: 120
  cloud-config:
    stages:
      boot:
        - name: "Size COS_STATE for reprovisioning"
          files:
            - path: /etc/elemental/config.d/partitions.yaml
              permissions: 0644
              content: |
                install:
                  partitions:
                    state:
                      size: 20480
```

- Keep `device-selection: inventory`, `eject-cd: true`, and `reboot: true`: a host installs only to the disk you select in [Select the System Disk](#select-system-disk), and without the other two it can stay in the live environment.
- Keep the `os.baremetal.alauda.io/arch` and `os.baremetal.alauda.io/id` labels in `machineInventoryLabels`: the provider uses them to find the image catalog key of each host; see [OS Image Keys per Architecture and OS](./prerequisites.mdx#catalog-key-format).
- Do not annotate a workload `MachineRegistration` with `baremetal.cluster.io/system-agent-auth-scope: global`; that marks `global` hosts.
- Do not add `/etc/resolv.conf` to `SeedImage.spec.cloud-config`. Put site-specific resolver configuration in `MachineRegistration.spec.config.cloud-config` only when first-boot registration needs it.

#### Size COS_STATE \{#size-cos-state}

Keep the `state` partition size of the `SeedImage` above, 20480 MiB. With the Elemental default of 8192 MiB, a later cluster upgrade fails with `no space left on device`, and the size cannot be changed after the host is installed.

<Directive type="warning" title="Placement and stage both matter">
  The fragment must sit in `SeedImage.spec.cloud-config` under `stages.boot`. In `MachineRegistration.spec.config.cloud-config`, or under any other stage, the partition stays at 8 GiB and nothing reports an error.
</Directive>

### 2. Build the ISO and Boot the Hosts \{#build-iso}

Run the following commands from a machine where `ac` is logged in to the platform:

```bash
ac config use-cluster global
ac apply -f 01-machineregistration-seedimage.yaml
ac -n cpaas-system wait --for=condition=SeedImageReady=True \
  seedimage/<cluster-name>-registration-iso --timeout=30m
ac -n cpaas-system get seedimage <cluster-name>-registration-iso \
  -o jsonpath='{.status.conditions[?(@.type=="SeedImageReady")].reason}{"\n"}{.status.downloadURL}{"\n"}{.status.checksumURL}{"\n"}'
```

Continue only when the reason is `SeedImageBuildSuccess` and both URLs are non-empty. After `cleanupAfterMinutes`, the URLs are cleared while `SeedImageReady` can stay `True`; check the reason again before you download the ISO. To get a new URL, delete the `SeedImage`, apply the file again, and repeat the commands above from `wait`:

```bash
ac -n cpaas-system delete seedimage <cluster-name>-registration-iso
ac apply -f 01-machineregistration-seedimage.yaml
```

Hosts that have already booted the ISO keep registering; boot the remaining hosts from the new ISO.

#### Verify the ISO \{#verify-iso}

The checksum file holds the SHA-256 hash and the original file name of the ISO. The original name contains colons, which Windows does not allow, so the saved file often has another name and `sha256sum -c` cannot find it. Compare the hashes instead:

```bash
curl -sSk <checksum-url> | awk '{print $1}'    # expected hash
sha256sum <saved-iso-file> | awk '{print $1}'  # actual hash
```

Continue when the two hashes are the same; otherwise download the ISO again. On Windows, `certutil -hashfile <saved-iso-file> SHA256` prints the actual hash.

Boot every host from the ISO. Each host registers as a `MachineInventory`, reports its disks, and waits in the live environment until you select its system disk. If the live ISO has no DHCP address, configure the network from the host console as in [Network Connectivity](./prerequisites.mdx#network-connectivity).

#### Select the System Disk \{#select-system-disk}

Every host waits for a selection, including a host with a single disk. List the hosts and the disks that a waiting host reports:

```bash
ac -n cpaas-system get machineinventories.elemental.cattle.io \
  -o custom-columns='NAME:.metadata.name,PHASE:.status.install.phase'
ac -n cpaas-system get machineinventories.elemental.cattle.io <inventory-name> \
  -o jsonpath='{range .status.install.candidates[*]}{.id}{"\t"}{.eligible}{"\t"}{.path}{"\t"}{.sizeBytes}{"\t"}{.reasons}{"\n"}{end}'
```

A waiting host shows `AwaitingTarget`. Each candidate line prints the disk ID, whether the disk can be selected, its device path in the live environment, its size in bytes, and the reasons when it cannot be selected. Identify the system disk by its size and path, and select it by its ID while the host is still in the live environment:

```bash
ac -n cpaas-system annotate machineinventories.elemental.cattle.io <inventory-name> \
  baremetal.alauda.io/install-target-device=<disk-id>
```

- Select a disk that shows `true`, using its ID exactly as printed.
- The phase changes to `Installing`, and the host installs Alauda OS to that disk and reboots. The selection cannot be changed after that.
- If the annotation is rejected because the host was not seen recently, make sure that the host is still running the ISO, and run the command again.

### 3. Confirm the Registration \{#confirm-registration}

```bash
ac config use-cluster global
ac -n cpaas-system get machineinventories.elemental.cattle.io \
  -L os.baremetal.alauda.io/arch,os.baremetal.alauda.io/id
```

Use an inventory only when it:

- Shows `Ready=True`, `status.install.phase=Installed`, and a non-empty `status.plan.secretRef.name`.
- Shows the `os.baremetal.alauda.io/arch` and `os.baremetal.alauda.io/id` labels that you set in the registration. A host without them is treated as `amd64` with Alauda OS M55.
- Has a `spec.observedNetwork` that matches the host's expected NIC, when the install-time IP must survive reprovisions.
- For managed data disks, runs an observer-capable OS image, reports a fresh `status.observedStorage`, and reaches `status.storage.phase=Prepared`.

Record the exact `MachineInventory` names for the pools.

### 4. Optional: Prepare Managed Data Disks \{#optional-prepare-managed-storage}

Managed storage belongs to the long-lived `MachineInventory`, so configure it while the inventory is unallocated, before you add it to a pool. Follow [Manage Data Disks on Bare-Metal Hosts](../../../configure/nodes/alauda_os/manage-bare-metal-storage.mdx) to verify `elemental-storage-observer.service`, select each device by a stable ID with `Adopt` or `InitializeIfBlank`, patch the declaration with `storagectl`, and wait for `StoragePrepared=True/AllRequiredVolumesPrepared` and `status.storage.phase=Prepared`. Then return to [Create the Pools](#step-2-pools).

Without managed disks, leave `spec.storage` absent or set `volumes: []`; the inventory converges to `Unmanaged` with `StoragePrepared=True/NoManagedVolumes`.

### 5. Create the Pools \{#step-2-pools}

Create one pool for the control plane and one for each worker node group; two node groups cannot share a pool, and a `MachineInventory` must not appear in two active pools.

```yaml title="02-machineinventorypool.yaml"
apiVersion: infrastructure.cluster.x-k8s.io/v1beta1
kind: MachineInventoryPool
metadata:
  name: <cluster-name>-control-plane-pool
  namespace: cpaas-system
spec:
  clusterName: <cluster-name> # [!code callout]
  machineInventories:
    - name: <control-plane-inventory-1> # [!code callout]
      hostname: <control-plane-host-1> # [!code callout]
    - name: <control-plane-inventory-2>
    - name: <control-plane-inventory-3>
---
apiVersion: infrastructure.cluster.x-k8s.io/v1beta1
kind: MachineInventoryPool
metadata:
  name: <cluster-name>-worker-pool
  namespace: cpaas-system
spec:
  clusterName: <cluster-name>
  machineInventories:
    - name: <worker-inventory-1>
    - name: <worker-inventory-2>
    - name: <worker-inventory-3>
```

<Callouts>

1. `clusterName`: the workload cluster this pool serves.
2. `name`: the exact `MachineInventory` name.
3. `hostname`: optional. Applied at reprovision; defaults to the inventory name.

</Callouts>

```bash
ac config use-cluster global
ac apply -f 02-machineinventorypool.yaml
ac -n cpaas-system get machineinventorypools.infrastructure.cluster.x-k8s.io \
  -o custom-columns='NAME:.metadata.name,READY:.status.conditions[?(@.type=="Ready")].status,TOTAL:.status.total,AVAILABLE:.status.available'
```

Continue when each pool shows `READY` `True` and `TOTAL` equals the number of listed inventories; otherwise read the pool's `MembersValid` condition and see [Provider Conditions](./troubleshooting.mdx#provider-conditions).

Size each pool to at least the `replicas` of its node group: an upgrade replaces each node with a host from the same pool.

#### Pool Capacity \{#worker-pool-capacity}

```bash
ac config use-cluster global
ac -n cpaas-system get machineinventorypools.infrastructure.cluster.x-k8s.io <cluster-name>-worker-pool
```

`status.available` must be at least the target replica count. For more capacity, register more hosts, prepare any managed storage while each inventory is unallocated, and add their names to `spec.machineInventories`. A new host goes through the same first boot as the original nodes, so confirm its [network paths](./prerequisites.mdx#network-connectivity) and [clock](./prerequisites.mdx#host-time-synchronization) as well.

### 6. Write `install-config.yaml` \{#write-install-config}

Create an installation directory for the cluster and write `install-config.yaml` in it. `ac` writes `manifests/` and `logs/ac.log` next to it.

Copy the following template and fill in the placeholders. The numbered lines are specific to Bare Metal and are described below the template; for the other fields, see [Common `install-config.yaml` Fields](../reference.mdx#install-config). For the objects that `ac` renders from this file, see [Rendered Manifests](./reference/install-config-parameters.mdx).

```yaml title="install-config.yaml"
cluster:
  clusterName: <cluster-name>
  sshKeys:
    - <ssh-public-key>
  # registrySecretRef:
  #   name: <registry-secret-name>
  #   namespace: cpaas-system
  # encryptionProviderConfig: <encryption-key>
  ntpServers: []
  network:
    podCIDR: 10.199.0.0/16
    serviceCIDR: 10.96.0.0/12
    kubeOVN:
      joinCIDR: 100.64.0.0/16
    loadBalancer: # [!code callout]
      type: internal
      address: <control-plane-endpoint>
      port: 6443
      vrid: <vrid>

controlPlane:
  replicas: 3
  baremetal:
    machineInventoryPool: <cluster-name>-control-plane-pool # [!code callout]

computes:
  - name: worker
    replicas: 3
    baremetal:
      machineInventoryPool: <cluster-name>-worker-pool # [!code callout]
```

The numbers in the table match the numbers in the template.

On Bare Metal, the hosts supply the size, network, and disks of every node, so a node group takes only `replicas` and `baremetal.machineInventoryPool`; data disks are declared on the `MachineInventory`, see [Prepare Managed Data Disks](#optional-prepare-managed-storage). Writing `cpuCore`, `memoryGiB`, `network`, `disks`, or `hosts` in a node group, `provider.baremetal`, or `credentialRef` is an error that names the field.

You do not set the Kubernetes version: `ac` installs the latest version that the platform supports, and the image catalog must have its key for the architecture and OS of your hosts; see [Add Kubernetes Versions to the Image Catalog](./prerequisites.mdx#add-versions-to-image-catalog).

### 7. Create the Cluster \{#create-with-ac}

Run the following command from a machine where `ac` is logged in to the platform:

```bash
ac config use-cluster global
ac adm alpha cluster create --dir <install-dir> --provider baremetal
```

`ac` first checks the provider CRDs on the `global` cluster, the pools and their size, and the registry. If a check fails, nothing is changed and the error names the item. Make sure that each pool has enough available hosts; see [Pool Capacity](#worker-pool-capacity).

`create` returns once the objects are applied, and the cluster keeps building. Add `--wait` to wait until all stages are ready; `--timeout` (default `2h`) limits only the wait. To render without applying, run `ac adm alpha cluster manifests` with the same flags.

### 8. Monitor the Creation \{#monitor-creation}

```bash
ac config use-cluster global
ac adm alpha cluster status --cluster <cluster-name>                      # prints the four stages once
ac adm alpha cluster wait-for install-complete --cluster <cluster-name>   # waits until all four are ready
```

Continue when all four stages are ready; otherwise see [Troubleshooting](./troubleshooting.mdx).

### 9. Verify the Cluster \{#verify-the-cluster}

Run the following commands from a machine where `ac` is logged in to the platform:

```bash
ac config sync
ac config use-cluster <cluster-name>
ac get nodes
ac config use-cluster global
```

Continue when every node is `Ready`; otherwise see [Troubleshooting](./troubleshooting.mdx).

#### Hosts and Pools \{#verify-hosts-and-pools}

```bash
ac config use-cluster global
ac -n cpaas-system get baremetalmachines.infrastructure.cluster.x-k8s.io
ac -n cpaas-system get machineinventorypools.infrastructure.cluster.x-k8s.io \
  -o custom-columns='NAME:.metadata.name,READY:.status.conditions[?(@.type=="Ready")].status,TOTAL:.status.total,AVAILABLE:.status.available'
```

Continue when every `BaremetalMachine` reports `Running` and each pool shows `READY` `True`; otherwise see [Provider Conditions](./troubleshooting.mdx#provider-conditions).

#### Managed Data Disks \{#verify-managed-storage}

**Applies to**: hosts with managed data disks. Skip it when no `MachineInventory` declares `spec.storage`.

```bash
ac config use-cluster global
ac -n cpaas-system get machineinventories.elemental.cattle.io \
  -o custom-columns='NAME:.metadata.name,PHASE:.status.storage.phase,PREPARED:.status.storage.conditions[?(@.type=="StoragePrepared")].status,ACTIVE:.status.storage.conditions[?(@.type=="StorageActive")].status'
```

Continue when every used inventory with managed volumes shows `Active`, `True`, and `True`; otherwise see [Provider Conditions](./troubleshooting.mdx#provider-conditions).

#### Self-built VIP \{#verify-self-built-vip}

**Applies to**: `type: internal`. Skip it for an external load balancer.

```bash
ac config sync
ac config use-cluster <cluster-name>
ac -n kube-system get pods -l app=alive -o wide
ac config use-cluster global
```

Continue when an Alive Pod is `Running` on each control plane node; otherwise see [Provider Conditions](./troubleshooting.mdx#provider-conditions).

Log in to a control plane node of the cluster as the `boot` user, with the private key of an SSH public key in `cluster.sshKeys` (`ssh boot@<control-plane-node-ip>`). Only `root` can read the cluster CA file, so run `curl` with `sudo`:

```bash
sudo curl --cacert /etc/kubernetes/pki/ca.crt https://<vip>:6443/healthz
```

Continue when it prints `ok`; otherwise see [Provider Conditions](./troubleshooting.mdx#provider-conditions).

#### External Load Balancer \{#verify-external-load-balancer}

**Applies to**: `type: external`. Skip it for a Self-built VIP.

On the load balancer, check the frontend and every backend against [the External Load Balancer requirements](../../../install/prepare/communication_matrix.mdx#external_load_balancer). Continue when every current control plane node is registered and HTTPS `/healthz` returns HTTP `200` for each backend; otherwise fix the load balancer configuration.

## Run `create` Again \{#rerun-create}

`create` only creates the cluster. Do not run it on a cluster that is already created; to change a running cluster, see [Manage Nodes](../../../configure/nodes/alauda_os/bare-metal.mdx).

If `create` stops before the cluster is created, run the same command again; completed work is skipped. Running `create` again on the same directory recreates objects that were deleted, except that `ac` creates Secrets once and then leaves them as they are. It does not overwrite a field changed with another tool: when the rendered value differs, `create` reports that the fields are owned by another manager and stops. Do not delete the object that the error names. When `manifests/` already exists, `create` asks whether to reuse it: press Enter to reuse it, or answer `n` to render again after you change `install-config.yaml`. When standard input is not a terminal, pass `--reuse-manifests=true` or `--reuse-manifests=false`. Reusing `manifests/` ignores `install-config.yaml` and skips every check.

Do not edit the files in `manifests/`.

:::warning
Keep `<install-dir>/manifests/`, or set `cluster.encryptionProviderConfig`: a generated encryption key is kept only in `manifests/`. Rendering again without either generates a new key, and `manifests/` then no longer records the key the cluster uses.
:::
