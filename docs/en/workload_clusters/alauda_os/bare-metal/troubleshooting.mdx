# Troubleshooting Bare Metal Workload Clusters

Start from the stage that `ac adm alpha cluster status` reports, then match the condition on the `BaremetalMachine`, the `MachineInventory`, or the `BaremetalCluster`. Read them on the `global` cluster: run `ac config use-cluster global` first. For failures that every provider shares, see [Troubleshooting](../troubleshooting/index.mdx).

## Creation Stages \{#common-failure-modes}

| Symptom | Where to look first |
|---|---|
| `[1/4] CAPI Cluster` stays `NotFound` | The cluster name or namespace: `ac -n cpaas-system get clusters.cluster.x-k8s.io`. |
| `[2/4] KubeadmControlPlane` does not advance | `ac -n cpaas-system describe machine <name>` and the `BaremetalMachine`: `ImageCatalogMiss`, or no `Available` inventory in the pool. See [Provider Conditions](#provider-conditions). |
| The control plane does not come up | Whether the endpoint works: an `external` load balancer forwards `6443` to the control plane nodes; for `internal`, see the `Internal` row in [Provider Conditions](#provider-conditions). |
| `[3/4] MachineDeployment` shows the wrong node groups | `computes[].name`, and whether two groups share a pool. |
| `[4/4] ClusterView` does not advance | The platform `ClusterView` and the provider manager log. |
| `elemental-operator` does not start: `MountVolume.SetUp failed for volume "elemental-ca-cert": references non-existent secret key: ca.crt` | `elemental.tls.caCertSecretKey`; see [Providers](./prerequisites.mdx#providers). |

## Provider Conditions \{#provider-conditions}

| Symptom | Likely cause | Where to look |
|---|---|---|
| `BaremetalMachine` stuck in `Pending`, `InventoryAllocated=False / Reason=PoolMissing` | The template's `machineInventoryPoolRef.name` points at a pool that does not exist, for example a pool deleted after `create`. | The pool name and namespace. |
| `BaremetalMachine` stuck in `Pending`, `InventoryAllocated=False / Reason=PoolExhausted` | The pool has no `Available` inventory left. | `MachineInventoryPool.status.available`, and the allocation annotations on each member. |
| `BaremetalMachine` stuck after allocation, `BootstrapReady=False / Reason=BootstrapWaiting` | The `KubeadmConfig` has not produced a bootstrap data Secret yet. | `Machine.spec.bootstrap.dataSecretName`. |
| `BaremetalMachine` waits in `Allocated`, `ImageResolved=False / Reason=ImageCatalogMiss` | `elemental-image-catalog` has no key for `Machine.spec.version` on the architecture and OS of the host. | `ac -n cpaas-system get cm elemental-image-catalog -o yaml`. Add the key as in [OS Images and Image Catalog](./prerequisites.mdx#os-images-and-image-catalog); the `BaremetalMachine` continues by itself. |
| `ImageResolved=False / Reason=ImageRegistryMissing` | Neither the `cpaas.io/registry-address` annotation nor the platform registry credential Secret resolves a registry address. | The cluster annotations and the registry credential Secret. |
| A `MachineInventory` shows `status.install.phase=AwaitingTarget` | The host waits for you to select its system disk. | `MachineInventory.status.install.candidates`. Select the disk as described in [Select the System Disk](./create_cluster.mdx#select-system-disk). |
| A host stops before installing, and its `MachineInventory` lists a disk in `status.install.staleSystemDisks` with `action: Blocked` | A disk holds system partitions from an earlier installation (`COS_*` labels) that cannot be wiped safely. | The reason in `status.install.staleSystemDisks`. Clean that disk, then boot the host from the ISO again; see [Host Disks and Boot Order](./prerequisites.mdx#host-disk-and-boot-preparation). |
| An inventory is registered but not counted as `Available`, or a pool reports `MembersValid=False` | The inventory is missing, has no plan Secret, is not `Ready`, or its managed storage has not reached `StoragePrepared=True`. | `MachineInventory.status.storage`, `status.observedStorage`, `elemental-storage-observer.service`, and the `storage-prepare` plan output. |
| `BaremetalMachine` waits with `StorageReady=False` | A required managed volume did not activate, or no fresh post-reboot observation confirms its mount. | `BaremetalMachine.status.conditions[StorageReady]`, `MachineInventory.status.storage`, and the host mount units. |
| Reprovision never completes; `MachineInventory.status.plan.state=Failed` | `elemental upgrade` failed: registry unreachable, TLS, or disk full. | The plan Secret's `failed-output` field and the host serial console. |
| `BaremetalCluster` uses `Internal`, but the cluster cannot be reached through the VIP (`healthz` does not print `ok`), or no Alive Pod runs on a control plane node | The `vrid` collides with another cluster, the VIP is not in the control plane Layer 2 domain, or VRRP or gratuitous ARP is blocked. | The Alive Pods in `kube-system` of the workload cluster, and `ip addr show` on a control plane host. |
| `BaremetalCluster` uses `External`, but the endpoint is not reachable | The listener, backend membership, TLS passthrough, health check, route, DNS, or certificate SAN is wrong. | The load balancer configuration and HTTPS `/healthz` per backend. |
