# Troubleshooting Bare Metal Workload Clusters

Start from the stage that `ac adm alpha cluster status` reports. Then find the matching condition on the `BaremetalMachine`, the `MachineInventory`, or the `BaremetalCluster`. These objects are on the `global` cluster; run `ac config use-cluster global` before you read them. For failures that are common to all providers, see [Troubleshooting](../troubleshooting/index.mdx).

## Creation Stages \{#common-failure-modes}

| Symptom | Where to look first |
|---|---|
| `[1/4] CAPI Cluster` stays `NotFound` | The cluster name and namespace, with `ac -n cpaas-system get clusters.cluster.x-k8s.io`. |
| `[2/4] KubeadmControlPlane` does not advance | `ac -n cpaas-system describe machine <name>` and the `BaremetalMachine`. Look for `ImageCatalogMiss`, or for a pool with no `Available` inventory. See [Provider Conditions](#provider-conditions). |
| The control plane does not come up | Whether the endpoint works. For `external`, check that the load balancer forwards `6443` to the control plane nodes. For `internal`, see the `Internal` row in [Provider Conditions](#provider-conditions). |
| `[3/4] MachineDeployment` shows the wrong node groups | `computes[].name`, and whether two groups share a pool. |
| `[4/4] ClusterView` does not advance | The platform `ClusterView` and the provider manager log. |
| `elemental-operator` does not start: `MountVolume.SetUp failed for volume "elemental-ca-cert": references non-existent secret key: ca.crt` | `elemental.tls.caCertSecretKey`; see [Providers](./prerequisites.mdx#providers). |

## Provider Conditions \{#provider-conditions}

| Symptom | Likely cause | Where to look |
|---|---|---|
| `BaremetalMachine` stuck in `Pending`, `InventoryAllocated=False / Reason=PoolMissing` | The `machineInventoryPoolRef.name` of the template points to a pool that does not exist, for example because the pool was deleted after `create`. | The pool name and namespace. |
| `BaremetalMachine` stuck in `Pending`, `InventoryAllocated=False / Reason=PoolExhausted` | The pool has no `Available` inventory left. | `MachineInventoryPool.status.available`, and the allocation annotations on each member. |
| `BaremetalMachine` stuck after allocation, `BootstrapReady=False / Reason=BootstrapWaiting` | The `KubeadmConfig` has not produced a bootstrap data Secret yet. | `Machine.spec.bootstrap.dataSecretName`. |
| `BaremetalMachine` waits in `Allocated`, `ImageResolved=False / Reason=ImageCatalogMiss` | `elemental-image-catalog` has no key for `Machine.spec.version` on the architecture and OS of the host. | `ac -n cpaas-system get cm elemental-image-catalog -o yaml`. Add the key as described in [Add the Image Catalog Keys](./prepare_os.mdx#add-versions-to-image-catalog). The `BaremetalMachine` then continues by itself. |
| `ImageResolved=False / Reason=ImageRegistryMissing` | The provider finds no registry address in either the `cpaas.io/registry-address` annotation or the platform registry credential Secret. | The cluster annotations and the registry credential Secret. |
| A host does not register or install: no `MachineInventory` appears, it stays in `status.install.phase=AwaitingTarget`, or it lists a disk in `status.install.staleSystemDisks` with `action: Blocked` | The host cannot reach the `global` cluster, it waits for you to select its system disk, or one of its disks has system partitions from an earlier installation that cannot be wiped safely. | [Troubleshooting](./register_hosts.mdx#troubleshooting) in Register Hosts. |
| An inventory is registered but not counted as `Available`, or a pool reports `MembersValid=False` | The inventory is missing, has no plan Secret, or is not `Ready`. | `MachineInventory.status.conditions` and `status.plan.secretRef`. |
| Reprovisioning of a host never completes, and `MachineInventory.status.plan.state=Failed` | Writing the OS image failed: the registry is unreachable, TLS fails, or the disk is full. | `BaremetalMachine.status.conditions`, `journalctl -u elemental-system-agent` on the host, and the serial console of the host. On Alauda OS KU hosts, the `failed-output` key of the plan Secret also holds the output of the disk space check. Read these before you delete the `Machine`; see [Replacing a Single Failed Node](../../../configure/nodes/alauda_os/bare-metal.mdx#replacing-a-node). |
| `BaremetalCluster` uses `Internal`, but the cluster cannot be reached through the VIP (`healthz` does not print `ok`), or no Alive Pod runs on a control plane node | Another cluster already uses the same `vrid`, the VIP is not in the control plane Layer 2 domain, or VRRP or gratuitous ARP is blocked. | The Alive Pods in `kube-system` of the workload cluster, and `ip addr show` on a control plane host. |
| `BaremetalCluster` uses `External`, but the endpoint is not reachable | The listener, backend membership, TLS passthrough, health check, route, DNS, or certificate SAN is wrong. | The load balancer configuration, and HTTPS `/healthz` on each backend. |
