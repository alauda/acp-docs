# Troubleshooting Huawei Cloud Stack Workload Clusters

Start from the preflight error or the stage that `ac adm alpha cluster status` reports. For failures that every provider shares, see [Troubleshooting](../troubleshooting/index.mdx). Run the `ac` commands on this page from a machine where `ac` is logged in to the platform, after `ac config use-cluster global`.

## Creation Stages \{#troubleshooting}

| Symptom | Action |
|---|---|
| Preflight cannot reach the IAM endpoint | Check `externalGlobalDomain` and `schema` in the credential Secret, and that the machine that runs `ac` resolves and reaches `iam-apigateway-proxy.<externalGlobalDomain>` on `TCP/443`, or `TCP/80` for `http`. Then run `create` again. |
| `[1/4] CAPI Cluster` stays `NotFound` | Check the cluster name: `ac get clusters.cluster.x-k8s.io -n cpaas-system`. |
| `[2/4] KubeadmControlPlane` or `[3/4] MachineDeployment` does not become ready | Read the provider log: `ac -n cpaas-system logs deployment/cluster-api-provider-hcs-manager --tail=50`. If it names quota or an address that is in use, free it in HCS. Otherwise, contact technical support with the log. A hostname error is set on the owning `Machine`. |
| `ControlPlaneHAReady` is not `True` | See [Control Plane HA](#control-plane-ha). |
| `[4/4] ClusterView` does not become ready, or the cluster stays `Provisioned` with nodes `NotReady` | See [Troubleshoot a Workload Cluster Stuck in Provisioned](../troubleshooting/troubleshoot-cluster-not-ready.mdx). |
| Nodes stay `NotReady` because Kube-OVN is not installed, and the provider logs no `sentry` error | See [Kube-OVN Is Not Installed](#kube-ovn-not-installed). |
| `[2/4] KubeadmControlPlane` does not become ready, the instance is `ACTIVE`, and a pool hostname contains a dot | On the node, run `hostname`. If it returns the full dotted name, the provider on the `global` cluster is older than v1.0.1: upgrade it, then see [Configure FQDN Hostname on Existing HCS Clusters](../../../configure/nodes/alauda_os/migrate-hcs-node-fqdn-hostname.mdx). If that page's prerequisites are not met, contact technical support. |
| The `Cluster` stays in `Deleting` | See [Troubleshoot a Cluster Stuck in Deleting](../troubleshooting/troubleshoot-cluster-stuck-deleting.mdx). |

## Control Plane HA \{#control-plane-ha}

The [Control Plane HA check](./create_cluster.mdx#verify-control-plane-ha) prints the status, the reason, and a message:

| Result | Action |
|---|---|
| `True ControlPlaneHAReady` | None. |
| `False ControlPlaneHAPending` | Read the message and wait for the control plane machine or ECS operation it names to finish. If you enabled `controlPlaneHA` on an existing cluster or changed its policy, see [Control Plane HA Placement](./reference/install-config-parameters.mdx#control-plane-ha-placement). If it does not finish, contact technical support. |
| `False ControlPlaneHAFailed` | Read the message, then check HCS capacity and the policy: with `anti-affinity`, ECS creation fails when HCS has too few hosts for the rule. If they are correct, contact technical support. |

## Kube-OVN Is Not Installed \{#kube-ovn-not-installed}

The platform installs Kube-OVN and CoreDNS after the provider hands the cluster over:

```bash
ac -n cpaas-system get hcscluster <cluster-name> \
  -o jsonpath='{range .status.conditions[?(@.type=="CoreAddonsHandedOff")]}{.status}{" "}{.reason}{" "}{.message}{"\n"}{end}'
```

| Result | Action |
|---|---|
| `False CoreAddonsHandoffPending` or `False CoreDNSSkipPhasePending` | Read the message and wait for the operation it names to finish. If it does not finish, contact technical support. |
| `False CoreAddonsHandoffBlocked`, or `True` with Kube-OVN still not installed | Contact technical support with the message. |
