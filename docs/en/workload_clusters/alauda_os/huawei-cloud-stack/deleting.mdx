# Delete a Cluster on Huawei Cloud Stack \{#delete-with-ac}

:::warning
Deleting the cluster deletes the persistent and raw EVS disks of every node, and their data cannot be recovered.
:::

```bash
ac adm alpha cluster destroy --dir <install-dir>      # preferred: manifests/ records what ac rendered
ac adm alpha cluster destroy --cluster <cluster-name> # without the directory
```

`destroy` lists what it will delete and asks you to type the cluster name; `--yes` skips the prompt, and it is required when standard input is not a terminal. It deletes the Cluster API `Cluster` first and waits for the machines to go, then removes the remaining objects that `ac` rendered. If it is interrupted, run it again; it resumes where it stopped.

On Huawei Cloud Stack, deleting the `HCSMachineConfigPool` objects also deletes their persistent and raw EVS disks; `destroy` says so before it asks for confirmation. `--reclaim-disks` is not supported on Huawei Cloud Stack: `destroy` refuses it, because ordinary destroy already deletes the disks.

`destroy` only removes objects that carry the cluster's ownership label, and it removes the encryption Secret that `ac` rendered. The credential Secret, a registry Secret, and the HCS VPC, subnets, security group, and image are left in place. `--cluster global` is refused.

If the `Cluster` stays in `Deleting`, see [Troubleshoot a Cluster Stuck in Deleting](../troubleshooting/troubleshoot-cluster-stuck-deleting.mdx).
