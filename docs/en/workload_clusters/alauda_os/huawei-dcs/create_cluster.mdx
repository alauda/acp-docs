# Create a Cluster on Huawei DCS

ACP CLI (ac) renders the Cluster API and DCS objects from one `install-config.yaml`, applies them to the `global` cluster, and reports the creation stages. Every object lives in the `cpaas-system` namespace of the `global` cluster.

## Prerequisites

- You meet the [Huawei DCS prerequisites](./prerequisites.mdx).
- `ac` is logged in to the platform as a platform administrator (`ac login https://<platform-address>`).

## Procedure

### 1. Write `install-config.yaml` \{#write-install-config}

Create an installation directory for the cluster and write `install-config.yaml` in it. `ac` writes `manifests/` and `logs/ac.log` next to it. `ac` renders one `DCSIpHostnamePool` and one `DCSMachineTemplate` per node group from it, so you do not create IP pools or machine templates.

Copy the following template, fill in the placeholders, and delete the comment blocks you do not use; for the fields, see [Parameters](./reference/install-config-parameters.mdx).

{/* eslint-disable mdx/remark -- the ac field name contains a legacy OS name */}
{/* lint disable no-legacy-os-names */}

```yaml title="install-config.yaml"
cluster:
  # Required: a DNS-1123 subdomain of at most 63 characters, not global and not starting with global-.
  clusterName: <cluster-name>
  sshKeys:                                  # Required: the SSH public keys installed on every node.
    - <ssh-public-key>
  # Use the following block only for a registry other than the platform's. It requires platform v4.4.0 or later.
  # registrySecretRef:
  #   name: <registry-secret-name>          # Required: at most 63 characters.
  #   namespace: cpaas-system               # Default: cpaas-system, the only accepted value.
  # encryptionProviderConfig: <encryption-key>  # Optional: the base64 of a 16, 24, or 32 byte aescbc key. Empty generates a key.
  network:
    podCIDR: 10.199.0.0/16                  # Default: 10.199.0.0/16.
    serviceCIDR: 10.96.0.0/12               # Default: 10.96.0.0/12.
    kubeOVN:
      joinCIDR: 100.64.0.0/16               # Default: 100.64.0.0/16. The Pod, Service, and join CIDRs must not overlap.
    loadBalancer:                           # Required: the control plane endpoint.
      type: external                        # Default: external. Set internal for a Self-built VIP.
      # Required: the load balancer address, or the VIP with type: internal. An IPv4 address that is not a node address and is outside the CIDRs above.
      address: <control-plane-endpoint>
      port: 6443                            # Default: 6443.
      # Use the following two fields only with type: internal:
      # vrid: <vrid>                        # Required: 1 to 255, unique in the control plane Layer 2 domain.
      # interface: <nic-name>               # Optional: the NIC that carries the VIP. Empty uses the NIC that carries the node IP.

provider:
  dcs:
    vmTemplateName: <vm-template-name>      # Required: the VM template every node is cloned from. It decides the Kubernetes version.
    # Required: true or false. true keeps the control plane VMs on different DCS hosts; see the Huawei DCS prerequisites for what it needs.
    controlPlaneHA: <control-plane-ha>
    machineFolder: <folder-name>            # Required: an existing DCS VM folder.
    # cdRomDatastoreName: <datastore>       # Optional: the datastore for each node's CD-ROM. Empty lets the provider choose.
    # Default: false. Set true when vmTemplateName is an Alauda OS K template; otherwise the VMs boot without a network.
    # kubeOS: true
    # rootDisk:                             # Optional: the system disk. Empty keeps the template's size.
    #   sizeGiB: <root-disk-gib>            # Required: DCS rejects a size smaller than the template's.
    # resource:                             # Optional: fixes the VMs to an existing compute resource. Empty lets DCS place them.
    #   type: cluster                       # Required: cluster for a compute cluster, or host for a physical host.
    #   name: <cluster-or-host-name>        # Required.
    network:                                # Required: the primary NIC of every node.
      dvSwitchName: <dv-switch-name>        # Required: the distributed virtual switch.
      portGroupName: <port-group-name>      # Required: a port group of that switch.
    disks:
      datastore:
        type: <datastore-type>              # Required: Datastore or DatastoreCluster.
        name: <datastore-name>              # Required: the datastore or datastore cluster name.
      isThin: false                         # Default: false, thick provisioning. Applies to persistent and raw disks only.
      pciType: VIRTIO                       # Default: VIRTIO. VIRTIO, SCSI, or IDE.

controlPlane:                               # Required: the control plane node group.
  # Required: an odd number, 1 or 3 or more. A cluster with a single control plane node is for testing and cannot be upgraded.
  replicas: 3
  cpuCore: 8                                # Default: 8.
  memoryGiB: 16                             # Default: 16.
  # Use the following block only when this node group differs from provider.dcs:
  # dcs:
  #   machineFolder: <folder-name>          # Optional: overrides provider.dcs.machineFolder.
  #   cdRomDatastoreName: <datastore>       # Optional: overrides provider.dcs.cdRomDatastoreName.
  #   rootDisk:                             # Optional: overrides provider.dcs.rootDisk.
  #     sizeGiB: <root-disk-gib>
  #   resource:                             # Optional: overrides provider.dcs.resource. Set both fields.
  #     type: cluster
  #     name: <cluster-or-host-name>
  network:                                  # Required: the primary NIC network of this node group.
    gateway: <cp-gateway>                   # Required: the primary NIC gateway.
    # dns: [<dns-ip>]                       # Optional: DCS uses only the first entry.
    mask: <prefix-length>                   # Required: a prefix length from 1 to 32.
    additions: []                           # Default: []. The additional NICs, matched in order to hosts[].additionalIps.
    # To add NICs, replace "additions: []" with the following block:
    # additions:
    #   - mask: <prefix-length>             # Optional: 1 to 32. Empty takes network.mask.
    #     dcs:                              # Optional: empty takes provider.dcs.network.
    #       dvSwitchName: <dv-switch-name>
    #       portGroupName: <port-group-name>
  disks:                                    # Required: keep the standard disk names and set sizeGiB.
    ephemeral:                              # Required: disks recreated with the VM.
      - name: var-lib-containerd
        sizeGiB: 100
      - name: var-lib-kubelet
        sizeGiB: 100
      - name: var-lib-etcd                  # Control plane only.
        sizeGiB: 20
    persistent:                             # Required: disks kept when the VM is replaced.
      - name: var-cpaas
        sizeGiB: 100
    rawDisks: []                            # Default: []. Raw block volumes for TopoLVM.
    # To add raw disks, replace "rawDisks: []" with the following block:
    # rawDisks:
    #   - name: data-001                    # Required: a name of your choice.
    #     sizeGiB: 50                       # Required: greater than 0.
    # Use the following block only when this node group differs from provider.dcs.disks. Set only the fields that differ:
    # dcs:
    #   datastore:                          # Optional: overrides provider.dcs.disks.datastore. Set both fields.
    #     type: <datastore-type>
    #     name: <datastore-name>
    #   isThin: true                        # Optional: overrides provider.dcs.disks.isThin.
    #   pciType: VIRTIO                     # Optional: overrides provider.dcs.disks.pciType.
  hosts:                                    # Required: at least replicas entries.
    - hostname: <cp-0-hostname>             # Required.
      ip: <cp-0-ip>                         # Required: the primary NIC address, IPv4.
      additionalIps: []                     # Default: []. One IPv4 address per network.additions entry, in order.
    - hostname: <cp-1-hostname>
      ip: <cp-1-ip>
      additionalIps: []
    - hostname: <cp-2-hostname>
      ip: <cp-2-ip>
      additionalIps: []

computes:                                   # Optional: the worker node groups. Delete this section to run on the control plane nodes alone.
  - name: worker                            # Required: a DNS-1123 label, unique per group. control-plane is reserved.
    replicas: 3                             # Required: the number of nodes in this group.
    cpuCore: 8                              # Default: 8.
    memoryGiB: 16                           # Default: 16.
    # Use the following block only when this node group differs from provider.dcs:
    # dcs:
    #   machineFolder: <folder-name>        # Optional: overrides provider.dcs.machineFolder.
    #   cdRomDatastoreName: <datastore>     # Optional: overrides provider.dcs.cdRomDatastoreName.
    #   rootDisk:                           # Optional: overrides provider.dcs.rootDisk.
    #     sizeGiB: <root-disk-gib>
    #   resource:                           # Optional: overrides provider.dcs.resource. Set both fields.
    #     type: cluster
    #     name: <cluster-or-host-name>
    network:                                # Required: the primary NIC network of this node group.
      gateway: <worker-gateway>             # Required: the primary NIC gateway.
      # dns: [<dns-ip>]                     # Optional: DCS uses only the first entry.
      mask: <prefix-length>                 # Required: a prefix length from 1 to 32.
      additions: []                         # Default: []. The additional NICs, matched in order to hosts[].additionalIps.
      # To add NICs, replace "additions: []" with the following block:
      # additions:
      #   - mask: <prefix-length>           # Optional: 1 to 32. Empty takes network.mask.
      #     dcs:                            # Optional: empty takes provider.dcs.network.
      #       dvSwitchName: <dv-switch-name>
      #       portGroupName: <port-group-name>
    disks:                                  # Required: keep the standard disk names and set sizeGiB.
      ephemeral:                            # Required: disks recreated with the VM. Workers have no var-lib-etcd.
        - name: var-lib-containerd
          sizeGiB: 100
        - name: var-lib-kubelet
          sizeGiB: 100
      persistent:                           # Required: disks kept when the VM is replaced.
        - name: var-cpaas
          sizeGiB: 100
      rawDisks: []                          # Default: []. Raw block volumes for TopoLVM.
      # To add raw disks, replace "rawDisks: []" with the following block:
      # rawDisks:
      #   - name: data-001                  # Required: a name of your choice.
      #     sizeGiB: 50                     # Required: greater than 0.
      # Use the following block only when this node group differs from provider.dcs.disks. Set only the fields that differ:
      # dcs:
      #   datastore:                        # Optional: overrides provider.dcs.disks.datastore. Set both fields.
      #     type: <datastore-type>
      #     name: <datastore-name>
      #   isThin: true                      # Optional: overrides provider.dcs.disks.isThin.
      #   pciType: VIRTIO                   # Optional: overrides provider.dcs.disks.pciType.
    hosts:                                  # Required: at least replicas entries.
      - hostname: <worker-0-hostname>       # Required.
        ip: <worker-0-ip>                   # Required: the primary NIC address, IPv4.
        additionalIps: []                   # Default: []. One IPv4 address per network.additions entry, in order.
      - hostname: <worker-1-hostname>
        ip: <worker-1-ip>
        additionalIps: []
      - hostname: <worker-2-hostname>
        ip: <worker-2-ip>
        additionalIps: []

credentialRef:                              # Required: the DCS credential Secret.
  name: <credential-secret-name>            # Required: the Secret name.
  namespace: cpaas-system                   # Default: cpaas-system, the only accepted value.
```

### 2. Create the Cluster \{#create-with-ac}

:::warning
Make sure the password in the credential Secret is correct before you run `create`: DCS locks the account after repeated failed sign-ins.
:::

Run the following command from a machine where `ac` is logged in to the platform:

```bash
ac config use-cluster global
ac adm alpha cluster create --dir <install-dir> --provider dcs
```

`ac` first checks the credential Secret, the DCS objects named in `install-config.yaml`, the Kubernetes version of the VM template, and the registry. If a check fails, nothing is changed and the error names the item.

`create` returns once the objects are applied, and the cluster keeps building. Add `--wait` to wait until all stages are ready; `--timeout` (default `2h`) limits only the wait. To render without applying, run `ac adm alpha cluster manifests` with the same flags.

### 3. Monitor the Creation \{#monitor-creation}

```bash
ac config use-cluster global
ac adm alpha cluster status --cluster <cluster-name>                      # prints the four stages once
ac adm alpha cluster wait-for install-complete --cluster <cluster-name>   # waits until all four are ready
```

Continue when all four stages are ready; otherwise see [Troubleshooting](./troubleshooting.mdx).

### 4. Verify the Cluster \{#verify-the-cluster}

Run the following commands from a machine where `ac` is logged in to the platform:

```bash
ac config sync
ac config use-cluster <cluster-name>
ac get nodes
ac config use-cluster global
```

Continue when every node is `Ready`; otherwise see [Troubleshooting](./troubleshooting.mdx).

#### Self-built VIP \{#verify-self-built-vip}

**Applies to**: `cluster.network.loadBalancer.type: internal`. Skip it for an external load balancer.

```bash
ac config use-cluster global
ac -n cpaas-system get dcscluster <cluster-name> \
  -o jsonpath='{.spec.controlPlaneLoadBalancer.type}{" "}{.spec.controlPlaneEndpoint.host}{":"}{.spec.controlPlaneEndpoint.port}{"\n"}'
ac -n cpaas-system get moduleinfo \
  -l cpaas.io/cluster-name=<cluster-name>,cpaas.io/module-name=alive
ac config sync
ac config use-cluster <cluster-name>
ac -n cpaas-system get apprelease alive
ac -n kube-system get pods -l app=alive -o wide
ac config use-cluster global
```

Continue when the output shows `internal` with your VIP and port, an `alive` `ModuleInfo`, a synced and healthy `alive` `AppRelease`, and a Ready `alive` Pod on every control plane node; otherwise see [Self-built VIP](./troubleshooting.mdx#self-built-vip) in Troubleshooting.

Then, on a control plane node of the cluster:

```bash
curl --cacert /etc/kubernetes/pki/ca.crt https://<vip>:6443/healthz
```

Continue when it prints `ok`; otherwise see [Self-built VIP](./troubleshooting.mdx#self-built-vip) in Troubleshooting.

#### Control Plane HA \{#verify-control-plane-ha}

**Applies to**: `provider.dcs.controlPlaneHA: true`. Skip it when it is `false`.

```bash
ac config use-cluster global
ac -n cpaas-system get dcscluster <cluster-name> \
  -o jsonpath='{range .status.conditions[?(@.type=="ControlPlaneHAReady")]}{.status}{" "}{.reason}{" "}{.message}{"\n"}{end}'
```

Continue when the status is `True`; otherwise see [Control Plane HA](./troubleshooting.mdx#control-plane-ha) in Troubleshooting.

#### Additional NICs \{#verify-additional-nics}

**Applies to**: node groups with `network.additions`. Skip it otherwise.

```bash
ac config use-cluster global
ac -n cpaas-system get dcsmachine -l cluster.x-k8s.io/cluster-name=<cluster-name> \
  -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.networkConfig.ip}{"\t"}{.status.additionalNic}{"\n"}{end}'
```

Continue when each `DCSMachine` lists one additional NIC per address in its host's `additionalIps`; otherwise contact technical support.

## Run `create` Again \{#rerun-create}

`create` only creates the cluster. Do not run it on a cluster that is already created; to change a running cluster, see [Manage Nodes](../../../configure/nodes/alauda_os/huawei-dcs.mdx).

If `create` stops before the cluster is created, run the same command again; completed work is skipped. Running `create` again on the same directory recreates objects that were deleted, except that `ac` creates Secrets once and then leaves them as they are. It does not overwrite a field changed with another tool: when the rendered value differs, `create` reports that the fields are owned by another manager and stops. Do not delete the object that the error names. When `manifests/` already exists, `create` asks whether to reuse it: press Enter to reuse it, or answer `n` to render again after you change `install-config.yaml`. When standard input is not a terminal, pass `--reuse-manifests=true` or `--reuse-manifests=false`. Reusing `manifests/` ignores `install-config.yaml` and skips every check.

Do not edit the files in `manifests/`.

:::warning
Keep `<install-dir>/manifests/`, or set `cluster.encryptionProviderConfig`: a generated encryption key is kept only in `manifests/`. Rendering again without either generates a new key, and `manifests/` then no longer records the key the cluster uses.
:::
