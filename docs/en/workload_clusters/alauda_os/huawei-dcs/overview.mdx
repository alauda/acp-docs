# Huawei DCS Provider

The Infrastructure Provider for Huawei DCS creates and manages Alauda OS clusters on Huawei Datacenter Virtualization Solution (DCS). It clones each node from a DCS VM template, gives it a fixed address and hostname from the node group's plan, and attaches its disks. Disks declared as persistent, such as `/var/cpaas`, belong to the node's address slot rather than to the VM: when a rolling update replaces the VM, they are detached and reattached to the replacement, so nodes are replaced one at a time. The control plane endpoint is an external load balancer or a Self-built VIP that the provider runs on the control plane nodes, and the control plane VMs can be kept on different DCS hosts with a DRS rule.

## Creating and Managing Clusters

Create clusters with ACP CLI (ac) from one `install-config.yaml`; `ac` renders and applies the Cluster API and DCS objects. See [Create a Cluster](./create_cluster.mdx).

With Fleet Essentials installed, you can also create clusters and manage node pools in the web UI; see [Create in the Web UI](./create_cluster.mdx#create-in-web-ui). The web UI does not support a Self-built VIP, a dedicated registry, or persistent disks, which you then add with YAML. It requests the Distribution Version upgrade but not the Kubernetes and Alauda OS replacement; see [Upgrade Kubernetes on Huawei DCS](../../../upgrade/workload/alauda_os/huawei-dcs.mdx).

## DCS Objects and `install-config.yaml` \{#concepts-and-terminology}

The provider references DCS objects by name and creates none of them, except the VMs and their volumes.

| DCS object | What it is | Where it is set |
|---|---|---|
| Site | One DCS deployment. | `site` in the [credential Secret](./prerequisites.mdx#credential-secret). |
| VM template | A VM marked as a template, created from the Alauda OS image. | `provider.dcs.vmTemplateName` |
| VM folder | A grouping of VMs. It does not affect placement. | `provider.dcs.machineFolder` |
| DCS cluster, host | A pool of physical hosts, and one host in it. | `resource`, optional. By default the DCS scheduler picks the host. |
| Distributed virtual switch, port group | The network a NIC attaches to. A port group belongs to one switch. | `provider.dcs.network`, `network.additions[].dcs` |
| Datastore, datastore cluster | Storage for disks, and a group of datastores from which DCS picks one with free space. | `provider.dcs.disks.datastore` |
| Volume | A disk created by the provider; persistent ones outlive the VM. | `disks.persistent`, `disks.rawDisks` |

Two names are easy to confuse:

- A **DCS cluster** is a pool of physical hosts. The `DCSCluster` custom resource is the infrastructure side of one Kubernetes cluster; one DCS cluster can host the VMs of many Kubernetes clusters.
- A **datastore cluster** is a group of datastores (storage), not a DCS cluster (compute).

Addresses and hostnames are not DCS objects: they are declared in `install-config.yaml` and written into each VM at first boot. DCS does not reserve them, so keep them free of conflicts.

For the custom resources, see the [Huawei DCS API reference](../../../apis/kubernetes_apis/infrastructure_providers/huawei-dcs/index.mdx).
