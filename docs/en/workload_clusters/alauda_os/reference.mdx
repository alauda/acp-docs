# Creation Reference

This page describes what every provider shares when you create a workload cluster with `ac adm alpha cluster create`. Each provider's creation page links here.

## Common `install-config.yaml` Fields \{#install-config}

The file has four parts:

- `cluster`: the name, network, keys, and encryption.
- `provider.<name>`: the infrastructure of one provider.
- `controlPlane` and `computes`: the node groups.
- `credentialRef`: the infrastructure credential.

The following structure shows only the fields that every provider uses. It is not a complete file. To write your file, start from the template of your provider instead. The template adds the fields of that provider, such as the control plane endpoint and the node network and disks, and describes them.

`ac` rejects an unknown or misspelled field before it changes anything, and the error names the field path.

Unlike the file of the `global` cluster, this file has no `global` section and no `deployMode`. `ac` rejects both.

```yaml title="install-config.yaml (common structure)"
cluster:
  clusterName: <cluster-name> # [!code callout]
  sshKeys: # [!code callout]
    - <ssh-public-key>
  # [!code callout]
  # registrySecretRef:
  #   name: <registry-secret-name>
  #   namespace: cpaas-system
  # [!code callout]
  # encryptionProviderConfig: <encryption-key>
  ntpServers: [] # [!code callout]
  network:
    podCIDR: 10.199.0.0/16 # [!code callout]
    serviceCIDR: 10.96.0.0/12 # [!code callout]
    kubeOVN:
      joinCIDR: 100.64.0.0/16 # [!code callout]

provider:
  <provider-name>: {} # [!code callout]

controlPlane:
  replicas: 3 # [!code callout]
  <provider-name>: {} # [!code callout]

computes:
  - name: worker # [!code callout]
    replicas: 3 # [!code callout]
    <provider-name>: {}

credentialRef: # [!code callout]
  name: <credential-secret-name>
  namespace: cpaas-system
```
