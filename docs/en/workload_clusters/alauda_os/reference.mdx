# Creation Reference

This page describes what every provider shares when you create a workload cluster with `ac adm alpha cluster create`. Each provider's creation page links here.

## Common `install-config.yaml` Fields \{#install-config}

The file has four parts: `cluster` (the name, network, keys, and encryption), `provider.<name>` (the infrastructure of one provider), the node groups `controlPlane` and `computes`, and `credentialRef` (the infrastructure credential). The following structure shows the fields that every provider uses; it is not a complete file. Copy the template of your provider instead: it adds the provider's own fields, such as the control plane endpoint and the node network and disks, and describes them. An unknown or misspelled field fails before `ac` changes anything, and the error names the field path.

Unlike the `global` cluster's file, it has no `global` section and no `deployMode`: `ac` rejects them.

```yaml title="install-config.yaml (common structure)"
cluster:
  clusterName: <cluster-name> # [!code callout]
  sshKeys: # [!code callout]
    - <ssh-public-key>
  # [!code callout]
  # registrySecretRef:
  #   name: <registry-secret-name>
  #   namespace: cpaas-system
  # [!code callout]
  # encryptionProviderConfig: <encryption-key>
  ntpServers: [] # [!code callout]
  network:
    podCIDR: 10.199.0.0/16 # [!code callout]
    serviceCIDR: 10.96.0.0/12 # [!code callout]
    kubeOVN:
      joinCIDR: 100.64.0.0/16 # [!code callout]

provider:
  <provider-name>: {} # [!code callout]

controlPlane:
  replicas: 3 # [!code callout]
  <provider-name>: {} # [!code callout]

computes:
  - name: worker # [!code callout]
    replicas: 3 # [!code callout]
    <provider-name>: {}

credentialRef: # [!code callout]
  name: <credential-secret-name>
  namespace: cpaas-system
```
