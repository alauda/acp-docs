# Create a Cluster on VMware vSphere

ACP CLI (ac) renders the Cluster API, vSphere, and CPI objects from one `install-config.yaml`, applies them to the `global` cluster, and reports the creation stages. Every object lives in the `cpaas-system` namespace of the `global` cluster. For how the provider objects fit together, see [How It Works](./overview.mdx#how-it-works).

## Prerequisites \{#prerequisites}

- You meet the [VMware vSphere prerequisites](./prerequisites.mdx).
- `ac` is logged in to the platform as a platform administrator (`ac login https://<platform-address>`).

## Procedure

### 1. Write `install-config.yaml` \{#write-install-config}

Create an installation directory for the cluster and write `install-config.yaml` in it. `ac` writes `manifests/` and `logs/ac.log` next to it.

Copy the following template, fill in the placeholders, and delete the comment blocks you do not use; for the fields, see [Parameters](./reference/install-config-parameters.mdx).

```yaml title="install-config.yaml"
cluster:
  # Required: a DNS-1123 subdomain of at most 63 characters, not global and not starting with global-.
  clusterName: <cluster-name>
  sshKeys:                                  # Required: the SSH public keys installed on every node.
    - <ssh-public-key>
  # Use the following block only for a registry other than the platform's. It requires platform v4.4.0 or later.
  # registrySecretRef:
  #   name: <registry-secret-name>          # Required: at most 63 characters.
  #   namespace: cpaas-system               # Default: cpaas-system, the only accepted value.
  # encryptionProviderConfig: <encryption-key>  # Optional: the base64 of a 16, 24, or 32 byte aescbc key. Empty generates a key.
  network:
    podCIDR: 10.199.0.0/16                  # Default: 10.199.0.0/16.
    serviceCIDR: 10.96.0.0/12               # Default: 10.96.0.0/12.
    kubeOVN:
      joinCIDR: 100.64.0.0/16               # Default: 100.64.0.0/16. The Pod, Service, and join CIDRs must not overlap.
    loadBalancer:                           # Required: the control plane endpoint.
      type: external                        # Default: external. Set internal for a Self-built VIP.
      # Required: the load balancer address, or the VIP with type: internal. An IPv4 address that is not a node address and is outside the CIDRs above.
      address: <control-plane-endpoint>
      port: 6443                            # Default: 6443.
      # Use the following two fields only with type: internal:
      # vrid: <vrid>                        # Required: 1 to 255, unique in the control plane Layer 2 domain.
      # interface: <nic-name>               # Optional: the NIC that carries the VIP. Empty uses the NIC that carries the node IP.

provider:
  vsphere:
    server: <vcenter-address>               # Required: the vCenter address.
    # Required: the datacenter name. Use an inventory path, such as /folder/dc, only without computeResource.
    datacenter: <datacenter>
    template: <template-name-or-path>       # Required: the VM template every node is cloned from, by name or inventory path.
    datastore: <datastore>                  # Required: the datastore for the VMs and, by default, their disks.
    # folder: <folder-path>                 # Optional: the VM folder. Empty uses the datacenter's VM folder.
    # Required when the datacenter has several: the DRS cluster or standalone host, by name. Otherwise delete this line.
    computeResource: <cluster-or-host>
    # rootDisk:                             # Optional: the system disk. Empty keeps the template's size.
    #   sizeGiB: <root-disk-gib>            # Required: not smaller than the template's. It takes effect only on a full clone.
    releaseDelayHours: 24                   # Default: 24. How many hours a released pool slot keeps its persistent disks.
    network:                                # Required: the primary NIC of every node.
      name: <portgroup-name>                # Required: the port group or distributed port group.
      # deviceName: <nic-name>              # Optional: the NIC name in the guest. Empty names the NICs eth0, eth1, and so on.

controlPlane:                               # Required: the control plane node group.
  # Required: an odd number, 1 or 3 or more. A cluster with a single control plane node is for testing and cannot be upgraded.
  replicas: 3
  # cpuCore: <cpu-core>                     # Optional: empty keeps the template's size.
  # memoryGiB: <memory-gib>                 # Optional: empty keeps the template's size.
  # Use the following block only when this node group differs from provider.vsphere:
  # vsphere:
  #   datastore: <datastore>                # Optional: overrides provider.vsphere.datastore.
  #   folder: <folder-path>                 # Optional: overrides provider.vsphere.folder.
  #   computeResource: <cluster-or-host>    # Optional: overrides provider.vsphere.computeResource.
  #   rootDisk:                             # Optional: overrides provider.vsphere.rootDisk.
  #     sizeGiB: <root-disk-gib>
  network:                                  # Required: the primary NIC network of this node group.
    gateway: <cp-gateway>                   # Required: the primary NIC gateway.
    dns: [<dns-ip>]                         # Required: every entry is used.
    mask: <prefix-length>                   # Required: a prefix length from 1 to 32.
    additions: []                           # Default: []. The additional NICs, matched in order to hosts[].additionalIps.
    # To add NICs, replace "additions: []" with the following block:
    # additions:
    #   - mask: <prefix-length>             # Optional: 1 to 32. Empty takes network.mask.
    #     vsphere:                          # Optional: set it when this NIC differs from the primary NIC.
    #       name: <portgroup-name>          # Optional: empty takes provider.vsphere.network.name.
    #       deviceName: <nic-name>          # Optional: the NIC name in the guest.
  disks:                                    # Required: keep the standard disk names and set sizeGiB.
    ephemeral:                              # Required: disks recreated with the VM.
      - name: var-lib-containerd
        sizeGiB: 100
      - name: var-lib-kubelet
        sizeGiB: 100
      - name: var-lib-etcd                  # Control plane only.
        sizeGiB: 20
    persistent:                             # Required: disks kept when the VM is replaced.
      - name: var-cpaas
        sizeGiB: 100
    rawDisks: []                            # Default: []. Raw block volumes for TopoLVM.
    # To add raw disks, replace "rawDisks: []" with the following block:
    # rawDisks:
    #   - name: data-001                    # Required: a name of your choice.
    #     sizeGiB: 50                       # Required: greater than 0.
    # Use the following block only to place the data disks of this node group:
    # vsphere:
    #   datastore: <datastore>              # Optional: empty takes the group's datastore.
    #   storagePolicy: <storage-policy>     # Optional: the storage policy of the data disks.
  hosts:                                    # Required: at least replicas entries.
    - hostname: <cp-0-hostname>             # Required.
      ip: <cp-0-ip>                         # Required: the primary NIC address, IPv4.
      additionalIps: []                     # Default: []. One IPv4 address per network.additions entry, in order.
    - hostname: <cp-1-hostname>
      ip: <cp-1-ip>
      additionalIps: []
    - hostname: <cp-2-hostname>
      ip: <cp-2-ip>
      additionalIps: []

computes:                                   # Optional: the worker node groups. Delete this section to run on the control plane nodes alone.
  - name: worker                            # Required: a DNS-1123 label, unique per group. control-plane is reserved.
    replicas: 3                             # Required: the number of nodes in this group.
    # cpuCore: <cpu-core>                   # Optional: empty keeps the template's size.
    # memoryGiB: <memory-gib>               # Optional: empty keeps the template's size.
    # Use the following block only when this node group differs from provider.vsphere:
    # vsphere:
    #   datastore: <datastore>              # Optional: overrides provider.vsphere.datastore.
    #   folder: <folder-path>               # Optional: overrides provider.vsphere.folder.
    #   computeResource: <cluster-or-host>  # Optional: overrides provider.vsphere.computeResource.
    #   rootDisk:                           # Optional: overrides provider.vsphere.rootDisk.
    #     sizeGiB: <root-disk-gib>
    network:                                # Required: the primary NIC network of this node group.
      gateway: <worker-gateway>             # Required: the primary NIC gateway.
      dns: [<dns-ip>]                       # Required: every entry is used.
      mask: <prefix-length>                 # Required: a prefix length from 1 to 32.
      additions: []                         # Default: []. The additional NICs, matched in order to hosts[].additionalIps.
      # To add NICs, replace "additions: []" with the following block:
      # additions:
      #   - mask: <prefix-length>           # Optional: 1 to 32. Empty takes network.mask.
      #     vsphere:                        # Optional: set it when this NIC differs from the primary NIC.
      #       name: <portgroup-name>        # Optional: empty takes provider.vsphere.network.name.
      #       deviceName: <nic-name>        # Optional: the NIC name in the guest.
    disks:                                  # Required: keep the standard disk names and set sizeGiB.
      ephemeral:                            # Required: disks recreated with the VM. Workers have no var-lib-etcd.
        - name: var-lib-containerd
          sizeGiB: 100
        - name: var-lib-kubelet
          sizeGiB: 100
      persistent:                           # Required: disks kept when the VM is replaced.
        - name: var-cpaas
          sizeGiB: 100
      rawDisks: []                          # Default: []. Raw block volumes for TopoLVM.
      # To add raw disks, replace "rawDisks: []" with the following block:
      # rawDisks:
      #   - name: data-001                  # Required: a name of your choice.
      #     sizeGiB: 50                     # Required: greater than 0.
      # Use the following block only to place the data disks of this node group:
      # vsphere:
      #   datastore: <datastore>            # Optional: empty takes the group's datastore.
      #   storagePolicy: <storage-policy>   # Optional: the storage policy of the data disks.
    hosts:                                  # Required: at least replicas entries.
      - hostname: <worker-0-hostname>       # Required.
        ip: <worker-0-ip>                   # Required: the primary NIC address, IPv4.
        additionalIps: []                   # Default: []. One IPv4 address per network.additions entry, in order.
      - hostname: <worker-1-hostname>
        ip: <worker-1-ip>
        additionalIps: []
      - hostname: <worker-2-hostname>
        ip: <worker-2-ip>
        additionalIps: []

credentialRef:                              # Required: the vCenter credential Secret.
  name: <cluster-name>-credential           # Required: the Secret name.
  namespace: cpaas-system                   # Default: cpaas-system, the only accepted value.
```

### 2. Create the Cluster \{#create-with-ac}

Run the following command from a machine where `ac` is logged in to the platform:

```bash
ac config use-cluster global
ac adm alpha cluster create --dir <install-dir> --provider vsphere
```

`ac` first checks the provider CRDs on the `global` cluster, the credential and the vCenter sign-in, the vCenter objects named in `install-config.yaml`, and the registry. If a check fails, nothing is changed and the error names the item.

`create` returns once the objects are applied, and the cluster keeps building. Add `--wait` to wait until all stages are ready; `--timeout` (default `2h`) limits only the wait. To render without applying, run `ac adm alpha cluster manifests` with the same flags.

### 3. Monitor the Creation \{#monitor-creation}

```bash
ac config use-cluster global
ac adm alpha cluster status --cluster <cluster-name>                      # prints the four stages once
ac adm alpha cluster wait-for install-complete --cluster <cluster-name>   # waits until all four are ready
```

Continue when all four stages are ready; otherwise see [Troubleshooting](./troubleshooting.mdx).

### 4. Verify the Cluster \{#verify-the-cluster}

Run the following commands from a machine where `ac` is logged in to the platform:

```bash
ac config sync
ac config use-cluster <cluster-name>
ac get nodes
ac config use-cluster global
```

Continue when every node is `Ready`; otherwise see [Troubleshooting](./troubleshooting.mdx).

#### CPI and Pools \{#verify-cpi-and-pools}

```bash
ac config use-cluster global
ac -n cpaas-system get clusterresourceset,clusterresourcesetbinding
ac -n cpaas-system get vspheremachineconfigpool
ac config sync
ac config use-cluster <cluster-name>
ac -n kube-system get daemonset
ac config use-cluster global
```

Continue when a `ClusterResourceSetBinding` exists for the cluster, `vsphere-cloud-controller-manager` is listed in `kube-system`, and each pool reports `Ready=True` with `ALLOCATED` equal to the number of its machines; otherwise see [Troubleshooting](./troubleshooting.mdx#common-causes).

#### Persistent Disks \{#verify-persistent-disks}

Run it for each pool, `<cluster-name>-control-plane` and `<cluster-name>-<group>`:

```bash
ac config use-cluster global
ac -n cpaas-system get vspheremachineconfigpool <pool-name> \
  -o jsonpath='{range .status.persistentDiskStatuses[*]}{.hostname}{" "}{.name}{" "}{.phase}{"\n"}{end}'
```

Continue when every persistent disk of an allocated slot reports `Attached`; otherwise see [Troubleshooting](./troubleshooting.mdx#common-causes).

#### Optional Topology \{#verify-creation-time-variants}

**Applies to**: node groups with `network.additions` or `rawDisks`. Skip it when you use neither.

```bash
ac config use-cluster global
ac -n cpaas-system get vspheremachineconfigpool <pool-name> -o yaml
```

On a node of that group:

```bash
ls -l /dev/disk/by-capv/
```

Continue when each slot lists the declared additional NICs and disks, and every raw disk appears in `/dev/disk/by-capv/`; otherwise contact technical support.

#### Self-built VIP \{#verify-self-built-vip}

**Applies to**: `type: internal`. Skip it for an external load balancer.

```bash
ac config use-cluster global
ac -n cpaas-system get vspherecluster <cluster-name> \
  -o jsonpath='{.status.conditions[?(@.type=="SelfBuiltLoadBalancerReady")].status}{"\n"}'
ac config sync
ac config use-cluster <cluster-name>
ac -n kube-system get pods -l app=alive -o wide
ac config use-cluster global
```

Continue when the condition is `True` and one Alive Pod runs on each control plane node; otherwise see [Troubleshooting](./troubleshooting.mdx#self-built-vip).

On a control plane node of the cluster:

```bash
curl --cacert /etc/kubernetes/pki/ca.crt https://<vip>:6443/healthz
```

Continue when it prints `ok`; otherwise see [Troubleshooting](./troubleshooting.mdx#self-built-vip).

## Run `create` Again \{#rerun-create}

`create` only creates the cluster. Do not run it on a cluster that is already created; to change a running cluster, see [Manage Nodes](../../../configure/nodes/alauda_os/vmware-vsphere.mdx).

If `create` stops before the cluster is created, run the same command again; completed work is skipped. Running `create` again on the same directory recreates objects that were deleted, except the credential Secret, which `ac` does not render. It does not overwrite a field changed with another tool: when the rendered value differs, `create` reports that the fields are owned by another manager and stops. Do not delete the object that the error names. When `manifests/` already exists, `create` asks whether to reuse it: press Enter to reuse it, or answer `n` to render again after you change `install-config.yaml`. When standard input is not a terminal, pass `--reuse-manifests=true` or `--reuse-manifests=false`. Reusing `manifests/` ignores `install-config.yaml` and skips every check.

Do not edit the files in `manifests/`.

:::warning
Keep `<install-dir>/manifests/`, or set `cluster.encryptionProviderConfig`: a generated encryption key is kept only in `manifests/`. Rendering again without either generates a new key, and `manifests/` then no longer records the key the cluster uses.
:::
