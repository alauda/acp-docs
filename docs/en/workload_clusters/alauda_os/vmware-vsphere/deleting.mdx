# Delete a Cluster on VMware vSphere \{#delete-with-ac}

Run the following command from a machine where `ac` is logged in to the platform. `destroy` deletes the persistent disks of the cluster with it:

```bash
ac config use-cluster global
ac adm alpha cluster destroy --dir <install-dir> --reclaim-disks     # preferred: manifests/ records what ac rendered
ac adm alpha cluster destroy --cluster <cluster-name> --reclaim-disks # without the directory
```

`destroy` lists what it will delete and asks you to type the cluster name; `--yes` skips the prompt and is required when standard input is not a terminal. If it is interrupted, run it again; it resumes where it stopped.

The persistent disks cannot be kept. The provider deletes them while it deletes the cluster's machine config pools, and it reaches vCenter through the cluster's credential, so `destroy` deletes them before it removes that credential. `--reclaim-disks` is the default in current `ac`, and `--reclaim-disks=false` is refused before anything is deleted. Keep the flag in the command so that it also works with earlier versions of `ac`, where it is off by default and a destroy without it does not finish.

`destroy` removes only objects that carry the cluster's ownership label. The vCenter folders, datastores, port groups, and templates are left in place. The provider deletes the credential Secret with the cluster, so create it again before you recreate the cluster. `--cluster global` is refused.

If the `Cluster` stays in `Deleting`, see [Troubleshoot a Cluster Stuck in Deleting](../troubleshooting/troubleshoot-cluster-stuck-deleting.mdx).
