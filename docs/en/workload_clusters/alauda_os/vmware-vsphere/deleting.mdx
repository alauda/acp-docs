# Delete a Cluster on VMware vSphere \{#delete-with-ac}

Delete the cluster with `--reclaim-disks`, so that its persistent disks are deleted with it:

```bash
ac adm alpha cluster destroy --dir <install-dir> --reclaim-disks     # preferred: manifests/ records what ac rendered
ac adm alpha cluster destroy --cluster <cluster-name> --reclaim-disks # without the directory
```

`destroy` lists what it will delete and asks you to type the cluster name; `--yes` skips the prompt and is required when standard input is not a terminal. It deletes the Cluster API `Cluster` first and waits for the machines to go, then removes the remaining objects that `ac` rendered. If it is interrupted, run it again; it resumes where it stopped.

The machine config pools delete their persistent disks only after `releaseDelayHours`, and they need the vCenter credential to do it. Without `--reclaim-disks`, `destroy` removes the credential chain before that delay ends, and the disks stay allocated in the datastore with nothing left to delete them. `--reclaim-disks` sets the delay to zero first, so each disk is deleted as soon as its machine is gone. A destroy that was interrupted with `--reclaim-disks` must be resumed with it. See [Persistent disk lifecycle](./reference/install-config-parameters.mdx#persistent-disk-lifecycle).

`destroy` removes only objects that carry the cluster's ownership label. The vCenter folders, datastores, port groups, and templates are left in place. The provider deletes the credential Secret with the cluster, so create it again before you recreate the cluster. `--cluster global` is refused.

If the `Cluster` stays in `Deleting`, see [Troubleshoot a Cluster Stuck in Deleting](../troubleshooting/troubleshoot-cluster-stuck-deleting.mdx).
