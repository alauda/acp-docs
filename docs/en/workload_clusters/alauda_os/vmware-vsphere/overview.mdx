# VMware vSphere Provider

<Overview />

The Infrastructure Provider for Virtualization Platform creates Alauda OS clusters on VMware vSphere: it clones every node from a VM template through vCenter. When you plan a cluster, note what is specific to vSphere:

- Every node has a hostname and a static IPv4 address that you list in `install-config.yaml`. There is no DHCP, and each node group has its own pool of these slots.
- The control plane endpoint is your external load balancer, the default, or a Self-built VIP that the provider runs on the control plane nodes. The choice is fixed when the cluster is created.
- `/var/cpaas` and raw data disks are persistent: when a VM is replaced, they are reattached to its replacement. The containerd, kubelet, and etcd disks are recreated with the VM.
- A released persistent disk is deleted after `releaseDelayHours`. Delete a cluster with `--reclaim-disks` to delete its persistent disks with it.

## How It Works \{#how-it-works}

![VMware vSphere Cluster API resource dependencies](./assets/vsphere-resource-dependency.svg)

`ac` renders one `VSphereMachineConfigPool` and one `VSphereMachineTemplate` per node group. The pool's slots hold the hostnames, the static addresses, and the persistent disks of that group. The vSphere cloud provider (CPI) reaches the workload cluster through a `ClusterResourceSet` on the `global` cluster; until it runs, the nodes stay uninitialized.
