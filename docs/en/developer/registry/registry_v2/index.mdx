# <Term name="product" /> Registry Image Use

Use this section for developer and workload access to the Operator-managed <Term name="productShort" /> Registry.

Registry administrator tasks, including installation, configuration, and exposure, are documented in
[Alauda Container Platform Registry administration](../../../configure/registry/registry_v2/index.mdx).

The legacy Registry documentation remains available under [Legacy Registry workflows](../how_to/index.mdx)
for environments that still use the earlier `cpaas-system` Registry service.

## Documentation Structure

| Need | Continue with |
| --- | --- |
| Access the Registry from workloads or external clients. | [Accessing the registry](./accessing_the_registry.mdx) |
| Use `ac` to list, tag, import, mirror, delete, and inspect images. | [Managing images with ac](./managing_images_with_ac.mdx) |
| Review Operator-managed Registry components and administrator settings. | [Registry administration](../../../configure/registry/registry_v2/index.mdx) |

## Standard Address

Use the fully qualified internal service address for workloads running in the cluster:

```text
image-registry.image-registry-system.svc:5000
```

Use an external Ingress hostname only for developer machines, CI systems, or other clients outside the cluster. See [Exposing the registry](../../../configure/registry/registry_v2/exposing_the_registry.mdx).
