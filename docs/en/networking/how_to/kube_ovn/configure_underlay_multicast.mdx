# Configure Multicast for Kube-OVN Underlay Networks

This guide describes how to enable IPv4 multicast communication for workloads in a Kube-OVN Underlay subnet. After multicast snooping is enabled for a subnet, Kube-OVN configures multicast snooping and a multicast querier on the corresponding OVN logical switch.

This configuration applies to each subnet independently. It does not configure multicast routing between different Layer 3 networks or configure vendor-specific physical switches.

## Before You Begin

Make sure the following conditions are met:

- The target subnet is a Kube-OVN Underlay subnet.
- The physical network has been prepared according to [Preparing Kube-OVN Underlay Physical Network](./kubeovn_underlay_py.mdx).
- The subnet has at least one available IP address. Kube-OVN automatically allocates an IP address and a MAC address to the multicast querier.
- The physical network permits the multicast group and IGMP traffic used by the application.

If IGMP snooping is enabled on the physical switches, work with the network administrator to verify that multicast membership can be learned on the VLAN ports connected to the cluster nodes and external receivers. The querier and IGMP snooping behavior of physical switches varies by vendor.

## Enable Multicast Snooping

### Using the Web Console

1. Switch to **Administrator**.

2. From the **Cluster** drop-down list at the top, select the target cluster.

3. In the left navigation bar, expand **Clusters**, and then click **Resources**.

4. In the resource search box, enter **Subnet**. Expand **Correlated with Cluster**, and then select **Subnet** (`kubeovn.io`).

5. Click the action menu (⋮) next to the target Underlay subnet, and then select **Update**.

6. Add `enableMulticastSnoop: true` to `spec`:

   ```yaml
   spec:
     enableMulticastSnoop: true
   ```

7. Click **Update**.

Repeat these steps for every Underlay subnet that needs to carry multicast traffic.

### Using the CLI

Run the following command to enable multicast snooping for the target subnet:

```shell
kubectl patch subnet <subnet-name> --type=merge \
  -p '{"spec":{"enableMulticastSnoop":true}}'
```

## Verify the Configuration

Run the following command:

```shell
kubectl get subnet <subnet-name> \
  -o jsonpath='{.spec.enableMulticastSnoop}{"\n"}{.status.mcastQuerierIP}{"\n"}{.status.mcastQuerierMAC}{"\n"}'
```

The output contains three lines:

1. `true`, indicating that multicast snooping is enabled.
2. The IP address allocated to the multicast querier.
3. The MAC address allocated to the multicast querier.

If the querier IP or MAC address is empty, make sure the subnet has an available IP address.

## Verify Multicast Traffic

The following example uses the IPv4 multicast group `239.255.0.1`. Run the commands in test containers that have `socat` installed and are connected to the target Underlay subnet.

On the receiving workload, join the multicast group and listen on UDP port `5000`:

```shell
socat -v \
  UDP4-RECVFROM:5000,reuseaddr,ip-add-membership=239.255.0.1:<receiver-underlay-ip>,fork \
  -
```

On the sending workload, send a test message through its Underlay IP address:

```shell
printf 'multicast-test\n' | socat - \
  UDP4-DATAGRAM:239.255.0.1:5000,ip-multicast-if=<sender-underlay-ip>,ip-multicast-ttl=16
```

The receiver should display `multicast-test`. Repeat the test for the paths required by the application:

- Sender and receiver Pods on the same node.
- Sender and receiver Pods on different nodes.
- A Pod and an external host in the same Underlay Layer 2 network.

If same-node communication succeeds but cross-node or external communication fails intermittently, first verify the VLAN path, IGMP membership, and querier state on the physical switches. Also confirm that the application joins the multicast group on the correct Underlay interface.

## Disable Multicast Snooping

To disable multicast snooping and release the querier IP and MAC address, run:

```shell
kubectl patch subnet <subnet-name> --type=merge \
  -p '{"spec":{"enableMulticastSnoop":false}}'
```
