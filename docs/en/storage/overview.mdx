# Overview

Alauda Container Platform documents three storage systems. Choose one based on how volumes are provisioned and whether data must survive a node failure.

Do not use Local Storage and LVM Storage as interchangeable names. Local Storage is the static local-disk provisioner. LVM Storage is the TopoLVM-based dynamic provisioner.

## Choose a storage system

| Storage system | Provisioning | Typical use | Data protection |
| --- | --- | --- | --- |
| **Local Storage** | Static. One PersistentVolume per listed disk or partition. | Expose a specific local disk to a workload, including as a Block volume consumed by another storage system. The Marketplace package name is **Alauda Container Platform Local Disk Provisioner**. | A node failure makes the volume unavailable. A disk failure can cause data loss. |
| **LVM Storage** | Dynamic. TopoLVM carves logical volumes from node volume groups. | Databases and caches that need low-latency local volumes and PVC resize. The Marketplace package name is **Alauda Container Platform LVM Volume Provisioner**. | A node failure makes the volume unavailable. A disk failure can cause data loss. |
| **Ceph Distributed Storage** | Dynamic. Replicated or erasure-coded pools. | Shared block, file, and object storage that must survive a node failure. | Replicas or erasure coding across nodes. |
