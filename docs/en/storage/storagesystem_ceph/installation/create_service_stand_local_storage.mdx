# Deploying in Internal Mode with Local Storage

This Internal Mode path creates a Ceph cluster in the current business cluster and backs OSDs with Block PersistentVolumes from **Local Storage**. It is the same Internal Mode as [Deploying in Internal Mode](./create_service_stand.mdx), except OSD devices come from Local Storage volumes instead of host paths selected in the wizard.

Do not mix host devices and `storageClassDeviceSets` on the same `CephCluster`.

This procedure applies a `CephCluster` directly. It is not the Distributed Storage **Create Cluster** wizard.

## Prerequisites

- **Alauda Container Platform Storage Essentials** and **Alauda Build of Rook-Ceph** are installed. Follow the operator install steps in [Deploying in Internal Mode](./create_service_stand.mdx), then stop before **Create Cluster**.
- **Alauda Build of LocalStorage** is installed. See [Install Local Storage](../../local_storage/installation.mdx).
- You have provisioned Block PersistentVolumes that are `Available`. Use [Provision with LocalVolume](../../local_storage/functions/local_volume.mdx) or [Provision with LocalVolumeSet](../../local_storage/functions/local_volume_set.mdx). Do not repeat those steps here.
- You have at least three `Available` Block PersistentVolumes, typically one per storage node. The StorageClass name is the one you set on the `LocalVolume` or `LocalVolumeSet` (for example `localblock`).
- At least three nodes will run OSDs.

## Procedure

### 1. Confirm Available Block volumes

```bash
kubectl get pv -o custom-columns=NAME:.metadata.name,STATUS:.status.phase,SC:.spec.storageClassName,MODE:.spec.volumeMode,CAPACITY:.spec.capacity.storage
```

Each OSD consumes one Block PersistentVolume from that StorageClass. `count` in the next step must not exceed the number of `Available` volumes.

### 2. Get the Ceph image from the Operator

After **Alauda Build of Rook-Ceph** is installed, copy the unique CSV `relatedImages` entry whose `name` is `ceph`. Do not invent a tag.

```bash
kubectl get csv -A -o jsonpath='{range .items[*]}{range .spec.relatedImages[*]}{.name}{"\t"}{.image}{"\n"}{end}{end}' | grep '^ceph[[:space:]]'
```

### 3. Create the CephCluster

Create the `rook-ceph` namespace if it does not exist, then apply the cluster. Replace `<ceph-image-from-csv>` and `localblock` with your values. Set `resources.requests.storage` no larger than the smallest Available PersistentVolume.

```yaml
cat << EOF | kubectl apply -f -
apiVersion: v1
kind: Namespace
metadata:
  name: rook-ceph
---
apiVersion: ceph.rook.io/v1
kind: CephCluster
metadata:
  name: ceph-cluster
  namespace: rook-ceph
spec:
  dataDirHostPath: /var/lib/rook
  cephVersion:
    image: <ceph-image-from-csv> # [!code callout]
  mon:
    count: 3
    allowMultiplePerNode: false
  storage:
    storageClassDeviceSets:
      - name: local-osds
        count: 3 # [!code callout]
        portable: false # [!code callout]
        volumeClaimTemplates:
          - metadata:
              name: data
            spec:
              storageClassName: localblock # [!code callout]
              volumeMode: Block
              accessModes:
                - ReadWriteOnce
              resources:
                requests:
                  storage: 100Gi # [!code callout]
EOF
```

<Callouts>
1. Ceph image from the installed Operator CSV `relatedImages` entry named `ceph`.
2. Number of OSDs Rook creates from this set. Each OSD binds one Block PersistentVolume. Increase `count` only after more `Available` volumes exist.
3. Must be `false` for Local Storage. Local volumes cannot move to another node.
4. StorageClass created by your `LocalVolume` or `LocalVolumeSet`. The PVC `volumeMode` must be `Block`.
5. Must be less than or equal to the smallest matching PersistentVolume capacity.
</Callouts>

### 4. Verify OSDs

```bash
kubectl -n rook-ceph get pod -l app=rook-ceph-osd
kubectl -n rook-ceph get cephcluster ceph-cluster -o jsonpath='{.status.ceph.health}{"\n"}'
```

Wait until three OSD pods are running and health is `HEALTH_OK` or `HEALTH_WARN` only for expected start-up notes.

## Scale OSDs

1. Provision additional Block PersistentVolumes with the same StorageClass. See [Guides](../../local_storage/functions/index.mdx).
2. Confirm they are `Available`.
3. Edit the cluster and increase `spec.storage.storageClassDeviceSets[].count` to match the new total. Change only `count`. Do not replace the rest of the device set.

   ```bash
   kubectl -n rook-ceph edit cephcluster ceph-cluster
   ```

Do not lower `count` to remove OSDs. That is not a supported scale-in path on this page.
