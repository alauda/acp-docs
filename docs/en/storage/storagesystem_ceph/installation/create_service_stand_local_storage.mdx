# Deploying in Internal Mode with Local Storage

This Internal Mode path creates a Ceph cluster in the current business cluster and backs OSDs with Block PersistentVolumes from **Local Storage**. Configure cluster type, snapshots, monitoring, and advanced options in the Distributed Storage wizard, then switch to YAML and replace `spec.storage` so Rook consumes Local Storage volumes instead of host devices.

Do not mix host devices (`spec.storage.nodes`) and `storageClassDeviceSets` on the same `CephCluster`.

## Prerequisites

- At least three nodes will run OSDs.
- Each of those nodes has at least one unused disk that is not mounted and has no partitions.
- **Download** and **Upload** the installation packages for **Alauda Container Platform Storage Essentials**, **Alauda Build of Rook-Ceph**, and **Alauda Build of LocalStorage**.

## Procedure

<Steps>

### 1. Install Alauda Build of LocalStorage and provision Block volumes

Install the operator as described in [Install Local Storage](../../local_storage/installation.mdx).

Confirm the operator is running:

```bash
kubectl -n acp-storage get csv | grep local-storage
```

Example output:

```bash
local-storage-operator.v4.5.0   Alauda Build of LocalStorage   Succeeded
```

Provision one Block PersistentVolume per OSD. The following `LocalVolumeSet` claims at most one whole disk per selected node and creates StorageClass `localblock`. Replace the hostnames with `kubectl get node` values. For exact device paths, use [Provision with LocalVolume](../../local_storage/functions/local_volume.mdx) instead.

```yaml
cat << EOF | kubectl apply -f -
apiVersion: local.storage.openshift.io/v1alpha1
kind: LocalVolumeSet
metadata:
  name: local-block-disks
  namespace: acp-storage
spec:
  storageClassName: localblock
  volumeMode: Block
  maxDeviceCount: 1
  nodeSelector:
    nodeSelectorTerms:
      - matchExpressions:
          - key: kubernetes.io/hostname
            operator: In
            values:
              - worker-01
              - worker-02
              - worker-03
  deviceInclusionSpec:
    deviceTypes:
      - disk
EOF
```

Check the `LocalVolumeSet` and StorageClass:

```bash
kubectl -n acp-storage get localvolumeset local-block-disks
kubectl get sc localblock
```

Example output:

```bash
NAME                AGE
local-block-disks   45s

NAME         PROVISIONER                    RECLAIMPOLICY   VOLUMEBINDINGMODE      ALLOWVOLUMEEXPANSION   AGE
localblock   kubernetes.io/no-provisioner   Delete          WaitForFirstConsumer   false                  45s
```

Check that Block PersistentVolumes are `Available`. You need at least as many as the OSD `count` you will set later (three in this example):

```bash
kubectl get pv -o custom-columns=NAME:.metadata.name,STATUS:.status.phase,SC:.spec.storageClassName,MODE:.spec.volumeMode,CAPACITY:.spec.capacity.storage
```

Example output:

```bash
NAME                STATUS      SC           MODE    CAPACITY
local-pv-1cec77cf   Available   localblock   Block   1Ti
local-pv-2ef7cd2a   Available   localblock   Block   1Ti
local-pv-3fa1c73    Available   localblock   Block   1Ti
```

If a volume is missing, inspect discovery results in [Discover local disks](../../local_storage/functions/device_discovery.mdx) and confirm the disk is `Available` and matches `deviceInclusionSpec`.

### 2. Deploy the Rook-Ceph Operator in the wizard

1. Login, go to the **Administrator** page.

2. In the left sidebar, click **Storage Management** > **Distributed Storage**.

3. Click **Configure Now**.

4. If **Alauda Container Platform Storage Essentials** is not installed, the wizard installs it first. Use the same OperatorHub values as [Deploying in Internal Mode](./create_service_stand.mdx): channel `stable`, installation mode `Cluster`, namespace **acp-storage**, upgrade strategy `Manual`.

5. On the **Install Operator** wizard page, click **Start Deployment** (or **Deploy Operator**) for **Alauda Build of Rook-Ceph**.

   - When the page proceeds to **Create Cluster**, the Operator is installed.
   - If deployment fails, follow the on-screen prompts, click **Clean Up**, and deploy the Operator again.

### 3. Create the cluster: fill the wizard, then edit YAML storage

1. On the **Create Cluster** wizard page, set **Cluster Type** to **Standard** (Internal Mode).

2. Configure everything **except host storage devices**:

   - **Snapshot** and **Monitoring Alarm**, as required.
   - **Advanced Configuration**: network, optimization parameters, and component placement. Place MON/MGR/MDS/RGW on at least three nodes when you use fixed-point deployment.

   Do not add **Device Class** host devices (**Selection Device** or **Input Device**). Those fields write `spec.storage.nodes` and conflict with PVC-backed OSDs.

3. Switch the page from **Form** to **YAML**. The editor shows the `CephCluster` the wizard would create. Leave `cephVersion`, `network`, `mon`, `monitoring`, and other non-storage fields as generated.

4. Replace the entire `spec.storage` section. Remove `spec.storage.nodes` if it is present. Use the StorageClass from step 1 (`localblock` in the example). Set `count` to the number of `Available` Block PersistentVolumes you will consume.

   ```yaml
   spec:
     storage:
       storageClassDeviceSets:
         - name: local-osds
           count: 3 # [!code callout]
           portable: false # [!code callout]
           volumeClaimTemplates:
             - metadata:
                 name: data
               spec:
                 storageClassName: localblock # [!code callout]
                 volumeMode: Block
                 accessModes:
                   - ReadWriteOnce
                 resources:
                   requests:
                     storage: 1Gi # [!code callout]
   ```

   <Callouts>
   1. Number of OSDs. Each OSD binds one Block PersistentVolume. Do not set this higher than the number of `Available` volumes.
   2. Must be `false` for Local Storage. Local volumes cannot move to another node.
   3. StorageClass created by the `LocalVolume` or `LocalVolumeSet`. Must be Block.
   4. PVC request used only to bind an `Available` Block PersistentVolume. Kubernetes requires this field; do not omit it. The OSD uses the whole disk (for example `1Ti`), not this request. Set it less than or equal to the smallest matching PersistentVolume.
   </Callouts>

5. Click **Create Cluster** and wait for the wizard to finish.

6. Verify OSDs and the PVCs Rook created:

   ```bash
   kubectl -n rook-ceph get pod -l app=rook-ceph-osd
   kubectl -n rook-ceph get pvc
   kubectl -n rook-ceph get cephcluster ceph-cluster -o jsonpath='{.status.ceph.health}{"\n"}'
   ```

   Example PVC output after binding 1Ti local volumes with a `1Gi` request:

   ```bash
   NAME                    STATUS   VOLUME             CAPACITY   ACCESS MODES   STORAGECLASS   AGE
   local-osds-data-0-0-0   Bound    local-pv-1cec77cf  1Ti        RWO            localblock     2m
   local-osds-data-1-0-0   Bound    local-pv-2ef7cd2a  1Ti        RWO            localblock     2m
   local-osds-data-2-0-0   Bound    local-pv-3fa1c73   1Ti        RWO            localblock     2m
   ```

   `CAPACITY` is the PersistentVolume size (the disk). `.spec.resources.requests.storage` on the PVC remains the request from the template (`1Gi` in this example).

   Wait until three OSD pods are running and health is `HEALTH_OK`, or `HEALTH_WARN` only for expected start-up notes.

</Steps>

## Scale OSDs

1. Provision additional Block PersistentVolumes with the same StorageClass. See [Guides](../../local_storage/functions/index.mdx).
2. Confirm they are `Available`.
3. Edit the cluster and increase `spec.storage.storageClassDeviceSets[].count` to match the new total. Change only `count`. Do not replace the rest of the device set.

   ```bash
   kubectl -n rook-ceph edit cephcluster ceph-cluster
   ```

Do not lower `count` to remove OSDs. That is not a supported scale-in path on this page.
