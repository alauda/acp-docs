# violet CLI

The platform provides the **`violet`** command-line tool for downloading packages from the Customer Portal and uploading packages to <Term name="productShort" />.

Use **Violet v4.2.13 or later** for the documented download, inventory, and upload workflows.

For details, see [Download Packages](/extend/download_package) and [Upload Packages](/extend/upload_package).

## Addresses and Credentials \{#addresses-and-credentials}

Each command connects to the service it works on. Use the address and credentials of that service:

| Task | Commands | Address | Credentials |
| --- | --- | --- | --- |
| Download packages | `violet ac` | `--ac-url`: the address of the <Term name="company" /> Customer Portal that you sign in to. It is not the ACP address. | `--access-token`: an access token of your Customer Portal account, exported from **Settings** in the Customer Portal. Or `--account`, `--username`, and `--password` of that account. |
| List and publish Extensions | `violet list`, `violet push`, `violet gc` | `--platform-address`: the ACP platform address, `https://<platform-address>` | `--platform-token`: an ACP API token, created in the Web Console under **Profile** > **API Tokens**. Or `--platform-username` and `--platform-password`. |
| Push the images of a package | `violet push` | `--dest-repo`: the image registry that the target ACP cluster uses. Always set it. | `--username` and `--password` of a registry account that can push, or `--no-auth` |

For an external registry, including every new installation of ACP 4.5 or later, set `--dest-repo` to the address of the registry that you prepared, not to `cpaas-registry.cpaas-system`, the address that ACP records for it.

`violet push` pushes the images only to `--dest-repo`. When clusters use different registries, such as the standby `global` cluster or a workload cluster with its own registry, run `violet push` once for each registry: set `--dest-repo` to that registry and, for an Operator, `--clusters` to the clusters that use it. For the standby `global` cluster, also set `--platform-address` to its VIP.

`violet ac` needs access to the Customer Portal; `violet list` and `violet push` need access to ACP and its registry. They can run on different machines. In an air-gapped environment, download the packages on a machine that has access to the Customer Portal, or in the Customer Portal web console, and carry them to the machine that runs `violet push`.

## Troubleshooting \{#troubleshooting}

| Message | Cause and action |
| --- | --- |
| `violet ac login`: `token validation request returned status: 404 Not Found`, or `failed to fetch public key, status: 401 Unauthorized` | `--ac-url` is not the Customer Portal, for example the ACP address. Set it to the address of the Customer Portal that you sign in to. |
| `violet ac login`: `provided access token is invalid (401 Unauthorized)` | The token is not a Customer Portal access token, or it has expired. An ACP API token does not work here. Export a new token from the Customer Portal. |
| `violet ac login`: `Login failed: login failed with status: <status>` | Check the account, username, and password of your Customer Portal account. |
| `violet push` without `--dest-repo`: `no such host`, or `failed to get cluster global registry push address` | Set `--dest-repo` and the registry credentials. |
| A command with `--platform-token`: `failed to get user info from platform server` | Violet is earlier than v4.2.13. Upgrade Violet. |
