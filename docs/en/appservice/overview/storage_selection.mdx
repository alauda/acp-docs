# Storage Selection

Choose the storage before you create an instance. The storage class of a persistent volume claim (PVC) cannot be changed later, so moving to other storage means creating a new instance and moving the data. This page covers high availability and backup in a single <Term name="product" /> (<Term name="productShort" />) cluster in one data center.

## Selection Procedure

1. List the storage on site, using [Storage Types](#storage-types). Count enterprise storage only if it exists or is within the budget.
2. Find the rows of each instance and its backup in [Storage by Product](#by-product).
3. If you create MySQL-MGR, PostgreSQL, Redis, Kafka, or RabbitMQ in the console on storage other than TopoLVM, [make that storage selectable](#console).
4. Run the [pre-production checks](#verify).

Local Storage stays on its node like TopoLVM, so the node and disk limits of TopoLVM apply to it. The tables below do not rate it. The tables use enterprise object storage and Ceph Object Storage only for backups and Milvus data. For more, see [Overview](/storage/overview.mdx), [Access Modes and Volume Modes](/configure/storage/concepts/selection.mdx), and [Third-Party Storage Capability Annotation Guide](/configure/storage/how_to/third_mask.mdx).

### Storage Limits \{#limits}

- **TopoLVM**: a volume stays on its node and cannot span nodes. A node failure makes it unavailable, and a disk failure can lose its data. After a permanent loss, the replica restarts empty on another node once its PVC is deleted. In production, use device classes whose **Provision Type** is **Thick**, because a **Thin** device class over-provisions and a volume can run out of space before it reaches its requested size.
- **Enterprise SAN**: all replicas on one array share it as a failure domain. With 2 arrays, a majority of 3 replicas still sits on one array, so use 3 arrays to survive the loss of one. After an unexpected node shutdown, a volume might not detach. See [Detach CSI Volumes After Non-Graceful Node Shutdown](/configure/storage/trouble_shooting/detach_csi_volumes_non_graceful_shutdown.mdx). No product documentation lists a validated SAN.
- **Ceph RBD**: all replicas share one Ceph failure domain, and the default pool keeps 3 copies of each volume, so 3 replicas take 9 copies.

## Storage by Product \{#by-product}

Each cell gives a recommendation: **Recommended**, **Secondary** (when the recommended storage is not available or does not fit), **Last resort** (test it first, and see [Storage Limits](#limits)), **Testing only** (only where data loss is acceptable), or **Avoid**. Two **Recommended** cells in a row are equal choices. A dash means not applicable or not evaluated.

Back up to a different device from the primary data. Where the product supports it, register the backup target in [Backup Management](/appservice/unified-om/backup-mgt/index.mdx), also called **Backup Center**. If the primary data is in Ceph, back up outside that Ceph cluster.

- Prefer the SAN over TopoLVM only when a full rebuild of the largest replica takes too long, the SAN passes your commit latency test, and you accept the array as a shared failure domain.
- For a recovery point objective (RPO) of 0, use synchronous replication: MySQL-MGR with 3 or 5 members, PostgreSQL with `spec.patroni.synchronous_mode` and `synchronous_mode_strict` set to `true`, and CloudNativePG with `spec.postgresql.synchronous` and `dataDurability` not set to `preferred`. Run at least 3 replicas so that losing one does not stop writes. PostgreSQL and CloudNativePG pause writes when too few synchronous standbys remain.

## Storage Classes in the Console \{#console}

The instance forms of MySQL-MGR, PostgreSQL, Redis, Kafka, and RabbitMQ offer only TopoLVM by default. To offer another storage class, an administrator adds its provisioner to the `middleware-sc-cm` ConfigMap in the `cpaas-system` namespace of the `global` cluster, under the component key `MGR`, `PostgreSQL`, `Redis`, `Kafka`, or `RabbitMQ`. Do not edit `middleware-sc-cm-base`.

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: middleware-sc-cm
  namespace: cpaas-system
data:
  middleware_sc_map.yaml: |
    Redis:
      instance:
        - rook-ceph.rbd.csi.ceph.com
```

The `Redis.backup` key lists the provisioners allowed for Redis PVC backups, and from Data Services Essentials v4.4.1 it allows NFS, CephFS, and TopoLVM by default. The ConfigMap has no keys for Valkey, CloudNativePG, ClickHouse, OpenSearch, or Milvus. Set their storage class in the custom resource, for Valkey in `spec.storage.storageClassName`.

## Pre-Production Checks \{#verify}

The product documentation gives no performance thresholds, so test against your own requirements:

- Commit latency for databases, ClickHouse Keeper, and Milvus etcd, especially on an enterprise SAN or Ceph RBD.
- Throughput on Ceph RBD, and the rebuild time of the largest replica on TopoLVM.
- Recovery after you shut down a node. See [Node and Disk Loss](#node-loss) for what each product documents.
- A restore into a new instance, repeated regularly.

## Node and Disk Loss \{#node-loss}

On TopoLVM and Local Storage, check what the product documents before you delete the PVC of a replica on a lost node:

| Product | Product documentation |
| --- | --- |
| MySQL-MGR | Recovery needs manual reprovisioning and data resync. See <ExternalSiteLink name="mysql-mgr" href="/how_to/40-deploy-without-topolvm.html" children="Deploy MySQL-MGR Without TopoLVM" />. |
| CloudNativePG | In v1.30.1-acp.1, PVC replacement was tested with RPO = 0, and node shutdown was not tested. See <ExternalSiteLink name="cnpg" href="/release_notes.html" children="Release Notes" />. |
| Valkey | Do not delete the PVC until the recovery procedure is known. See <ExternalSiteLink name="valkey" href="/trouble_shooting/10-instance-not-ready.html" children="Diagnose an instance that is not Ready" />. |
| ClickHouse Keeper | Losing 2 of 3 members, or the Keeper volumes, makes replicated tables read-only. See <ExternalSiteLink name="clickhouse" href="/how_to/deploy_keeper_quorum.html" children="Deploy a Keeper quorum" />. |
| OpenSearch | Keep `number_of_replicas` at 1 or more so that no data is lost. See <ExternalSiteLink name="opensearch" href="/functions/storage.html" children="Storage" />. |
| Others | Not documented. Test the recovery first. RabbitMQ quorum queue membership might need manual repair. |
