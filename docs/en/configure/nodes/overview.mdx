# Overview

Nodes are the fundamental building blocks of a cluster. Nodes can be virtual machines or physical servers, and each node runs the components required to host Pods, including kubelet, kube-proxy, and the container runtime.

Users with platform management permissions can add, manage, and plan nodes under clusters.

:::note
Adding nodes to imported clusters or deleting nodes from imported clusters is not supported.
:::

## Node types

- **Control plane nodes** run cluster components such as kube-apiserver, kube-scheduler, kube-controller-manager, etcd, container networking, and some platform management components.
- **Worker nodes** host business Pods running on the cluster. Plan worker node count based on workload demand.

## Node operation paths

The following tasks apply to clusters whose nodes run Alauda OS and to clusters whose nodes run a non-Alauda OS.

Nodes on Alauda OS clusters are managed through Cluster API resources and are replaced rather than changed in place.

| --- | --- |

## Linux node availability check \{#node_checks}

Before building a workload cluster on a non-Alauda OS, complete the [node checks](/install/non_alauda_os/node_preprocessing.mdx#node_checks) and confirm that every node meets the requirements. Cluster deployment can fail when prerequisites are not satisfied.
