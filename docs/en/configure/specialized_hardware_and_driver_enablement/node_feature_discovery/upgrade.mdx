# Upgrade Node Feature Discovery

## Upgrade the Operator

1. Record the current Subscription, CSV, `NodeFeatureDiscovery` resource, and
   Helm release state.
2. Upload the target `nfd-operator` package following [Upload
   Packages](../../../extend/upload_package.mdx).
3. In **Administrator** > **Marketplace** > **OperatorHub**, switch to the
   target cluster and approve the target InstallPlan if approval is manual.
4. Wait for the target CSV to report **Succeeded**.
5. Verify that the existing `NodeFeatureDiscovery` resource remains present and
   reports `Deployed=True`.

The Operator upgrade preserves the CR and its values. The NFD operand image
changes only when the CR's `spec.image.tag` is changed. If the CR explicitly
pins an image tag, update that field deliberately and verify the resulting Helm
release revision and operand image IDs.

## Verify the upgrade

```bash
kubectl -n node-feature-discovery get subscription,csv
kubectl -n node-feature-discovery get nodefeaturediscovery node-feature-discovery -o yaml
kubectl -n node-feature-discovery get deployment,daemonset,pods
kubectl get nodes --show-labels
```

Confirm the CR UID and non-image fields are preserved, all NFD workloads are
ready, and the expected `feature.node.kubernetes.io/*` labels remain present.

Downgrade is not validated. If the CR or operand does not become ready, retain
the evidence and contact support before changing versions again.

## Migrate from the Cluster Plugin

The former NFD Cluster Plugin cannot be upgraded in place to the `nfd-operator`
Operator Bundle. Uninstall the old Cluster Plugin, verify that its workloads
and labels are cleaned up, then install the Operator and create the
`NodeFeatureDiscovery` resource as described on the [Install Node Feature
Discovery](./install.mdx) page.
