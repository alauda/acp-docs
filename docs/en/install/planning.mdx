# Plan

Before you start the installation, choose the deployment architecture and confirm the installation settings that affect later operations. These decisions apply to both installation paths: [Install on Alauda OS](./alauda_os/index.mdx) and [Install on Non-Alauda OS](./non_alauda_os/installing.mdx).

<Directive type="info" title="INFO">
The <Term name="productShort" /> installation deploys the `global` cluster on new nodes: nodes that you prepare on a non-Alauda OS, or Alauda OS nodes that the installation provisions through an infrastructure provider. It does not support direct installation of the `global` cluster into an existing Kubernetes environment.
</Directive>

## Choose a Deployment Architecture

Choose the architecture that matches your business scenario, management model, workload placement, resource planning, and isolation requirements.

| Architecture | Use when | Planning notes |
| --- | --- | --- |
| Multi-Cluster | You need one `global` cluster to manage multiple workload clusters. | Avoid running non-platform workloads on the `global` cluster. Plan resources for the expected number of managed workload clusters. |
| Single Cluster | You intentionally use one cluster for platform components and application workloads. | Single Cluster supports production use when it fits the business scenario. Because the `global` cluster also runs application workloads, plan resources and platform/workload isolation before installation. |
| Single Node | You need a test or proof-of-concept environment. | Do not use Single Node for production. |

For resource requirements and sizing guidance on a non-Alauda OS, see [Prerequisites](./non_alauda_os/prerequisites.mdx). For Alauda OS, see [Common Prerequisites](./alauda_os/installing.mdx#common-prerequisites) and [Bootstrap Node Requirements](./alauda_os/installing.mdx#bootstrap-host-requirements).

## Confirm Install-Time Decisions

Confirm the following decisions before you start the installation. The last two columns link to the page that documents each decision on each path.

| Decision | What to confirm | Non-Alauda OS | Alauda OS |
| --- | --- | --- | --- |
| Installation packages | Choose an x86, ARM, or hybrid Core Package and download the required Aligned Extension packages for the same <Term name="productShort" /> version and architecture. On Alauda OS, also prepare the provider packages and the Alauda OS image or VM template. | [Download](./prepare/download.mdx) | [Download](./prepare/download.mdx) and [Common Prerequisites](./alauda_os/installing.mdx#common-prerequisites) |
| Cluster network protocol | On a non-Alauda OS, choose IPv4, IPv6, or dual stack before starting the installer. On Alauda OS, plan the Pod and Service CIDR ranges. | [Installing](./non_alauda_os/installing.mdx#start_installer) | [Common Prerequisites](./alauda_os/installing.mdx#common-prerequisites) |
| Cluster Endpoint and Platform Access Address | Prepare the access addresses that cluster components, administrators, and users will use. | [Prerequisites](./non_alauda_os/prerequisites.mdx#network-resources) and [Installer Parameters](./non_alauda_os/installer-parameters.mdx) | [Common Prerequisites](./alauda_os/installing.mdx#common-prerequisites) and [Plan the Control Plane Endpoint](../workload_clusters/alauda_os/prepare/control-plane-endpoint.mdx) |
| Load balancing | Decide whether to use an external load balancer or Self-built VIP. On Alauda OS, the endpoint modes available depend on the provider. | [Prerequisites](./non_alauda_os/prerequisites.mdx#network-resources) and [LoadBalancer Forwarding Rules](./non_alauda_os/prerequisites.mdx#port-forward) | [Plan the Control Plane Endpoint](../workload_clusters/alauda_os/prepare/control-plane-endpoint.mdx) |
| Certificates | Decide whether to use installer-generated self-signed certificates or trusted certificates that you provide. | [Prerequisites](./non_alauda_os/prerequisites.mdx#network-resources) and [Installer Parameters](./non_alauda_os/installer-parameters.mdx) | [Trigger the Platform Installation](./alauda_os/installing.mdx#trigger-platform-installation) |
| Platform image source | Decide whether to use the platform built-in Registry or a customer-managed external platform image registry. For new production deployments, use an external registry when it meets the documented availability and lifecycle requirements. | [Prepare an External Platform Image Registry](./prepare/external-platform-image-registry.mdx) and [Installer Parameters](./non_alauda_os/installer-parameters.mdx) | [Trigger the Platform Installation](./alauda_os/installing.mdx#trigger-platform-installation) |
| Nodes | Confirm node names, node roles, and whether platform node isolation is required. | [Node Preprocessing](./non_alauda_os/node_preprocessing.mdx) and [Installer Parameters](./non_alauda_os/installer-parameters.mdx) | [Common Prerequisites](./alauda_os/installing.mdx#common-prerequisites) |
| Global Cluster Disaster Recovery | Decide whether your environment requires primary and standby `global` clusters. | [Global Cluster Disaster Recovery](./non_alauda_os/global_dr.mdx) | [Global Cluster Disaster Recovery](./alauda_os/global_dr.mdx) and [Optional Disaster Recovery Deployment](./alauda_os/installing.mdx#optional-disaster-recovery-deployment) |

If you plan to use Global Cluster Disaster Recovery, read the Global Cluster Disaster Recovery page for your installation path before installing <Term name="productShort" /> Core. Disaster recovery planning affects domain names, VIPs, certificates, load balancer rules, image registry choices, package architecture, and installation parameter consistency.

## Read Before You Install

Use the following pages as the source of truth before you start the installation.

For both installation paths:

- [Disk Configuration Requirements](../configure/scalability/disk_configuration.mdx): Confirm disk capacity and performance requirements.
- [Download](./prepare/download.mdx): Download the Core Package and `Common ACP Extensions` separately, and verify that their version and architecture match.
- [Prepare an External Platform Image Registry](./prepare/external-platform-image-registry.mdx): If selected, upload the complete target-version Core and Extension payload before starting the installer.

For a non-Alauda OS:

- [Prerequisites](./non_alauda_os/prerequisites.mdx): Prepare resource, network, and storage requirements.
- [Node Preprocessing](./non_alauda_os/node_preprocessing.mdx): Check and prepare each node before installation.
- [Global Cluster Disaster Recovery](./non_alauda_os/global_dr.mdx): Plan primary and standby `global` clusters if disaster recovery is required.
- [Installing](./non_alauda_os/installing.mdx): Upload the Core Package, stage required packages, and start the installer.
- [Installer Parameters](./non_alauda_os/installer-parameters.mdx): Configure the installation choices in the Web UI.

For Alauda OS:

- [Installing the global Cluster](./alauda_os/installing.mdx): Meet the common prerequisites and bootstrap node requirements, then install the `global` cluster through the bootstrap cluster for your provider.
- [Global Cluster Disaster Recovery](./alauda_os/global_dr.mdx): Plan primary and standby `global` clusters if disaster recovery is required.
