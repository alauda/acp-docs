# Prerequisites

First prepare the resources that every installation needs, as listed in [Prepare Resources](../prepare/planning.mdx#prepare-resources): the nodes and their sizes, the network, the addresses and domain name, your own certificate if you use one, the installation packages, and the external platform image registry. This page lists the additional requirements on a non-Alauda OS.

:::info
1. The platform currently does not support direct installation of the `global` cluster in an existing Kubernetes environment. If your environment already has a Kubernetes cluster, please back up your data and clean the environment before installation.
2. If you plan to use global Cluster Disaster Recovery, please first read [global Cluster Disaster Recovery](./global_dr.mdx).
3. Make sure all of the new nodes meet the [Nodes Requirements](./node_preprocessing.mdx).
:::

## Network \{#network-resources}

If a hardware LoadBalancer is available in your environment, it is **recommended** to use it. If not, you can enable `Self-built VIP`, which provides software load balancing using keepalived. For the network requirements of `Self-built VIP`, see [Self-built VIP](../prepare/communication_matrix.mdx#self_built_vip).

In the installer, enter the `global` VIP as the Cluster Endpoint. The Cluster Endpoint does not take a domain name. The API server certificate is issued by the cluster's own CA, so a domain name on the cluster endpoint cannot carry a customer-issued certificate.

### LoadBalancer Forwarding Rules \{#port-forward}

Configure the load balancer of the `global` cluster to forward the ports marked in the **Forward on load balancer** column of [Platform Access Address and `global` VIP](../prepare/communication_matrix.mdx#global_vip) to all control plane nodes. That section also covers a custom HTTPS port, HTTP access, and global disaster recovery. The platform built-in Registry port applies only to a `global` cluster upgraded from an earlier version that still uses that registry.

## External Platform Image Registry

A new installation of <Term name="productShort" /> 4.5 or later requires a customer-managed external platform image registry.

Before running `setup.sh`, complete [Prepare an External Platform Image Registry](../prepare/external-platform-image-registry.mdx). That page defines the required address, network access, storage, and push and pull permissions; separates those requirements from production recommendations; and explains how to upload the complete target-version payload.
