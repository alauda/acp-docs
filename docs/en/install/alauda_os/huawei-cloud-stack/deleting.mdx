# Delete the global Cluster on Huawei Cloud Stack

`destroy` deletes the `global` cluster and the Huawei Cloud Stack resources that it created, with the credential stored in the `global-credential` Secret. It refuses while the platform still manages another cluster; for this and the other rules every provider shares, see [The `destroy` Command](../reference.mdx#destroy).

## Before You Begin

- Delete every workload cluster that the platform manages.
- Detach in HCS any disk attached to the `global` instances that you need to keep: every disk still attached to an instance is deleted with it.
- Use a machine that reaches the `global` cluster and, on `TCP/443`, `ecs.<region>.<externalGlobalDomain>`, `evs.<region>.<externalGlobalDomain>`, and `vpc.<region>.<externalGlobalDomain>`, such as the bootstrap node. `destroy` uses HTTPS even when `schema` is `http`.

## Procedure \{#destroy}

On that machine:

```bash
<extract-dir>/res/<arch>/ac adm alpha global destroy --kubeconfig <install-dir>/output/kubeconfig
```

`destroy` lists each item, then asks you to type the cluster name. It deletes:

- The persistent and raw disks of the `HCSMachineConfigPool` objects. The instance is stopped and the disk detached first.
- Every ECS instance of the cluster, with its system and data disks and any other disk still attached to it.
- The control plane ELB with its listeners, pools, and health monitors, which releases the VIP and the L4 and L7 addresses.
- The control plane server group.

It keeps the VPC, subnets, security group and its rules, the image, and any DNS record. A disk that is attached to an instance of another cluster is kept and listed. An `HCSMachine` that never recorded an instance ID is listed and left to you.

If `destroy` stops, run the same command again; see [The `destroy` Command](../reference.mdx#destroy).
