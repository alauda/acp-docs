# install-config.yaml Parameters for Huawei Cloud Stack

This page lists the Huawei Cloud Stack fields of the `global` cluster's `install-config.yaml` and the objects that `ac` renders from them. The fields that every provider shares, such as `global.platform.cert`, `cluster.encryptionProviderConfig`, and the Pod, Service, and join CIDRs, are in [Installation Reference](../../reference.mdx#install-config).

## Optional Fields \{#optional-fields}

The template in [Create the global Cluster](../create_cluster.mdx#install-config) shows every optional field, with its default value or as a commented block. The topics that need more than a comment are as follows:

- Node placement: [Availability Zone Placement](../../../../workload_clusters/alauda_os/huawei-cloud-stack/reference/install-config-parameters.mdx#availability-zone-placement) and [Place Node Groups Separately](../../../../workload_clusters/alauda_os/huawei-cloud-stack/reference/install-config-parameters.mdx#node-group-overrides). The control plane spreads across hosts by default; see [Control Plane HA Placement](../../../../workload_clusters/alauda_os/huawei-cloud-stack/reference/install-config-parameters.mdx#control-plane-ha-placement).
- Additional NICs and raw disks: [Add a Second NIC](../../../../workload_clusters/alauda_os/huawei-cloud-stack/reference/install-config-parameters.mdx#add-a-second-nic) and [Add Raw Disks](../../../../workload_clusters/alauda_os/huawei-cloud-stack/reference/install-config-parameters.mdx#add-raw-disks).
- `deployMode`: [Platform Node Groups](../../reference.mdx#deploy-mode).

## Huawei Cloud Stack Fields \{#fields}

| Field | Required | Default | Description |
|---|---|---|---|
| `provider.hcs.credential` | Yes | — | `accessKey`, `secretKey`, `projectID`, `region`, and `externalGlobalDomain`; `schema` is `https` or `http`. `ac` renders it into the `global-credential` Secret. `credentialRef` is rejected. |
| `provider.hcs.imageName` | Yes | — | The image every node is created from. |
| `provider.hcs.flavorName` | Yes, unless every group sets its own | — | The ECS flavor. The flavor sets the size, so `cpuCore` and `memoryGiB` are rejected on every node group. |
| `provider.hcs.availabilityZone` | No | Chosen by the provider | A node group can override it. See [Availability Zone Placement](../../../../workload_clusters/alauda_os/huawei-cloud-stack/reference/install-config-parameters.mdx#availability-zone-placement). |
| `provider.hcs.rootDisk` | Yes, unless every group sets its own | — | `sizeGiB` greater than 0, and `type` `SSD`, `SAS`, or `SATA`, default `SSD`. |
| `provider.hcs.diskType` | No | `SSD` | The EVS type of the data disks. `disks.hcs.type` overrides it for one node group. |
| `provider.hcs.controlPlaneHA` | No | Enabled, `soft-anti-affinity` | The server group policy for the control plane instances: `soft-anti-affinity` or `anti-affinity`. |
| `provider.hcs.network` | Yes | — | `vpcName`, `securityGroupName`, and the node `subnetName`. `ac` collects every subnet named anywhere in the file into the `HCSCluster`. |
| `provider.hcs.elb.vipAddress` | Yes | — | The control plane VIP, an IPv4 address in the VIP subnet. |
| `provider.hcs.elb.vipSubnetName` | No | `network.subnetName` | The subnet of the VIP. |
| `provider.hcs.elb.l4.ips`, `provider.hcs.elb.l7.ips` | Yes | — | Exactly two distinct IPv4 addresses each. `subnetName` defaults to `network.subnetName`. |
| `cluster.network.loadBalancer` | No | — | Rejected: the control plane endpoint is the ELB under `provider.hcs.elb`. |
| `controlPlane.replicas` | Yes | — | An odd number: `1`, or `3` or more. The control plane runs stacked etcd. A cluster with a single control plane node is for testing and cannot be upgraded. |
| `*.hcs` | No | The `provider.hcs` values | `flavorName`, `availabilityZone`, `subnetName`, and `rootDisk` for one node group. A group's `rootDisk` replaces `provider.hcs.rootDisk`, so set both `sizeGiB` and `type`. |
| `*.network` | No | — | Only `additions`, each with an optional `hcs.subnetName`; empty takes the node group's subnet. `gateway`, `dns`, and `mask` are rejected, also on an addition: the subnet provides them. |
| `*.disks` | Yes | — | The standard disks are all required: `var-lib-containerd`, `var-lib-kubelet`, and `var-cpaas` on every group, and `var-lib-etcd` on the control plane. Other names are rejected; add extra volumes as `rawDisks`, raw block volumes for TopoLVM. `disks.hcs.type` overrides `provider.hcs.diskType` for one node group. |
| `*.hosts` | Yes | — | At least `replicas` entries, one per node: `hostname`, `ip`, and `additionalIps`, one address per `network.additions` entry, in order. |
| `computes[].name` | Yes | — | A DNS-1123 label, unique per group. `control-plane` is reserved. |

## Rendered Manifests \{#rendered-manifests}

`ac adm alpha global manifests` writes the following objects to `manifests/`, all in `cpaas-system`. For their API fields, see the [Provider APIs](../../../../apis/kubernetes_apis/infrastructure_providers/huawei-cloud-stack/index.mdx).

| Object | Name | Notes |
|---|---|---|
| `Secret` | `global-encryption-provider-config` | The encryption configuration, referenced by `HCSCluster`. |
| `Secret` | `global-credential` | The HCS API credential, referenced by `HCSCluster.spec.identityRef`. |
| `Cluster` | `global` | |
| `HCSCluster` | `global` | The network, the subnets, the control plane ELB, and `controlPlaneHA`. `ac` does not write `controlPlaneEndpoint`; the provider sets it from the ELB. |
| `KubeadmControlPlane`, `HCSMachineTemplate`, `HCSMachineConfigPool` | `global-control-plane` | The pool holds each node's address, hostname, and persistent and raw disks. |
| `MachineDeployment`, `HCSMachineTemplate`, `HCSMachineConfigPool` | `global-<group>` | One set per `computes` entry. |
| `KubeadmConfigTemplate` | `global-<group>-config` | One per `computes` entry. |
| `ConfigMap` | `dcs-import-extra-resources` | The manifest that the installer reads before it hands the cluster over. The name is the same on every provider. |

The ephemeral disks are data volumes of the `HCSMachineTemplate`, formatted as xfs and recreated with the instance. `var-cpaas` and the raw disks are declared in the `HCSMachineConfigPool`, so they are kept when an instance is replaced; raw disks have no mount path.

Do not delete the `global-credential` or `global-encryption-provider-config` Secret on the `global` cluster: without them, new control plane machines cannot be created.
