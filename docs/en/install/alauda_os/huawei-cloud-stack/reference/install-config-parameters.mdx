# install-config.yaml Parameters for Huawei Cloud Stack

This page lists the Huawei Cloud Stack fields of the `global` cluster's `install-config.yaml` and the objects that `ac` renders from them. The fields that every provider shares, such as `global.platform.cert`, `cluster.encryptionProviderConfig`, and the Pod, Service, and join CIDRs, are in [Installation Reference](../../reference.mdx#install-config).

## Optional Fields \{#optional-fields}

The template in [Create the global Cluster](../create_cluster.mdx#install-config) omits the optional fields. Add them where you need them:

```yaml
provider:
  hcs:
    credential:
      schema: https # [!code callout]
    availabilityZone: <az> # [!code callout]
    rootDisk:
      type: SSD # [!code callout]
    diskType: SSD # [!code callout]
    controlPlaneHA: # [!code callout]
      enabled: true
      policy: soft-anti-affinity # [!code callout]
    elb:
      vipSubnetName: <subnet-name> # [!code callout]
      l4:
        subnetName: <subnet-name> # [!code callout]
      l7:
        subnetName: <subnet-name>
controlPlane: # [!code callout]
  deployMode: normal # [!code callout]
  hcs: # [!code callout]
    flavorName: <flavor-name>
    availabilityZone: <az>
    subnetName: <subnet-name>
    rootDisk: # [!code callout]
      sizeGiB: <root-disk-gib>
      type: SSD
  network:
    additions: # [!code callout]
      - hcs:
          subnetName: <subnet-name>
  disks:
    rawDisks: # [!code callout]
      - name: data-001
        sizeGiB: 50
    hcs:
      type: SSD # [!code callout]
  hosts:
    - hostname: <cp-0-hostname>
      ip: <cp-0-ip>
      additionalIps: [<cp-0-nic2-ip>] # [!code callout]
```

<Callouts>

1. `schema`: optional. `https`, the default, or `http`.
2. `availabilityZone`: optional. Empty lets HCS choose one.
3. `rootDisk.type`: optional. `SSD`, the default, `SAS`, or `SATA`.
4. `diskType`: optional. The data disk type: `SSD`, the default, `SAS`, or `SATA`.
5. `controlPlaneHA`: optional. The default spreads the control plane across hosts.
6. `policy`: `soft-anti-affinity`, the default, or `anti-affinity`.
7. `vipSubnetName`: optional. Empty takes `network.subnetName`.
8. `l4.subnetName` and `l7.subnetName`: optional. Empty takes `network.subnetName`.
9. The same fields apply to each `computes` entry.
10. `deployMode`: `normal`, the default, or `base`.
11. `hcs`: overrides `provider.hcs` for this group only.
12. `rootDisk`: replaces `provider.hcs.rootDisk`; set both fields.
13. `additions`: additional NICs only, with no `gateway`, `dns`, or `mask`. Empty `subnetName` takes the node group's subnet.
14. `rawDisks`: raw block volumes for TopoLVM.
15. `disks.hcs.type`: optional. Overrides `provider.hcs.diskType` for this group only.
16. `additionalIps`: one per `network.additions` entry, in order.

</Callouts>

## Huawei Cloud Stack Fields \{#fields}

| Field | Required | Default | Description |
|---|---|---|---|
| `provider.hcs.credential` | Yes | — | `accessKey`, `secretKey`, `projectID`, `region`, and `externalGlobalDomain`; `schema` is `https` or `http`. `ac` renders it into the `global-credential` Secret, because there is no cluster yet to hold one. `credentialRef` is rejected. |
| `provider.hcs.imageName` | Yes | — | The image every node is created from. |
| `provider.hcs.flavorName` | Yes, unless every group sets its own | — | The ECS flavor. The flavor sets the size, so `cpuCore` and `memoryGiB` are rejected on every node group. |
| `provider.hcs.availabilityZone` | No | Chosen by HCS | A node group can override it. |
| `provider.hcs.rootDisk` | Yes | — | `sizeGiB` greater than 0, and `type` `SSD`, `SAS`, or `SATA`, default `SSD`. |
| `provider.hcs.diskType` | No | `SSD` | The EVS type of the data disks. `disks.hcs.type` overrides it for one node group. |
| `provider.hcs.controlPlaneHA` | No | Enabled, `soft-anti-affinity` | The server group policy for the control plane instances: `soft-anti-affinity` or `anti-affinity`. |
| `provider.hcs.network` | Yes | — | `vpcName`, `securityGroupName`, and the node `subnetName`. `ac` collects every subnet named anywhere in the file into the `HCSCluster`. |
| `provider.hcs.elb.vipAddress` | Yes | — | The control plane VIP, IPv4. |
| `provider.hcs.elb.vipSubnetName` | No | `network.subnetName` | The subnet of the VIP. |
| `provider.hcs.elb.vipDomainName` | No | — | Leave unset. The provider only uses it to backfill the derived control plane endpoint; cluster access by domain is not supported, and the API server certificate can only be issued by the cluster's own CA. |
| `provider.hcs.elb.l4.ips`, `provider.hcs.elb.l7.ips` | Yes | — | Exactly two distinct IPv4 addresses each. `subnetName` defaults to `network.subnetName`. |
| `controlPlane.replicas` | Yes | — | An odd number: `1`, or `3` or more. The control plane runs stacked etcd. A single control plane node is accepted but cannot be upgraded later: Cluster API cannot roll a single member out without creating its replacement first, and the fixed node addresses leave no room for it; plan `3` or more for a cluster you will upgrade. |
| `*.hcs` | No | The `provider.hcs` values | `flavorName`, `availabilityZone`, `subnetName`, and `rootDisk` for one node group. A group's `rootDisk` replaces `provider.hcs.rootDisk`, so set both `sizeGiB` and `type`. |
| `*.network` | No | — | Only `additions`, each with an optional `hcs.subnetName`. `gateway`, `dns`, and `mask` are rejected: the subnet provides them. |
| `*.disks` | Yes | — | The standard disks are all required: `var-lib-containerd`, `var-lib-kubelet`, and `var-cpaas` on every group, and `var-lib-etcd` on the control plane. Other names are rejected; add extra volumes as `rawDisks`. |
| `*.hosts` | Yes | — | One entry per node: `hostname`, `ip`, and `additionalIps` in the order of `network.additions`. |
| `computes[].name` | Yes | — | Unique per group. `control-plane` is reserved. |

## Rendered Manifests \{#rendered-manifests}

`ac adm alpha global manifests` writes the following objects to `manifests/`, all in `cpaas-system`. Field-level reference: [Huawei Cloud Stack Provider](../../../../workload_clusters/alauda_os/huawei-cloud-stack/overview.mdx).

| Object | Name | Notes |
|---|---|---|
| `Secret` | `global-encryption-provider-config` | The encryption configuration, referenced by `HCSCluster`. |
| `Secret` | `global-credential` | The HCS API credential, referenced by `HCSCluster.spec.identityRef`. |
| `Cluster` | `global` | |
| `HCSCluster` | `global` | The network, the subnets, the control plane ELB, and `controlPlaneHA`. `ac` does not write `controlPlaneEndpoint`; the provider sets it from the ELB. |
| `KubeadmControlPlane`, `HCSMachineTemplate`, `HCSMachineConfigPool` | `global-control-plane` | The pool holds each node's address, hostname, and persistent and raw disks. |
| `MachineDeployment`, `HCSMachineTemplate`, `HCSMachineConfigPool` | `global-<group>` | One set per `computes` entry. |
| `KubeadmConfigTemplate` | `global-<group>-config` | One per `computes` entry. |
| `ConfigMap` | `dcs-import-extra-resources` | The import list, described below. |

The ephemeral disks are data volumes of the `HCSMachineTemplate`, formatted as xfs and recreated with the instance. `var-cpaas` and the raw disks are declared in the `HCSMachineConfigPool`, so they are kept when an instance is replaced; raw disks have no mount path.

In stage 6, `cpaas-installer` imports the following into the `global` cluster:

- The `HCSCluster`, the `HCSMachineConfigPool` and `HCSMachineTemplate` objects, and every `HCSMachine`, with their status.
- The `global-credential` and `global-encryption-provider-config` Secrets, without status.

The provider serves the platform ELB listeners only for an `HCSCluster` named `global`, which is why every object carries that name. Stage 7 checks that every imported resource arrived.
