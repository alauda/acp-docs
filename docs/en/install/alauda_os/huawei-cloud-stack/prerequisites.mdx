# Prerequisites for Huawei Cloud Stack

Complete the [common prerequisites](../prerequisites.mdx) first. On Huawei Cloud Stack, the provider creates every node as an ECS instance from one image, gives it the address you list in `install-config.yaml`, and creates the control plane ELB itself. Prepare the following on Huawei Cloud Stack. `ac` creates none of them, and its preflight does not look them up: it checks only that the IAM endpoint answers. A wrong name surfaces in stage 4, when the provider creates the instances.

- **An HCS API credential**: the access key and secret key, the project ID, the region, and the external global domain of the HCS deployment.
- **An image created from the Alauda OS image**. It must carry the Kubernetes version of the Core Package; see [OS Support Matrix](../../../overview/alauda_os_support_matrix.mdx).
- **The ECS flavors** for the control plane and each worker group, by their API names.
- **A VPC, a security group, and every subnet** that `install-config.yaml` names: the node subnet, and any subnet for the ELB, an additional NIC, or a node group.
- **Free IPv4 addresses**: the control plane VIP, two L4 and two L7 addresses for the ELB, and one address per node. The ELB is created by the provider; you do not prepare a load balancer.
- **Quota** for the instances, the EVS disks, the ELB, and the server group. `ac` does not check quota.
- **The bootstrap node and the `global` cluster nodes reach the HCS API** under `<externalGlobalDomain>`, on `TCP/443` for `https` or `TCP/80` for `http`. The provider calls it from the bootstrap node until the handoff and from the `global` cluster afterwards, for scaling, upgrades, and `destroy`; preflight checks only the IAM endpoint `iam-apigateway-proxy.<externalGlobalDomain>`.
- **The bootstrap node reaches the control plane VIP** on `TCP/6443`.
