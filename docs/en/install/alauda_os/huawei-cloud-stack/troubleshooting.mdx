# Troubleshooting the global Cluster on Huawei Cloud Stack \{#troubleshooting}

For the installation stages and the failures every provider shares, see [Troubleshooting](../troubleshooting.mdx). The following are specific to Huawei Cloud Stack. Run the commands below on the bootstrap node; they read the bootstrap cluster, which exists until the installation completes.

| Symptom | Where to look first |
|---|---|
| Preflight cannot reach the IAM endpoint | `externalGlobalDomain` and `schema`, and whether the bootstrap node resolves and reaches `iam-apigateway-proxy.<externalGlobalDomain>`. |
| Stage 4 does not advance | `<extract-dir>/res/<arch>/ac --kubeconfig /var/cpaas/data/alauda.kubeconfig -n cpaas-system describe hcsmachine <name>`: the access key, the image, flavor, VPC, subnet, and security group names, the free addresses, and quota. |
| Stage 5 does not advance | `<extract-dir>/res/<arch>/ac --kubeconfig /var/cpaas/data/alauda.kubeconfig -n cpaas-system get hcscluster global -o yaml`: whether the ELB was created and `controlPlaneEndpoint` is set. |
| An instance is created but never joins | Whether the node reaches the control plane endpoint on `6443` and the registry, through the subnet and the security group. |

For provider failures that also apply after installation, see [Troubleshooting Huawei Cloud Stack Workload Clusters](../../../workload_clusters/alauda_os/huawei-cloud-stack/troubleshooting.mdx).
