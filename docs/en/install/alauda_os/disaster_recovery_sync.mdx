# Start Global Cluster Disaster Recovery Synchronization

Use this page after both `global` clusters are installed as described in [Global Cluster Disaster Recovery](./global_dr.mdx). You install **<Term name="product" /> Global Cluster Disaster Recovery** (`etcd-sync`) on the standby, which then copies the primary's etcd data to it, and you verify the synchronization.

Before you start:

- The platform domain points at the primary VIP.
- Both sides were installed with the same `cluster.encryptionProviderConfig`; see [Generate the Shared Keys](./global_dr.mdx#generate-the-shared-keys). If they were not, contact technical support before you continue.
- **Applies to** workload clusters on infrastructure other than the `global` cluster's own: install that provider on **both** `global` clusters, so that the standby can reconcile the same workload clusters after a failover. See [Prepare](../../workload_clusters/alauda_os/prepare/index.mdx). Upload to the standby with the standby's `--platform-address` and `--dest-repo`, as in [step 1](#install-etcd-sync). Skip it otherwise: `ac` has installed the provider of its own platform on each side.

## Conventions \{#conventions}

Run the commands on a machine with `ac` that reaches both sides:

- **Primary**: log in once with `ac login https://<platform-domain>` as the platform administrator while the domain points at the primary. Commands for the primary start with `ac config use-cluster global`.
- **Standby**: use the standby's kubeconfig, `output/kubeconfig` in its installation directory, here `<standby-kubeconfig>`. Commands for the standby start with `export KUBECONFIG=<standby-kubeconfig>` and end with `unset KUBECONFIG`.
- To show which cluster a command talks to, run `ac whoami --show-server`.
- In the plugin's parameter names, **Active** means the primary.

Steps marked **Bare Metal only** are not numbered. Your provider does these steps:

| Step | Huawei DCS, VMware vSphere, Huawei Cloud Stack | Bare Metal |
|---|---|---|
| Set `sharedAuthReadOnly` on the standby | | Yes |
| Apply the rule ConfigMap | | Yes |
| 1. Install `etcd-sync` | Yes | Yes |
| Check the rule source | | Yes |
| 2. Start and verify synchronization | Yes | Yes |
| Check the shared agent identity | | Yes |
| 3. Restart the dependent Pods | Yes | Yes |

## Bare Metal Only: Set sharedAuthReadOnly on the Standby \{#set-shared-auth-read-only}

On the standby, set the provider's `sharedAuthReadOnly` to `true`. Change no other `elemental` value:

```bash
export KUBECONFIG=<standby-kubeconfig>
ac get moduleinfo -l cpaas.io/cluster-name=global,cpaas.io/module-name=cluster-api-provider-baremetal
ac patch moduleinfo <name> --type=json -p '[{"op":"replace","path":"/spec/valuesOverride/acp~1chart-cluster-api-provider-baremetal/elemental/systemAgent/sharedAuthReadOnly","value":true}]'
ac -n cpaas-system get deploy elemental-operator -o yaml | grep -- --system-agent-shared-auth-read-only
unset KUBECONFIG
```

Continue when the last command prints `--system-agent-shared-auth-read-only`; otherwise, wait and run it again.

## Bare Metal Only: Apply the Rule ConfigMap \{#apply-the-rule-configmap}

Apply the same `baremetal-dr-rules` ConfigMap to the primary and the standby, **before** you install `etcd-sync`. `etcd-sync` runs on the standby and reads the primary. The built-in rules of the version given in [step 1](#install-etcd-sync) keep `SeedImage` and the `global` `MachineRegistration` resources local to each side, and synchronize the workload `MachineRegistration` resources, so a workload ISO stays valid across a failover when its registration URL uses the platform domain. `baremetal-dr-rules` adds only the runtime `global` plan Secret keys; do not duplicate the built-in entries.

The ConfigMap lists every `global` plan Secret of both clusters; collect the names after both sides have completed `create`. On each side, list them with:

```bash
# Primary: ac config use-cluster global
# Standby: export KUBECONFIG=<standby-kubeconfig>, and unset KUBECONFIG afterwards
ac -n cpaas-system get machineinventories.elemental.cattle.io -o json | jq -r '.items[]
  | select(.metadata.annotations["baremetal.cluster.io/system-agent-auth-scope"]=="global")
  | .status.plan.secretRef.name // empty | "/registry/secrets/cpaas-system/" + .'
```

Save the ConfigMap as `baremetal-dr-rules.yaml`. The list command needs `jq`.

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: baremetal-dr-rules
  namespace: cpaas-system
  labels:
    etcd-sync.cpaas.io/enabled: "true"
  annotations:
    etcd-sync.cpaas.io/weight: "100"
data:
  ignore-equal.txt: |
    # One line for every global plan Secret on both sides, as printed above.
    /registry/secrets/cpaas-system/<primary-global-plan-secret>
    /registry/secrets/cpaas-system/<standby-global-plan-secret>
```

Apply it on each side:

```bash
# Primary
ac config use-cluster global
ac apply -f baremetal-dr-rules.yaml

# Standby
export KUBECONFIG=<standby-kubeconfig>
ac apply -f baremetal-dr-rules.yaml
unset KUBECONFIG
```

<Directive type="warning" title="Create the rule source before the mirror can start">
  The mirror starts copying the primary's data 3 minutes after the `etcd-sync` Pods start, by default. Without the rule source, the first synchronization overwrites the standby's `global` plan Secrets with the primary's, and the standby `global` hosts receive plans that belong to the primary. The plugin parameters are required, so apply the ConfigMap on both sides first.
</Directive>

## 1. Install etcd-sync \{#install-etcd-sync}

Install **<Term name="product" /> Global Cluster Disaster Recovery** (`etcd-sync`) on the standby `global` cluster only, after both sides have completed `create`. It must never be installed on both sides. Use the version released with <Term name="productShort" /> 4.5.

Reach the standby through its VIP.

1. Get the plugin package from **ACP Common Aligned Extensions** and upload it to the standby with **Violet v4.2.13 or later**. Create the token on the standby Web Console (`https://<standby-vip>`): **Profile** → **API Tokens**. Set both `--platform-address` and `--dest-repo` to the standby: otherwise the package goes to the primary. `--dest-repo` is the platform image registry of the standby, the same address as the primary's when both sides share a registry. Use `--no-auth` instead of the registry credentials when the standby registry needs none. For the flags, see [Upload Packages](../../extend/upload_package.mdx#violet_push_usage).

   ```bash
   read -rsp "Standby platform token: " STANDBY_TOKEN; printf '\n'
   read -rsp "Standby registry password: " STANDBY_REGISTRY_PASSWORD; printf '\n'
   violet push <etcd-sync-package>.tgz \
     --platform-address "https://<standby-vip>" --platform-token "${STANDBY_TOKEN}" \
     --dest-repo "<standby-registry-address>" --username "<registry-username>" --password "${STANDBY_REGISTRY_PASSWORD}"
   unset STANDBY_TOKEN STANDBY_REGISTRY_PASSWORD
   ```

2. Create the token Secret on the standby. The value is the bearer token of the primary's `cpaas-system/k8sadmin` ServiceAccount; the commands do not print it:

   ```bash
   ac config use-cluster global
   ac whoami --show-server   # the primary
   PRIMARY_TOKEN=$(ac -n cpaas-system get secret k8sadmin -o jsonpath='{.data.token}' | base64 -d)
   export KUBECONFIG=<standby-kubeconfig>
   ac whoami --show-server   # the standby VIP
   printf '%s' "${PRIMARY_TOKEN}" | ac -n cpaas-system create secret generic etcd-sync-active-cluster-token \
     --from-file=token=/dev/stdin --dry-run=client -o yaml | ac apply -f -
   unset PRIMARY_TOKEN
   unset KUBECONFIG
   ```

3. Open the standby Web Console at `https://<standby-vip>`, go to **Marketplace** → **Cluster Plugins**, select the `global` cluster, and install **<Term name="product" /> Global Cluster Disaster Recovery** with these parameters.

   | Parameter | Value |
   |-----------|-------|
   | Active Global Cluster VIP | Control plane VIP of the primary `global` cluster |
   | Active Global Cluster ETCD Endpoints | Optional. `https://<primary-control-plane-vip>:2379`; separate several addresses with commas |
   | Standby Cluster ETCD Endpoints | Default value |
   | Active Global Cluster Token Secret | `etcd-sync-active-cluster-token` |
   | Data Check Interval (unit: hour) | Default value |
   | Print detail logs | Disabled unless troubleshooting |

## Bare Metal Only: Check the Rule Source \{#check-the-rule-source}

Right after the installation, before the mirror starts copying, on the standby:

```bash
export KUBECONFIG=<standby-kubeconfig>
ac -n cpaas-system get configmap baremetal-dr-rules \
  -o jsonpath='{.metadata.annotations.etcd-sync\.cpaas\.io/status}{"\n"}'
ac -n cpaas-system get configmap etcd-sync-rule-snapshot \
  -o jsonpath='{.data.snapshot\.json}'
unset KUBECONFIG
```

Continue when the first command prints `accepted` and the snapshot contains `baremetal-dr-rules`; otherwise, fix the ConfigMap as described in [Troubleshooting](#troubleshooting) before you continue.

## 2. Start and Verify Synchronization \{#start-and-verify-synchronization}

First check that the plugin is running on the standby:

```bash
export KUBECONFIG=<standby-kubeconfig>
ac get moduleinfo -l cpaas.io/module-name=etcd-sync
ac -n cpaas-system get pod -l 'app in (etcd-sync,etcd-sync-monitor)'
unset KUBECONFIG
```

Continue when the `ModuleInfo` shows `STATUS` `Running` and every Pod is `Running`; otherwise, wait and run the commands again. If they do not change, run the steps in [Global Cluster Disaster Recovery Does Not Synchronize](../../upgrade/troubleshooting.mdx#dr-sync-diagnostics).

The mirror copies the primary's data after its start delay. Wait until the initial synchronization has finished:

```bash
export KUBECONFIG=<standby-kubeconfig>
leader_pod=$(ac -n cpaas-system get lease etcd-sync-mirror -o jsonpath='{.spec.holderIdentity}')
ac -n cpaas-system logs "$leader_pod" | grep "Start Sync update"
unset KUBECONFIG
```

Continue when the output contains `Start Sync update`; otherwise, wait and run it again.

Then check the synchronization. Read the monitor's address on your machine:

```bash
export KUBECONFIG=<standby-kubeconfig>
ac -n cpaas-system get svc etcd-sync-monitor -o jsonpath='{.spec.clusterIP}{"\n"}'
unset KUBECONFIG
```

Run the check on a standby control plane node; put an IPv6 address in brackets, for example `[fd00::10]`:

```bash
curl -g "http://<monitor-cluster-ip>/check"
```

| Result | Action |
|---|---|
| Zero missed and zero surplus keys (`localMissedKeys [0]` and `localSurplusKeys [0]`) | Continue. |
| HTTP `425` (`check too frequent`) | Wait, then run the check again. |
| Missed keys are listed (`localMissedKeys`) | Wait until the log of the current leader shows `Start Sync update`, then run the check again. If missed keys remain, restart the leader Pod with the commands below, wait for `Start Sync update` again, and run the check again. |
| Surplus keys are listed (`localSurplusKeys`) | Contact technical support. |
| `paused: true` | Synchronization is paused for an upgrade. Contact technical support. |
| The command fails or prints anything else | Run the steps in [Global Cluster Disaster Recovery Does Not Synchronize](../../upgrade/troubleshooting.mdx#dr-sync-diagnostics), then run the check again. |

```bash
export KUBECONFIG=<standby-kubeconfig>
leader_pod=$(ac -n cpaas-system get lease etcd-sync-mirror -o jsonpath='{.spec.holderIdentity}')
ac -n cpaas-system delete pod "$leader_pod"
unset KUBECONFIG
```

## Bare Metal Only: Check the Shared Agent Identity \{#check-the-shared-agent-identity}

Check the shared workload agent identity on each side:

```bash
# Primary: ac config use-cluster global
# Standby: export KUBECONFIG=<standby-kubeconfig>, and unset KUBECONFIG afterwards
ac -n cpaas-system get sa/baremetal-system-agent secret/baremetal-system-agent-token \
  role/baremetal-system-agent rolebinding/baremetal-system-agent
```

Continue when all four objects exist on both sides, or none exists on either side; otherwise, contact technical support.

## 3. Restart the Dependent Pods \{#restart-the-dependent-pods}

On each side, restart the Pods that must reload the DR and endpoint configuration, where installed:

```bash
# Primary: ac config use-cluster global
# Standby: export KUBECONFIG=<standby-kubeconfig>, and unset KUBECONFIG afterwards
ac delete po -n cpaas-system -l 'service_name in (alertmanager,vmselect,vminsert)'
ac delete po -n cpaas-system -l service_name=cpaas-elasticsearch
ac delete po -n cpaas-system -l service_name=cluster-transformer
```

## Keep It Healthy \{#keep-it-healthy}

- Run the check in [step 2](#start-and-verify-synchronization) regularly. The plugin also checks by itself, by default every hour, and reports the results as the metrics `local_missed_keys_count` and `local_surplus_keys_count`.
- After each change to your workload clusters, save the output of `ac get clusters.cluster.x-k8s.io -A` and `ac get machines.cluster.x-k8s.io -A` from the primary. After a failover you compare against it; see [Fail Over](./disaster_recovery_failover.mdx#check-the-new-primary).
- **Bare Metal only:** update `baremetal-dr-rules` on both sides whenever a `global` host is added or replaced; see [Apply the Rule ConfigMap](#apply-the-rule-configmap).
- A DR-aware upgrade of the `global` clusters uninstalls the plugin and has its own consistency check; see [Upgrade `global` Clusters in a DR Environment](../../upgrade/global/upgrade_global_dr.mdx).

To switch to the standby, see [Fail Over to the Standby global Cluster](./disaster_recovery_failover.mdx).

## Troubleshooting \{#troubleshooting}

| Symptom | First check |
| --- | --- |
| The monitor reports differences | [Global Cluster Disaster Recovery Does Not Synchronize](../../upgrade/troubleshooting.mdx#dr-sync-diagnostics). |
| Bare Metal: the rule source is `rejected` | The rule data keys, the syntax, and the `message` annotation. |
| Bare Metal: a `global` plan is overwritten | Its exact Secret key is missing from `ignore-equal.txt`. Stop sync and update both rule ConfigMaps. |
| Bare Metal: a `global` inventory is deleted | The `etcd-sync` version; see [step 1](#install-etcd-sync). Stop sync before restoring the local object. |
