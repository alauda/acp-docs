# Bare Metal DR Model

How a Bare Metal disaster recovery pair keeps hosts, identities, and plans apart. For the procedure, see [Disaster Recovery](../../disaster_recovery.mdx).

## Endpoint and Identity \{#endpoint-and-identity}

| Host | Endpoint | Identity | Sync |
| --- | --- | --- | --- |
| Local `Cluster/global` host | `https://<local-control-plane-vip>:6443` | `baremetal-global-system-agent` | Local only |
| Non-`global` workload host | `https://<platform-domain>/kubernetes/global` | `baremetal-system-agent` | Primary to standby |

The workload row is the standard registration path; see [Network Connectivity](../../../../workload_clusters/alauda_os/bare-metal/prerequisites.mdx#network-connectivity).

After handoff, every `global` registration uses the local API server. A registration that you create later on a `global` cluster, for example to replace a `global` host, needs these annotations:

~~~yaml
metadata:
  annotations:
    baremetal.cluster.io/system-agent-auth-scope: global
    baremetal.cluster.io/system-agent-server-url: https://<local-control-plane-vip>:6443
    baremetal.cluster.io/system-agent-endpoint-mode: direct-apiserver
~~~

Do not reuse a bootstrap Global ISO after handoff; create a new Global registration and `SeedImage` on the `global` cluster that the host belongs to.

## Synchronization Rules \{#synchronization-rules}

`etcd-sync` runs on the standby and reads the primary. Its built-in rules, in the version given in [Install etcd-sync](../../disaster_recovery.mdx#install-etcd-sync), cover the CAPI, Bare Metal, and Elemental resources, the `global` inventories and registrations, the `global` agent identity, `SeedImage`, the registry credentials, and the monitor. `baremetal-dr-rules` adds only the runtime `global` plan Secret keys, which cannot be known when the chart is rendered; do not duplicate the built-in entries. The rule source must exist on both sides, so that it is available after a role switch.

The built-in rules keep `SeedImage` and the `global` `MachineRegistration` resources local to each side, and synchronize the workload `MachineRegistration` resources, so a workload ISO stays valid across a failover when its registration URL uses the platform domain.
