# Objects Rendered from install-config.yaml on Bare Metal

This page lists the objects that `ac` renders from the `global` cluster's `install-config.yaml` on Bare Metal. The Bare Metal fields are described below the template in [Write `install-config.yaml`](../create_cluster.mdx#install-config). The fields that all providers share are described in [Common `install-config.yaml` Fields](../../reference.mdx#install-config).

## Rendered Manifests \{#rendered-manifests}

`ac adm alpha global manifests` writes the following objects to `manifests/`. All of them are in the `cpaas-system` namespace. For a field-level reference, see [Bare Metal Provider](../../../../workload_clusters/alauda_os/bare-metal/overview.mdx).

| Object | Name | Notes |
|---|---|---|
| `Secret` | `global-sa` | Rendered only when `serviceAccountSigningKey` is set. `ac` refuses to overwrite an existing `global-sa` that holds a different key. |
| `Secret` | `global-encryption-provider-config` | The encryption configuration, referenced by `BaremetalCluster`. |
| `Cluster` | `global` | Labeled `cluster-type: ProviderBaremetal`. |
| `BaremetalCluster` | `global` | The control plane load balancer and the encryption Secret reference. |
| `KubeadmControlPlane`, `BaremetalMachineTemplate` | `global-control-plane` | The template references `controlPlane.baremetal.machineInventoryPool`. |
| `MachineDeployment`, `BaremetalMachineTemplate` | `global-<group>` | One set per `computes` entry. |
| `KubeadmConfigTemplate` | `global-<group>-config` | One per `computes` entry. |

`create` also creates objects in the bootstrap cluster that are not part of `manifests/`:

{/* lint ignore no-legacy-os-names */}

| Object | Name | Purpose |
|---|---|---|
| `MachineRegistration` | `global-registration` | The registration that the hosts enroll through. The hosts register as `MachineInventory` objects named `global-<system-uuid>`. With Alauda OS M55, the hosts are installed with Btrfs snapshots and keep four of them. With Alauda OS KU, the hosts carry the labels `os.baremetal.alauda.io/id: alaudaos.k.25` and `os.baremetal.alauda.io/arch`, which is set to the architecture that each host reports. Alauda OS KU hosts also install the root filesystem image from `rootImageTag`. |
| `SeedImage` | `global-registration-iso` | Builds the installation ISO for `architecture` from `tkestack/baremetal-base-image-iso:<isoImageTag>`, or from `tkestack/kubeos-iso:<isoImageTag>` with Alauda OS KU. With Alauda OS M55, its `COS_STATE` partition is sized to 20 GiB. |
| `elemental-image-catalog` entry | Kubernetes version | Maps the Kubernetes version to the root filesystem image in the registry of `global.registry`: `tkestack/baremetal-base-image:<rootImageTag>` or `tkestack/kubeos-rootfs:<rootImageTag>`. For Alauda OS M55, the key is the version, such as `v1.36.4-acp.3`. For Alauda OS KU, the key is `<version>_<architecture>_alaudaos.k.25`. `ac` writes the same key on the `global` cluster in stage 8. The entry serves hosts of the `osType` and `architecture` in `install-config.yaml`. With Alauda OS M55, it also serves hosts that registered without architecture and OS labels. For other hosts, add their keys after the installation. See [Add the Image Catalog Keys](../../../../workload_clusters/alauda_os/bare-metal/prepare_os.mdx#add-versions-to-image-catalog). |
| `Secret` | `dex.tls` | The certificate for the registration endpoint, issued for `global.bootstrapIP`. |
