# Objects Rendered from install-config.yaml on Bare Metal

This page lists the objects that `ac` renders from the `global` cluster's `install-config.yaml` on Bare Metal. The Bare Metal fields are described with the template in [Write `install-config.yaml`](../create_cluster.mdx#install-config); the fields that every provider shares are in [Common `install-config.yaml` Fields](../../reference.mdx#install-config).

## Rendered Manifests \{#rendered-manifests}

`ac adm alpha global manifests` writes the following objects to `manifests/`, all in `cpaas-system`. Field-level reference: [Bare Metal Provider](../../../../workload_clusters/alauda_os/bare-metal/overview.mdx).

| Object | Name | Notes |
|---|---|---|
| `Secret` | `global-sa` | Only when `serviceAccountSigningKey` is set. `ac` refuses to overwrite an existing `global-sa` that holds a different key. |
| `Secret` | `global-encryption-provider-config` | The encryption configuration, referenced by `BaremetalCluster`. |
| `Cluster` | `global` | Labelled `cluster-type: ProviderBaremetal`. |
| `BaremetalCluster` | `global` | The control plane load balancer and the encryption Secret reference. |
| `KubeadmControlPlane`, `BaremetalMachineTemplate` | `global-control-plane` | The template references `controlPlane.baremetal.machineInventoryPool`. |
| `MachineDeployment`, `BaremetalMachineTemplate` | `global-<group>` | One set per `computes` entry. |
| `KubeadmConfigTemplate` | `global-<group>-config` | One per `computes` entry. |

`create` also creates objects in the bootstrap cluster that are not part of `manifests/`:

{/* lint ignore no-legacy-os-names */}

| Object | Name | Purpose |
|---|---|---|
| `MachineRegistration` | `global-registration` | The registration the hosts enrol through. Hosts register as `MachineInventory` objects named `global-<system-uuid>`. With Alauda OS M55, hosts install with Btrfs snapshots and keep four of them. With Alauda OS KU, hosts carry the labels `os.baremetal.alauda.io/id: alaudaos.k.25` and `os.baremetal.alauda.io/arch`, the architecture each host reports, and install the root filesystem image from `rootImageTag`. |
| `SeedImage` | `global-registration-iso` | Builds the installation ISO for `architecture` from `tkestack/baremetal-base-image-iso:<isoImageTag>`, or `tkestack/kubeos-iso:<isoImageTag>` with Alauda OS KU. With Alauda OS M55, its `COS_STATE` partition is sized to 20 GiB. |
| `elemental-image-catalog` entry | Kubernetes version | Maps the Kubernetes version to the root filesystem image, `tkestack/baremetal-base-image:<rootImageTag>` or `tkestack/kubeos-rootfs:<rootImageTag>`. The key is the version, such as `v1.36.4-acp.3`, for Alauda OS M55, and `<version>_<architecture>_alaudaos.k.25` for Alauda OS KU. `ac` writes the same entry on the `global` cluster in stage 8. It serves hosts of the `osType` and `architecture` in `install-config.yaml`; with Alauda OS M55, it also serves hosts registered without architecture and OS labels. For other hosts, add their keys after the installation; see [Add Kubernetes Versions to the Image Catalog](../../../../workload_clusters/alauda_os/bare-metal/prerequisites.mdx#add-versions-to-image-catalog). |
| `Secret` | `dex.tls` | The certificate for the registration endpoint, issued for `global.bootstrapIP`. |
