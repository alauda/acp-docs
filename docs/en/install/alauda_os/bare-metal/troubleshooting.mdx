# Troubleshooting the global Cluster on Bare Metal

For the installation stages and the failures every provider shares, see [Troubleshooting](../troubleshooting.mdx). The following are specific to Bare Metal. Run the commands below on the bootstrap node; they read the bootstrap cluster, which exists until the installation completes.

| Symptom | Where to look first |
|---|---|
| The first run does not print the ISO URL | The `SeedImageReady` condition of `seedimage/global-registration-iso`, and whether the registry serves `tkestack/baremetal-base-image-iso:<isoImageTag>`. |
| The ISO build fails with `SeedImageBuildFailure` | Read the cause with `<extract-dir>/res/<arch>/ac --kubeconfig /var/cpaas/data/alauda.kubeconfig -n cpaas-system logs global-registration-iso -c baseiso`, fix it, and run `create` again. |
| A host does not appear as a `MachineInventory` | The host has no network address in the live ISO, or cannot reach `https://<bootstrapIP>:12443`. Check from the host console. |
| The registration check fails on a pool | Whether the pool named in `install-config.yaml` exists in `cpaas-system` with `spec.clusterName: global`, and lists at least as many hosts as the replicas of the node groups that draw from it. |
| The registration check fails with `pool members invalid` | The `MembersValid` message names the host that does not exist or belongs to another pool. |
| Stage 4 does not advance | Whether the `BaremetalMachine` reports `ImageCatalogMiss`, and whether the pool still has an available `MachineInventory`. |
| A `BaremetalMachine` stays `Failed` with `ImageCatalogMiss` | The entry is missing from the image catalog. The machine does not recover after the entry is added: delete the `Machine` with `<extract-dir>/res/<arch>/ac --kubeconfig /var/cpaas/data/alauda.kubeconfig -n cpaas-system delete machine <name>` so that its owner creates it again. |
| Stage 7 waits for the agent handover | Whether the `cpaas-system/baremetal-system-agent-handoff` ConfigMap on the `global` cluster reports `ready: "true"`, and the provider logs. |
| Stage 8 waits for the image catalog | Whether `elemental-image-catalog` on the `global` cluster holds the entry for its Kubernetes version. |

For provider conditions that also apply after installation, see [Troubleshooting Bare Metal Workload Clusters](../../../workload_clusters/alauda_os/bare-metal/troubleshooting.mdx).
