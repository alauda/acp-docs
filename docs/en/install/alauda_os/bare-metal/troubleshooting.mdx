# Troubleshooting the global Cluster on Bare Metal

For the installation stages and the failures every provider shares, see [Troubleshooting](../troubleshooting.mdx). The following are specific to Bare Metal. Run `kubectl` against `minialauda` with `--kubeconfig /var/cpaas/data/alauda.kubeconfig` until stage 8.

| Symptom | Where to look first |
|---|---|
| The first run does not print the ISO URL | The `SeedImageReady` condition of `seedimage/global-registration-iso`, and whether the registry serves `tkestack/baremetal-base-image-iso:<isoImageTag>`. |
| The ISO build fails with `SeedImageBuildFailure` | The controller does not retry a failed build, so `ac` deletes the `SeedImage` and builds it once more before it reports the error. Read the cause with `ac --kubeconfig /var/cpaas/data/alauda.kubeconfig -n cpaas-system logs global-registration-iso -c baseiso`, fix it, and run `create` again. |
| A host does not appear as a `MachineInventory` | The host has no network address in the live ISO, or cannot reach `https://<bootstrapIP>:12443`. Check from the host console. |
| The registration check fails with `pool members invalid` | The `MembersValid` message names the host that does not exist or belongs to another pool. |
| Stage 4 does not advance | Whether the `BaremetalMachine` reports `ImageCatalogMiss`, and whether the pool still has an available `MachineInventory`. |
| A `BaremetalMachine` stays `Failed` with `ImageCatalogMiss` | The entry is missing from the image catalog. The machine does not recover after the entry is added: delete the `Machine` so that its owner creates it again. |
| Stage 7 waits for the agent handover | The `baremetal-system-agent-handoff` Job on the `global` cluster, and the provider logs. |

For provider conditions that also apply after installation, see [Troubleshooting Bare Metal Workload Clusters](../../../workload_clusters/alauda_os/bare-metal/troubleshooting.mdx).
