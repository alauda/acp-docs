# Create the global Cluster on Bare Metal

On Bare Metal, you run `create` twice. The first run builds the installation ISO and stops. You then register the hosts with the ISO and assign them to pools. The second run installs the cluster.

## Prerequisites \{#prerequisites}

- You completed the [common prerequisites](../prerequisites.mdx) and the [Bare Metal prerequisites](./prerequisites.mdx).
- The Core Package is extracted on the bootstrap node, and its payload is in the external registry. See [Prepare the Core Package and the Registry](../prerequisites.mdx#prepare-core-package).
- For a disaster recovery pair, write both files as described in [Create a Global Cluster Disaster Recovery Pair](../global_dr.mdx#configure-install-config), then run this procedure on each side.

## Procedure

### 1. Write `install-config.yaml` \{#install-config}

Create an installation directory on the bootstrap node and write `install-config.yaml` in it. Keep the file private (`chmod 600 install-config.yaml`).

Copy the following template and fill in the placeholders. The numbered lines are specific to Bare Metal and are described in the table below the template. For the other fields, see [Common `install-config.yaml` Fields](../reference.mdx#install-config). For the objects that `ac` renders from this file, see [Rendered Manifests](./reference/install-config-parameters.mdx).

```yaml title="install-config.yaml"
global:
  bootstrapIP: <bootstrap-node-ip> # [!code callout]
  registry:
    address: <host>:<port>
    username: <user>
    password: <password>
  platform:
    address: <platform-domain-or-ip>
    username: admin@cpaas.io
    password: <password>
    extraAddresses: []
    cert:
      certificateFile: <console-cert-file>
      privateKeyFile: <console-key-file>
      # pkcs12CertificateFile: <console-pkcs12-file>
      # pkcs12Password: <password>

cluster:
  sshKeys:
    - <ssh-public-key>
  encryptionProviderConfig: <encryption-key>
  ntpServers: []
  network:
    podCIDR: 10.199.0.0/16
    serviceCIDR: 10.96.0.0/12
    kubeOVN:
      joinCIDR: 100.64.0.0/16
    loadBalancer: # [!code callout]
      type: internal
      address: <control-plane-endpoint>
      port: 6443
      vrid: <vrid>

provider:
  baremetal:
    # [!code callout]
    # osType: alaudaos-k
    # [!code callout]
    # architecture: arm64
    isoImageTag: <iso-image-tag> # [!code callout]
    rootImageTag: <root-image-tag> # [!code callout]
    serviceAccountSigningKey: <base64-pem-key> # [!code callout]

controlPlane:
  replicas: 3
  deployMode: normal
  baremetal:
    machineInventoryPool: global-control-plane-pool # [!code callout]

computes:
  - name: worker
    replicas: 3
    deployMode: normal
    baremetal:
      machineInventoryPool: global-worker-pool # [!code callout]
```

On Bare Metal, a node group takes only `replicas`, `deployMode`, and `baremetal.machineInventoryPool`, because the hosts supply the size, network, and disks of every node. Do not set `cpuCore`, `memoryGiB`, `network`, `disks`, `hosts`, or `credentialRef`. Any of them causes an error.

For the values of each side of a disaster recovery pair, see [Create a Global Cluster Disaster Recovery Pair](../global_dr.mdx#configure-install-config).

### 2. Build the Installation ISO \{#build-iso}

On the bootstrap node:

```bash
<extract-dir>/res/<arch>/ac adm alpha global create --dir <install-dir> --provider baremetal
```

The first run prepares the bootstrap cluster, builds the installation ISO, and prints its download and checksum URLs:

```text
The installation ISO is built. Boot every host of the global cluster from it:
  download: https://<bootstrapIP>:12443/...
  checksum: https://<bootstrapIP>:12443/...
```

The run then stops with a failed registration check because no host has registered yet. This is expected. No part of the `global` cluster has been applied yet.

Download the ISO. Verify it against the checksum URL, either on the bootstrap node or on the machine that downloaded it. The checksum file holds the SHA-256 hash and the original file name of the ISO. The original name contains colons, which Windows does not allow in file names. The saved file therefore often has a different name, and `sha256sum -c` cannot find it. Compare the hashes instead:

```bash
curl -sSk <checksum-url> | awk '{print $1}'    # expected hash
sha256sum <saved-iso-file> | awk '{print $1}'  # actual hash
```

Continue when the two hashes are the same. Otherwise, download the ISO again. On Windows, `certutil -hashfile <saved-iso-file> SHA256` prints the actual hash.

### 3. Register the Hosts \{#register-hosts}

1. Boot every host from the ISO. Each host registers as a `MachineInventory` named `global-<system-uuid>` and reports its disks. It then waits in the live environment until you select its system disk. You can boot all hosts at once. If a host gets no DHCP address in the live environment, configure its network as prepared in [Prerequisites](./prerequisites.mdx#network). The download URL expires 120 minutes after the ISO is built. If it has expired, see [The ISO Download URL Has Expired](./troubleshooting.mdx#iso-url-expired). Use this ISO only for this installation. Do not reuse it after the handover.
2. On the bootstrap node, list the registered hosts and the disks that each waiting host reports. Every host waits for you to select a disk, even a host with a single disk:

   ```bash
   <extract-dir>/res/<arch>/ac --kubeconfig /var/cpaas/data/alauda.kubeconfig \
     -n cpaas-system get machineinventories.elemental.cattle.io \
     -o custom-columns='NAME:.metadata.name,PHASE:.status.install.phase,IP:.metadata.labels.elemental\.cattle\.io/registration-ip'
   <extract-dir>/res/<arch>/ac --kubeconfig /var/cpaas/data/alauda.kubeconfig \
     -n cpaas-system get machineinventories.elemental.cattle.io <inventory-name> \
     -o jsonpath='{range .status.install.candidates[*]}{.id}{"\t"}{.eligible}{"\t"}{.path}{"\t"}{.sizeBytes}{"\t"}{.reasons}{"\n"}{end}'
   ```

   A waiting host shows `AwaitingTarget`. `IP` is the address that the host uses to reach the bootstrap node, so that you can match an inventory to a host. Each candidate line prints the disk ID, whether the disk can be selected, its device path in the live environment, its size in bytes, and the reasons why it cannot be selected, if any. Identify the system disk by its size and path.
3. While each host is still in the live environment, select its system disk by the disk ID:

   ```bash
   <extract-dir>/res/<arch>/ac --kubeconfig /var/cpaas/data/alauda.kubeconfig \
     -n cpaas-system annotate machineinventories.elemental.cattle.io <inventory-name> \
     baremetal.alauda.io/install-target-device=<disk-id>
   ```

   - Select a disk that shows `true`, using its ID exactly as printed.
   - The phase changes to `Installing`, and the host installs Alauda OS to that disk and reboots. The selection cannot be changed after that.
   - If the annotation is rejected because the host was not seen recently, make sure that the host is still running the ISO, and run the command again.
4. List the registered hosts again on the bootstrap node:

   ```bash
   <extract-dir>/res/<arch>/ac --kubeconfig /var/cpaas/data/alauda.kubeconfig \
     -n cpaas-system get machineinventories.elemental.cattle.io \
     -o custom-columns='NAME:.metadata.name,READY:.status.conditions[?(@.type=="Ready")].status,PHASE:.status.install.phase,PLAN:.status.plan.secretRef.name'
   ```

   You can use a host when `READY` is `True`, `PHASE` is `Installed`, and `PLAN` is not `<none>`. Otherwise, see [Troubleshooting on Bare Metal](./troubleshooting.mdx).

### 4. Create the Pools \{#create-pools}

Create one `MachineInventoryPool` for each node group. Each pool must:

- Have the name that `install-config.yaml` gives it.
- Set `spec.clusterName: global`.
- List at least as many hosts as the replicas of the node groups that take hosts from it.

A host can belong to only one pool.

```yaml title="pools.yaml"
apiVersion: infrastructure.cluster.x-k8s.io/v1beta1
kind: MachineInventoryPool
metadata:
  name: global-control-plane-pool
  namespace: cpaas-system
spec:
  clusterName: global
  machineInventories:
    - name: <inventory-1>
      hostname: <hostname-1> # [!code callout]
    - name: <inventory-2>
    - name: <inventory-3>
---
apiVersion: infrastructure.cluster.x-k8s.io/v1beta1
kind: MachineInventoryPool
metadata:
  name: global-worker-pool
  namespace: cpaas-system
spec:
  clusterName: global
  machineInventories:
    - name: <inventory-4>
    - name: <inventory-5>
    - name: <inventory-6>
```

<Callouts>

1. `hostname`: optional. Defaults to the inventory name.

</Callouts>

On the bootstrap node:

```bash
<extract-dir>/res/<arch>/ac --kubeconfig /var/cpaas/data/alauda.kubeconfig apply -f pools.yaml
```

### 5. Install the Cluster \{#create}

On the bootstrap node, run `create` again, reusing the manifests that the first run rendered:

```bash
<extract-dir>/res/<arch>/ac adm alpha global create --dir <install-dir> --provider baremetal --reuse-manifests
```

`ac` first checks the pools named in `install-config.yaml` (their members and size) and the ISO URL. If a check fails, no part of the `global` cluster is applied, and the error names the item that failed. Make sure that an `external` load balancer is ready before you run `create`.

`create` returns when the installation is complete. If `create` stops, run the same command again. It skips the work that is already complete. See [The `create` Command](../reference.mdx#create-command).

### 6. Monitor the Installation \{#monitor}

From another terminal on the bootstrap node:

```bash
<extract-dir>/res/<arch>/ac adm alpha global status
```

For the stages and common failures, see [Troubleshooting](../troubleshooting.mdx). For Bare Metal failures, see [Troubleshooting on Bare Metal](./troubleshooting.mdx).

## Verification

When `create` returns, the installation is complete, but some platform components can take a few more minutes to become ready. Before you judge the result, wait for them as described in [Additional Checks for Alauda OS](../../validation.mdx#alauda-os-checks). Then verify the platform as described in [Validation](../../validation.mdx), including its [checks for Alauda OS](../../validation.mdx#alauda-os-checks).

**Applies to**: a Self-built VIP (`cluster.network.loadBalancer.type: internal`). Skip this check with an `external` load balancer.

Log in to a control plane node of the `global` cluster as the `boot` user (`ssh boot@<control-plane-node-ip>`). Use the private key that matches an SSH public key in `cluster.sshKeys`. Run `curl` with `sudo`, because only `root` can read the cluster CA file:

```bash
sudo curl --cacert /etc/kubernetes/pki/ca.crt https://<control-plane-vip>:6443/healthz
```

Continue when it prints `ok`. Otherwise, see [Troubleshooting on Bare Metal](./troubleshooting.mdx).

For hosts of that OS and architecture, create only the registration and its ISO. For hosts of another architecture or OS, also push the images and add the keys.
