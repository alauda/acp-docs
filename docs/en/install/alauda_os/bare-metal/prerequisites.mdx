# Prerequisites for Bare Metal

Complete the [common prerequisites](../prerequisites.mdx) first. On Bare Metal, `ac` does not create machines: hosts boot an installation ISO that `ac` builds, register themselves, and are assigned to the `global` cluster through pools. Prepare the following.

## OS Images in the Registry \{#os-images}

Push both Bare Metal Alauda OS images to the external registry, under `tkestack/` in `global.registry.address`. They come from one OS archive and are not interchangeable:

| Image | Used for |
|---|---|
| `tkestack/baremetal-base-image-iso` | The live ISO that hosts boot to register. |
| `tkestack/baremetal-base-image` | The root filesystem that hosts are installed, upgraded, and reprovisioned with. |

```bash
ctr -n bare-metal-os images import --all-platforms --no-unpack <archive>
ctr -n bare-metal-os images ls -q      # lists the two image names
ctr -n bare-metal-os images push <registry>/tkestack/<image>:<tag> <image>:<tag>
```

See [Image Format by Provider](../../../overview/alauda_os_support_matrix.mdx#image-format-by-provider) for the archive.

## Hosts \{#hosts}

One host for each control plane replica, plus one for each worker replica. Before a host boots the ISO:

- Wipe the system disk, including leftover `COS_*` partition labels from an earlier installation.
- Put the ISO first in the boot order. On virtual machines where ejecting the CD does not take effect, boot from disk first and CD second.
- Set the clock from firmware. The hosts must stay within 10 seconds of each other; see [Host Time Synchronization](../../../workload_clusters/alauda_os/bare-metal/prerequisites.mdx#host-time-synchronization).
- Decide whether the hosts use a hardware TPM; see `provider.baremetal.emulateTPM` in [Parameters](./reference/install-config-parameters.mdx).

## Network \{#network}

- **An address during the live ISO boot**, from DHCP or configured on the host console as described in [Network Connectivity](../../../workload_clusters/alauda_os/bare-metal/prerequisites.mdx#network-connectivity).
- **The hosts reach the bootstrap node on `TCP/12443`**, which serves both host registration and the ISO download. `global.bootstrapIP` is the bootstrap node address that the hosts route to.
- **A control plane endpoint.** With `internal`, the default, the provider runs the VIP on the control plane nodes: reserve an unused IPv4 address in the control plane Layer 2 domain and a `vrid` that no other VRRP instance in it uses. With `external`, your load balancer forwards `TCP/6443` to the control plane nodes. See [Plan the Control Plane Endpoint](../../../workload_clusters/alauda_os/prepare/control-plane-endpoint.mdx).
