# Prerequisites for Bare Metal

Complete the [common prerequisites](../prerequisites.mdx) first, then prepare the following for Bare Metal. `ac` creates no machines.

## Host OS and Architecture \{#host-os}

Every host of the `global` cluster runs the same host OS on the same host architecture. Choose them before you push the OS images:

- **Alauda OS M55**, on `amd64` only.
- **Alauda OS KU**, on `amd64` or `arm64`.

When the host architecture differs from the architecture of the bootstrap node, use the hybrid Core Package; see [Download](../../prepare/download.mdx).

## OS Images in the Registry \{#os-images}

Download the OS archive of the host OS and architecture that you chose above, as described in [Downloading Alauda OS](../../../overview/alauda_os_support_matrix.mdx#downloading-alauda-os); the archive is described in [Image Format by Provider](../../../overview/alauda_os_support_matrix.mdx#image-format-by-provider). Push its two OS images, the live ISO and the root filesystem, to the external registry of `global.registry` under its `tkestack/` project, with the account of `global.registry`. The `tkestack` project must exist in the registry. Both images come from the one archive and are not interchangeable.

Run the commands that the form prints as root on the bootstrap node, which needs free space in `/var/tmp` of at least the archive size. `<host-arch>` is the architecture of the bootstrap node, `amd64` or `arm64`. Fill in the form with the ACP version, the host OS and architecture, the OS image tag (see [Look Up the Image Tags](#os-image-tags)), and the registry address. The form prints **Push the OS images** and **Values for `install-config.yaml`**.

<BareMetalImageCatalog mode="install" />

Do not push with `docker push` or another tool that rewrites the image manifest: the Alauda OS KU installer reads the manifest as it is in the archive.

Continue when each `tags/list` response contains the tag; otherwise check the registry address, the credentials, the `tkestack` project, and the push output. Keep **Values for `install-config.yaml`**; you paste them into `install-config.yaml` in [Create the global Cluster on Bare Metal](./create_cluster.mdx#install-config).

### Look Up the Image Tags \{#os-image-tags}

The tag of both images, `isoImageTag` and `rootImageTag`, is the archive file name without `.tar`, such as `alaudaos-44.m55.202610030151-0.x86_64`. To look up the tags in the registry later, run the following on a host that reaches the registry, such as the bootstrap node. When the registry needs no credentials, omit the `read` line and the `-u` option.

{/* lint ignore no-legacy-os-names */}

```bash
# Alauda OS M55
ISO_REPO=baremetal-base-image-iso; ROOT_REPO=baremetal-base-image
# Alauda OS KU
# ISO_REPO=kubeos-iso; ROOT_REPO=kubeos-rootfs

read -rsp 'Registry password: ' REGISTRY_PASSWORD; echo
for repo in "${ISO_REPO}" "${ROOT_REPO}"; do
  curl -sSk -u "<registry-username>:${REGISTRY_PASSWORD}" \
    "https://<registry-address>/v2/tkestack/${repo}/tags/list"; echo
done
unset REGISTRY_PASSWORD
```

The output lists the tags of each repository, here for Alauda OS M55:

```text
{"name":"tkestack/baremetal-base-image-iso","tags":["<os-image-tag>"]}
{"name":"tkestack/baremetal-base-image","tags":["<os-image-tag>"]}
```

{/* lint ignore no-legacy-os-names */}

The tag of `tkestack/baremetal-base-image-iso` (`tkestack/kubeos-iso`) is the ISO image tag, and the tag of `tkestack/baremetal-base-image` (`tkestack/kubeos-rootfs`) is the root filesystem image tag. When a repository lists more than one tag, for example because images of another release or architecture were pushed earlier, use the tag of the archive that you downloaded for this ACP release and the host architecture.

## Hosts \{#hosts}

One host for each control plane replica, plus one for each worker replica. Prepare them before they boot the ISO as described in [Prepare the Hosts](../../../workload_clusters/alauda_os/bare-metal/register_hosts.mdx#prepare-hosts): wipe the disks, set the boot order and the clock, make the live ISO network ready, and provide SMBIOS on `arm64` hosts.

## Network \{#network}

- **An address during the live ISO boot**, from DHCP or configured on the host console as described in [Network in the Live ISO](../../../workload_clusters/alauda_os/bare-metal/register_hosts.mdx#live-iso-network).
- **A route from the hosts to the bootstrap node address**, the IPv4 address of the bootstrap node that the hosts reach. The hosts download the ISO and register through it on port `12443`. For the flows from the hosts to the bootstrap node, see [Installation](../../prepare/communication_matrix.mdx#installation).
- **A control plane endpoint**, as planned in [Plan the Control Plane Endpoint](../prerequisites.mdx#control-plane-endpoint): a Self-built VIP with its VRID, or an external load balancer that forwards the ports marked **Yes** in **Forward on load balancer** in [Platform Access Address and `global` VIP](../../prepare/communication_matrix.mdx#global_vip).

## Next Steps

You now have, in addition to the common values, the host OS and architecture, the values for `install-config.yaml` that the form printed (the ISO image tag and the root filesystem image tag), and the bootstrap node address. Continue with [Create the global Cluster on Bare Metal](./create_cluster.mdx).
