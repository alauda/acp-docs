# Install on Alauda OS

The `global` cluster is the platform's control plane: it runs the platform services and manages every workload cluster. This section installs the `global` cluster when its nodes run Alauda OS. To install it on a non-Alauda OS such as Ubuntu or RHEL, see [Install on Non-Alauda OS](../non_alauda_os/index.mdx).

## How the Installation Works

You describe the cluster in one `install-config.yaml` and run `ac adm alpha global create` on a temporary bootstrap node:

1. `ac` checks `install-config.yaml`, the registry, and the infrastructure.
2. It starts a temporary bootstrap cluster on the bootstrap node and installs the Cluster Bootstrap Provider and the infrastructure provider into it. All images come from the external registry.
3. The providers create the `global` machines, and the control plane is initialized.
4. The platform is installed on the `global` cluster.
5. The `global` cluster takes over: from then on it manages its own machines.
6. `ac` installs the two providers on the `global` cluster, writes the cluster's kubeconfig, and removes the bootstrap cluster.

After the installation, the `global` cluster runs the Cluster Bootstrap Provider and the infrastructure provider of its own platform, and the bootstrap node is no longer needed. On Huawei DCS, VMware vSphere, and Huawei Cloud Stack, `ac` keeps the infrastructure credential in the `global-credential` Secret on the `global` cluster: the provider uses it after the installation, and `destroy` uses it to delete the machines. Keep the installation directory, `<install-dir>`: `install-config.yaml`, the rendered manifests, `output/kubeconfig`, and the logs exist nowhere else. Copy it to a safe place before you reclaim the bootstrap node. See [Installation Directory](./reference.mdx#install-directory).

## Disaster Recovery

A disaster recovery pair is two `global` installations, a primary and a standby, each from its own bootstrap node with its own `install-config.yaml`. **<Term name="product" /> Global Cluster Disaster Recovery** on the standby copies the primary's data to it. The two sides share the platform domain, the console certificate, and the encryption key; each keeps its own control plane VIP, registry, and infrastructure credentials. Failover is a manual switch of the platform domain. See [Disaster Recovery](./disaster_recovery.mdx).

## Deployment Path

1. **Prepare.** Meet the [common prerequisites](./prerequisites.mdx), then the prerequisites of your provider.
2. **Install the `global` cluster** on your provider.
3. **Optional: add disaster recovery.** Follow [Disaster Recovery](./disaster_recovery.mdx) before you write either `install-config.yaml`; it covers every provider in one page.
4. **Create workload clusters.** See [Create on Alauda OS](../../workload_clusters/alauda_os/index.mdx).
