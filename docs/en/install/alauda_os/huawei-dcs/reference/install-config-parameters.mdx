# install-config.yaml Parameters for Huawei DCS

This page lists the DCS fields of the `global` cluster's `install-config.yaml` and the objects that `ac` renders from them. The fields that every provider shares are in [Installation Reference](../../reference.mdx#install-config). The DCS fields are the same for workload clusters, which describe [addresses, placement, disks, and optional NICs](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx) in more detail.

## Optional Fields \{#optional-fields}

The template in [Create the global Cluster](../create_cluster.mdx#install-config) omits the optional fields. Add them where you need them:

```yaml
cluster:
  network:
    loadBalancer:
      interface: <nic-name> # [!code callout]
provider:
  dcs:
    credential:
      userType: interconnect # [!code callout]
    cdRomDatastoreName: <datastore> # [!code callout]
    rootDisk:
      sizeGiB: <root-disk-gib> # [!code callout]
    resource: # [!code callout]
      type: cluster
      name: <cluster-or-host-name>
    disks:
      isThin: false # [!code callout]
      pciType: VIRTIO # [!code callout]
controlPlane: # [!code callout]
  deployMode: normal # [!code callout]
  dcs: # [!code callout]
    machineFolder: <folder-name>
    cdRomDatastoreName: <datastore>
    rootDisk:
      sizeGiB: <root-disk-gib>
    resource:
      type: cluster
      name: <cluster-or-host-name>
  network:
    additions: # [!code callout]
      - mask: <prefix-length> # [!code callout]
        dcs: # [!code callout]
          dvSwitchName: <dv-switch-name>
          portGroupName: <port-group-name>
  disks:
    rawDisks: # [!code callout]
      - name: data-001
        sizeGiB: 50
    dcs: # [!code callout]
      datastore:
        type: Datastore
        name: <datastore>
      isThin: true
      pciType: VIRTIO
  hosts:
    - hostname: <cp-0-hostname>
      ip: <cp-0-ip>
      additionalIps: [<cp-0-nic2-ip>] # [!code callout]
```

<Callouts>

1. `interface`: optional, for `internal` only. Empty uses the NIC that carries the node IP.
2. `userType`: `interconnect`, the default, or `domain`.
3. `cdRomDatastoreName`: optional. Empty lets the provider choose.
4. `rootDisk.sizeGiB`: optional. Empty keeps the template's system disk size.
5. `resource`: optional. `type` is `cluster` or `host`; empty lets DCS place the VMs.
6. `isThin`: `false`, the default, for thick provisioning; applies to persistent and raw disks only.
7. `pciType`: `VIRTIO`, the default, `SCSI`, or `IDE`.
8. The same fields apply to each `computes` entry.
9. `deployMode`: `normal`, the default, or `base`.
10. `dcs`: overrides `provider.dcs` for this group only.
11. `additions`: additional NICs, matched in order to `hosts[].additionalIps[]`.
12. `mask`: optional. Empty takes `network.mask`.
13. `dcs`: optional. Empty takes `provider.dcs.network`.
14. `rawDisks`: raw block volumes for TopoLVM.
15. `disks.dcs`: overrides `provider.dcs.disks` for this group only.
16. `additionalIps`: one per `network.additions` entry, in order.

</Callouts>

## DCS Fields \{#fields}

The `provider.dcs` and node group fields, their defaults, and the disk, NIC, and placement rules are the same as for workload clusters; see [Fields](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#fields). The `global` cluster differs in the following:

| Field | Required | Default | Description |
|---|---|---|---|
| `provider.dcs.credential` | Yes | — | The DCS API credential, written inline because there is no cluster yet to hold a Secret. `ac` renders it into the `global-credential` Secret. `credentialRef` is rejected. |
| `provider.dcs.credential.endpoint` | Yes | — | The FusionCompute address with `https://` and the port, without a trailing slash. |
| `provider.dcs.credential.authUser`, `authKey` | Yes | — | The user and the password in plain text, not the SHA-256 digest that the DCS console shows. |
| `provider.dcs.credential.site` | Yes | — | The bare site ID. The `urn:sites:` form is rejected. |
| `provider.dcs.credential.userType` | No | `interconnect` | `interconnect` or `domain`; see [DCS Credential Secret](../../../../workload_clusters/alauda_os/huawei-dcs/prerequisites.mdx#credential-secret) for the DCS-side requirements. |

`cluster.ntpServers` and `deployMode` apply to the `global` cluster only, and `cluster.clusterName` is not set; see [Installation Reference](../../reference.mdx#install-config).

## Rendered Manifests \{#rendered-manifests}

`ac adm alpha global manifests` writes the following objects to `manifests/`, all in `cpaas-system`. For their API fields, see the [Huawei DCS API reference](../../../../apis/kubernetes_apis/infrastructure_providers/huawei-dcs/index.mdx).

| Object | Name | Notes |
|---|---|---|
| `Secret` | `global-credential` | The DCS API credential from `provider.dcs.credential`. |
| `Secret` | `global-encryption-provider-config` | The encryption configuration, referenced by `DCSCluster`. |
| `Cluster` | `global` | Labelled `cluster-type: DCS`. |
| `DCSCluster` | `global` | The site, the control plane load balancer, `controlPlaneHA`, and the credential and encryption Secret references. |
| `KubeadmControlPlane`, `DCSMachineTemplate`, `DCSIpHostnamePool` | `global-control-plane` | The pool holds each node's address, hostname, and persistent and raw disks. |
| `MachineDeployment`, `DCSMachineTemplate`, `DCSIpHostnamePool` | `global-<group>` | One set per `computes` entry. |
| `KubeadmConfigTemplate` | `global-<group>-config` | One per `computes` entry. |
| `ConfigMap` | `dcs-import-extra-resources` | The import list, described below. |

The persistent and raw disks are declared in the `DCSIpHostnamePool`, so they are kept when a VM is replaced. The ephemeral disks are declared in the `DCSMachineTemplate` and are recreated with the VM.

In stage 6, `cpaas-installer` moves the DCS and Cluster API objects to the `global` cluster by its built-in migration. The import list adds the two Secrets that the migration does not carry, `global-credential` and `global-encryption-provider-config`. Without them, every later control plane machine fails to be created once the bootstrap cluster is gone.
