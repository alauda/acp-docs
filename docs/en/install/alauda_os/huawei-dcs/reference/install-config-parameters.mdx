# install-config.yaml Parameters for Huawei DCS

This page lists the DCS fields of `install-config.yaml`, which are the same for the `global` cluster and for workload clusters, and the objects that `ac` renders for the `global` cluster. The fields that every provider shares are in [Installation Reference](../../reference.mdx#install-config). The [workload cluster page](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx) describes the topology in more detail: addresses, placement, disks, optional NICs, and the control plane endpoint.

## Optional Fields \{#optional-fields}

The template in [Create the global Cluster](../create_cluster.mdx#install-config) keeps every optional field as a default value or a comment block: the Self-built VIP, the console certificate, additional NICs, raw disks, placement, and per-group overrides. [DCS Fields](#fields) gives the rules of the fields. The topics that need more than a table row are described on the workload cluster page:

- The control plane endpoint and the Self-built VIP: [Control Plane Endpoint and HA](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#configure-dcscluster) and [Self-built VIP](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#self-built-vip).
- Node addresses and placement: [Node Addresses and Placement](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#node-addresses).
- Disks, additional NICs, and raw disks: [Disks](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#disks), [Additional NICs](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#additional-nics), and [Raw Disks for TopoLVM](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#raw-disks).
- `deployMode`: [Platform Node Groups](../../reference.mdx#deploy-mode).

## DCS Fields \{#fields}

The fields are the same for the `global` cluster and for a workload cluster, except `provider.dcs.credential`: it is for the `global` cluster only, and a workload cluster sets `credentialRef` instead; see [Fields](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#fields).

| Field | Required | Default | Description |
|---|---|---|---|
| `provider.dcs.credential` | Yes | — | The DCS API credential, written inline. `ac` renders it into the `global-credential` Secret. `credentialRef` is rejected. |
| `provider.dcs.credential.endpoint` | Yes | — | The FusionCompute address with `https://` and the port, without a trailing slash. |
| `provider.dcs.credential.authUser`, `authKey` | Yes | — | The user and the password in plain text, not the SHA-256 digest that the DCS console shows. |
| `provider.dcs.credential.site` | Yes | — | The bare site ID. The `urn:sites:` form is rejected. |
| `provider.dcs.credential.userType` | No | `interconnect` | `interconnect` or `domain`; see [DCS Credential Secret](../../../../workload_clusters/alauda_os/huawei-dcs/prerequisites.mdx#credential-secret) for the DCS-side requirements. |
| `provider.dcs.vmTemplateName` | Yes | — | The VM template every node is cloned from. It must carry the Kubernetes version that `ac` installs. For a workload cluster, `ac` takes the version from the ConfigMap registered for the template; see [VM Template and Kubernetes Version](../../../../workload_clusters/alauda_os/huawei-dcs/prerequisites.mdx#resolving-placeholders). |
| `provider.dcs.controlPlaneHA` | Yes | — | `true` keeps the control plane VMs on different DCS hosts with a DRS rule. |
| `provider.dcs.machineFolder` | Yes | — | An existing VM folder. |
| `provider.dcs.cdRomDatastoreName` | No | Chosen by the provider | The datastore for the CD-ROM that carries each node's Ignition ISO. |
| `provider.dcs.rootDisk.sizeGiB` | No | The template's size | The system disk size. DCS rejects a size smaller than the template's. |
| `provider.dcs.resource` | No | Chosen by DCS | `type: cluster` places the VMs in a compute cluster, `type: host` on one physical host. See [Node Addresses and Placement](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#node-addresses). |
| `provider.dcs.network` | Yes | — | `dvSwitchName` and `portGroupName` of the primary NIC of every node. |
| `provider.dcs.disks` | Yes | — | `datastore` (`type: Datastore` or `DatastoreCluster`, and `name`), `isThin` (default `false`), and `pciType` (`VIRTIO`, the default, `SCSI`, or `IDE`). See [Disks](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#disks). |
| `cluster.network.loadBalancer` | Yes | — | The control plane endpoint: `type` (`external`, the default, or `internal`), `address`, `port` (`6443`), and for `internal` a `vrid` (1-255) and an optional `interface`. See [Control Plane Endpoint and HA](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#configure-dcscluster). |
| `controlPlane.replicas` | Yes | — | An odd number: `1`, or `3` or more. See [Control Plane Endpoint and HA](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#configure-dcscluster). |
| `*.cpuCore`, `*.memoryGiB` | No | `8` and `16` | The VM size of a node group. |
| `*.dcs`, `*.disks.dcs`, `*.network.additions[].dcs` | No | The `provider.dcs` values | Overrides for one node group or one NIC. `*.dcs` takes `machineFolder`, `cdRomDatastoreName`, `rootDisk`, and `resource`; `*.disks.dcs` takes `datastore`, `isThin`, and `pciType`. Fields not set keep the cluster-level value. |
| `*.network` | Yes | — | The primary NIC network of a node group; see [Node Addresses and Placement](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#node-addresses). |
| `*.disks` | Yes | — | The standard disk set and any raw disks; see [Disks](../../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#disks). |
| `*.hosts` | Yes | — | One entry per node: `hostname`, `ip`, and `additionalIps`. |
| `computes[].name` | Yes | — | Unique per group. `control-plane` is reserved. |

`cluster.ntpServers` and `deployMode` apply to the `global` cluster only. `cluster.clusterName` and `cluster.registrySecretRef` are rejected: `ac` names the cluster, and `global.registry` sets the registry. See [Installation Reference](../../reference.mdx#install-config).

### Alauda OS K Templates \{#alauda-os-k}

`provider.dcs.osType` is optional and left out by default. Set it to `alaudaos-k` when `vmTemplateName` is an Alauda OS K template: without it, Ignition fails on Alauda OS K and the VM has no network. Any other value is rejected.

## Rendered Manifests \{#rendered-manifests}

`ac adm alpha global manifests` writes the following objects to `manifests/`, all in `cpaas-system`. For their API fields, see the [Huawei DCS API reference](../../../../apis/kubernetes_apis/infrastructure_providers/huawei-dcs/index.mdx).

| Object | Name | Notes |
|---|---|---|
| `Secret` | `global-credential` | The DCS API credential from `provider.dcs.credential`. |
| `Secret` | `global-encryption-provider-config` | The encryption configuration, referenced by `DCSCluster`. |
| `Cluster` | `global` | Labelled `cluster-type: DCS`. |
| `DCSCluster` | `global` | The site, the control plane load balancer, `controlPlaneHA`, and the credential and encryption Secret references. |
| `KubeadmControlPlane`, `DCSMachineTemplate`, `DCSIpHostnamePool` | `global-control-plane` | The pool holds each node's address, hostname, and persistent and raw disks. |
| `MachineDeployment`, `DCSMachineTemplate`, `DCSIpHostnamePool` | `global-<group>` | One set per `computes` entry. |
| `KubeadmConfigTemplate` | `global-<group>-config` | One per `computes` entry. |

The persistent and raw disks are declared in the `DCSIpHostnamePool`, so they are kept when a VM is replaced. The ephemeral disks are declared in the `DCSMachineTemplate` and are recreated with the VM.

Do not delete the `global-credential` or `global-encryption-provider-config` Secret on the `global` cluster: without them, new control plane machines cannot be created.
