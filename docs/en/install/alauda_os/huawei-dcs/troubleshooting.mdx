# Troubleshooting the global Cluster on Huawei DCS

For the installation stages and the failures every provider shares, see [Troubleshooting](../troubleshooting.mdx). The following are specific to Huawei DCS. Run the commands below on the bootstrap node; they read the bootstrap cluster, which exists until the installation completes.

| Symptom | Where to look first |
|---|---|
| Preflight reports a name that was not found | The name and its type in `install-config.yaml`, against the DCS site named in the message. |
| Preflight cannot sign in | `endpoint`, `authUser`, `authKey`, `site`, and `userType`. `authKey` is the plain-text password and `site` the bare site ID. Correct them before retrying: repeated failed sign-ins lock the DCS account. |
| Stage 4 does not advance | `<extract-dir>/res/<arch>/ac --kubeconfig /var/cpaas/data/alauda.kubeconfig -n cpaas-system describe dcsmachine <name>`: the template, the folder, the port group, the datastore capacity, and the address in the `DCSIpHostnamePool`. |
| A VM is created but never joins | Whether the node reaches the control plane endpoint on `6443` and the registry, with the gateway and DNS from `install-config.yaml`. |
| The control plane VMs land on one host with `controlPlaneHA: true` | The requirements in [Control Plane Spread](./prerequisites.mdx#control-plane-ha), and whether DRS migration is blocked. |

For provider failures that also apply after installation, see [Troubleshooting Huawei DCS Workload Clusters](../../../workload_clusters/alauda_os/huawei-dcs/troubleshooting.mdx).
