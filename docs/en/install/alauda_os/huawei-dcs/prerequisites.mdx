# Prerequisites for Huawei DCS

Complete the [common prerequisites](../prerequisites.mdx) first, then prepare the following on Huawei DCS. `ac` creates none of them.

- **A dedicated DCS API account** with the `administrator` role: the FusionCompute endpoint, user, password, and site ID. For an interface interconnection user, the default `userType`, set the DCS policy **Whether to modify the password of an interface interconnection user upon password resetting and first login** to **No**. Do not use the portal `admin` account: DCS locks an account after repeated failed sign-ins.
- **A VM template created from the Alauda OS image** published for the platform release, without changes; see [Downloading Alauda OS](../../../overview/alauda_os_support_matrix.mdx#downloading-alauda-os). Note whether the template runs Alauda OS KO or Alauda OS KU: the template OS is part of the cluster configuration. Register the VM template on the `global` cluster with a ConfigMap; see [VM Template ConfigMap](../../../workload_clusters/alauda_os/huawei-dcs/prerequisites.mdx#vm-template-configmap).
- **The VM folder** for the nodes.
- **A distributed virtual switch and a port group on it** for the node network, and one for each additional NIC.
- **The datastore or datastore cluster** for the disks, and the datastore for the CD-ROM if you name one.
- **The compute cluster or host**, if you pin the nodes to one. Make sure it has room for the planned VMs.
- **Static IPv4 addresses and hostnames** for every node, with the gateway, prefix length, and DNS server of each network.
- **A control plane endpoint**, as planned in [Plan the Control Plane Endpoint](../prerequisites.mdx#control-plane-endpoint): a Self-built VIP with its VRID, or an external load balancer that forwards the ports marked **Yes** in **Forward on load balancer** in [Platform Access Address and `global` VIP](../../prepare/communication_matrix.mdx#global_vip).
- **Network access** from the bootstrap node and the `global` nodes to the DCS VRM and the DCS hosts, as listed in [Huawei DCS](../../prepare/communication_matrix.mdx#provider-dcs).

## Control Plane Spread \{#control-plane-ha}

Control plane spread places the control plane VMs on different DCS hosts with a DRS rule. Decide whether to use it. It needs DRS enabled on the compute cluster, at least as many healthy hosts as control plane replicas, a datastore visible to all of them, and nothing that blocks DRS migration, such as an attached CD-ROM. Do not pin the control plane to one host.

## Next Steps

You now have, in addition to the common values, the DCS API account, the VM template and its OS, the VM folder, the switch and port groups, the datastores, the compute cluster or host if you pin the nodes, the node addresses and hostnames, and whether to use control plane spread.
