# Prerequisites for Huawei DCS

Complete the [common prerequisites](../prerequisites.mdx) first, then prepare the following on Huawei DCS. `ac` does not create any of them.

- **A dedicated DCS API account** with the `administrator` role. You need its FusionCompute endpoint, user, password, and site ID. If the account is an interface interconnection user, which is the default `userType`, set the DCS policy **Whether to modify the password of an interface interconnection user upon password resetting and first login** to **No**. Do not use the portal `admin` account, because DCS locks an account after repeated failed sign-ins.
- **A VM template created from the Alauda OS image** that is published for the platform release. Create the template from the image without changes. See [Downloading Alauda OS](../../../overview/alauda_os_support_matrix.mdx#downloading-alauda-os). Note whether the template runs Alauda OS KO or Alauda OS KU, because the template OS is part of the cluster configuration.
- **The VM folder** for the nodes.
- **A distributed virtual switch and a port group on it** for the node network, and one for each additional NIC.
- **The datastore or datastore cluster** for the disks, and, if you name one, the datastore for the CD-ROM.
- **The compute cluster or host**, if you pin the nodes to one. Make sure it has room for the planned VMs.
- **Static IPv4 addresses and hostnames** for every node, with the gateway, prefix length, and DNS server of each network.
- **A control plane endpoint**, as planned in [Plan the Control Plane Endpoint](../prerequisites.mdx#control-plane-endpoint). It is either a Self-built VIP with its VRID, or an external load balancer. The load balancer must forward every port marked **Yes** under **Forward on load balancer** in [Platform Access Address and `global` VIP](../../prepare/communication_matrix.mdx#global_vip).
- **Network access** from the bootstrap node and the `global` nodes to the DCS VRM and the DCS hosts, as listed in [Huawei DCS](../../prepare/communication_matrix.mdx#provider-dcs).

## Control Plane Spread \{#control-plane-ha}

Decide whether to use control plane spread. It uses a DRS rule to place the control plane VMs on different DCS hosts. It needs:

- DRS enabled on the compute cluster.
- At least as many healthy hosts as control plane replicas.
- A datastore that all of these hosts can see.
- Nothing that blocks DRS migration, such as an attached CD-ROM.
- A control plane that is not pinned to one host.
