# Prerequisites for Huawei DCS

Complete the [common prerequisites](../prerequisites.mdx) first, then prepare the following on Huawei DCS. `ac` creates none of them.

- **A dedicated DCS API account** with the `administrator` role: the FusionCompute endpoint, user, password, and site ID. For an interface interconnection user, the default `userType`, set the DCS policy **Whether to modify the password of an interface interconnection user upon password resetting and first login** to **No**. Do not use the portal `admin` account: DCS locks an account after repeated failed sign-ins.
- **A VM template created from the Alauda OS image** published for the platform release, without changes; see [Downloading Alauda OS](../../../overview/alauda_os_support_matrix.mdx#downloading-alauda-os). For an Alauda OS K template, see [Alauda OS K Templates](../../../workload_clusters/alauda_os/huawei-dcs/reference/install-config-parameters.mdx#alauda-os-k).
- **The VM folder** for the nodes.
- **A distributed virtual switch and a port group on it** for the node network, and one for each additional NIC.
- **The datastore or datastore cluster** for the disks, and the datastore for the CD-ROM if you name one.
- **The compute cluster or host**, if you pin the nodes with `resource`. `ac` checks only its name: make sure it has room for the planned VMs.
- **Static IPv4 addresses and hostnames** for every node, with the gateway, prefix length, and DNS server of each network.
- **A control plane endpoint.** With `external`, the default, your load balancer forwards `TCP/6443` to the control plane nodes. With `internal`, the provider runs a Self-built VIP on the control plane nodes: reserve an unused IPv4 address in the control plane Layer 2 domain and a `vrid` that no other VRRP instance in it uses. See [Plan the Control Plane Endpoint](../../../workload_clusters/alauda_os/prepare/control-plane-endpoint.mdx).
- **The bootstrap node and the `global` nodes reach the DCS VRM on `TCP/7443`** and the management address of the DCS hosts, typically `TCP/8443`.

## Control Plane Spread \{#control-plane-ha}

`controlPlaneHA: true` spreads the control plane VMs across DCS hosts with a DRS rule. It needs DRS enabled on the compute cluster, at least as many healthy hosts as control plane replicas, a datastore visible to all of them, and nothing that blocks DRS migration, such as an attached CD-ROM. Do not pin the control plane to one host with `resource`.
