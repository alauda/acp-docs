# Create the global Cluster on Huawei DCS

## Prerequisites

- You completed the [common prerequisites](../prerequisites.mdx) and the [Huawei DCS prerequisites](./prerequisites.mdx).
- The Core Package is extracted on the bootstrap node and its payload is in the external registry; see [Prepare the Core Package and the Registry](../prerequisites.mdx#prepare-core-package).
- For a disaster recovery pair, write both files as described in [Disaster Recovery](../disaster_recovery.mdx#configure-install-config), then run this procedure on each side.

## Procedure

### 1. Write `install-config.yaml` \{#install-config}

Create an installation directory on the bootstrap node and write `install-config.yaml` in it. The fields are described in [Parameters](./reference/install-config-parameters.mdx); additional NICs, raw disks, placement, and per-group overrides are optional and listed there.

```yaml title="install-config.yaml"
global:
  registry:
    address: <host>:<port> # [!code callout]
    username: <user> # [!code callout]
    password: <password>
  platform:
    address: <platform-domain-or-ip> # [!code callout]
    username: admin@cpaas.io # [!code callout]
    password: <password> # [!code callout]
    extraAddresses: [] # [!code callout]

cluster: # [!code callout]
  sshKeys: # [!code callout]
    - <ssh-public-key>
  ntpServers: [] # [!code callout]
  network:
    loadBalancer:
      type: external # [!code callout]
      address: <control-plane-endpoint> # [!code callout]
      port: 6443
      # vrid: <vrid> # [!code callout]

provider:
  dcs:
    credential: # [!code callout]
      endpoint: https://<fc-address>:7443 # [!code callout]
      authUser: <user> # [!code callout]
      authKey: <password> # [!code callout]
      site: <site-id> # [!code callout]
    vmTemplateName: <vm-template-name> # [!code callout]
    controlPlaneHA: true # [!code callout]
    machineFolder: <folder-name> # [!code callout]
    network: # [!code callout]
      dvSwitchName: <dv-switch-name> # [!code callout]
      portGroupName: <port-group-name> # [!code callout]
    disks:
      datastore:
        type: Datastore # [!code callout]
        name: <datastore-name> # [!code callout]

controlPlane:
  replicas: 3 # [!code callout]
  cpuCore: 8 # [!code callout]
  memoryGiB: 16 # [!code callout]
  network:
    gateway: <cp-gateway> # [!code callout]
    dns: [<dns-ip>] # [!code callout]
    mask: <prefix-length> # [!code callout]
  disks:
    ephemeral: # [!code callout]
      - name: var-lib-containerd
        sizeGiB: 100
      - name: var-lib-kubelet
        sizeGiB: 100
      - name: var-lib-etcd # [!code callout]
        sizeGiB: 20
    persistent: # [!code callout]
      - name: var-cpaas
        sizeGiB: 100
  hosts: # [!code callout]
    - hostname: <cp-0-hostname>
      ip: <cp-0-ip>
    - hostname: <cp-1-hostname>
      ip: <cp-1-ip>
    - hostname: <cp-2-hostname>
      ip: <cp-2-ip>

computes: # [!code callout]
  - name: worker
    replicas: 3
    network:
      gateway: <worker-gateway>
      dns: [<dns-ip>]
      mask: <prefix-length>
    disks:
      ephemeral: # [!code callout]
        - name: var-lib-containerd
          sizeGiB: 100
        - name: var-lib-kubelet
          sizeGiB: 100
      persistent:
        - name: var-cpaas
          sizeGiB: 100
    hosts:
      - hostname: <worker-0-hostname>
        ip: <worker-0-ip>
      - hostname: <worker-1-hostname>
        ip: <worker-1-ip>
      - hostname: <worker-2-hostname>
        ip: <worker-2-ip>
```

<Callouts>

1. `registry.address`: required. The external registry as `<host>:<port>`, without a scheme or `/v2/`.
2. `registry.username` and `registry.password`: optional. Set both or neither.
3. `platform.address`: required. The platform access address, without a scheme or port. Disaster recovery requires a domain name.
4. `platform.username`: defaults to `admin@cpaas.io`.
5. `platform.password`: required. 8 to 32 characters, mixing letters, digits, and symbols.
6. `extraAddresses`: optional. List the control plane VIP to open the console on it. Required for disaster recovery, where each side lists its own VIP.
7. Do not set `clusterName`: `ac` names the cluster `global`.
8. `sshKeys`: required. The SSH public keys installed on every node.
9. `ntpServers`: optional. Empty keeps the image's time configuration.
10. `type`: `external`, the default, or `internal`.
11. `address`: required. The control plane endpoint, an IPv4 address.
12. `vrid`: required for `internal`, from 1 to 255.
13. `credential`: required. The DCS API credential.
14. `endpoint`: required. `https://`, with the port and without a trailing slash.
15. `authUser`: required. The DCS user name.
16. `authKey`: required. The plain-text password.
17. `site`: required. The bare site ID, not `urn:sites:...`.
18. `vmTemplateName`: required. The VM template every node is cloned from.
19. `controlPlaneHA`: required, `true` or `false`. `true` keeps the control plane VMs on different DCS hosts.
20. `machineFolder`: required. An existing VM folder.
21. `network`: the primary NIC of every node.
22. `dvSwitchName`: required. The distributed virtual switch.
23. `portGroupName`: required. A port group of that switch.
24. `datastore.type`: required. `Datastore` or `DatastoreCluster`.
25. `datastore.name`: required. The datastore or datastore cluster name.
26. `replicas`: an odd number, `1` or `3` or more. A single control plane node cannot be upgraded.
27. `cpuCore`: defaults to `8`.
28. `memoryGiB`: defaults to `16`.
29. `gateway`: required.
30. `dns`: DCS uses only the first entry.
31. `mask`: required. A prefix length from 1 to 32.
32. `ephemeral`: disks recreated with the VM.
33. `var-lib-etcd`: control plane only.
34. `persistent`: disks kept when the VM is replaced.
35. `hosts`: required. At least `replicas` entries.
36. `computes`: optional. Without workers, the platform runs on the control plane nodes.
37. Workers have no `var-lib-etcd`.

</Callouts>

### 2. Create the Cluster \{#create}

```bash
<extract-dir>/res/<arch>/ac adm alpha global create --dir <install-dir> --provider dcs
```

Before it runs `setup.sh`, `ac` checks that the credential signs in and the site exists; that the VM template, the folders, the switches and port groups, any configured compute resource, and every datastore and datastore cluster exist; and, for an `internal` VIP, that the Core Package version supports it. An `external` load balancer is not probed.

`create` returns when the cluster is installed. If it stops, run it again; see [The `create` Command](../reference.mdx#create-command).

### 3. Monitor the Installation \{#monitor}

From another terminal on the bootstrap node:

```bash
ac adm alpha global status
```

A typical installation takes 30 to 60 minutes after the machines are available. For the stages and common failures, see [Troubleshooting](../troubleshooting.mdx); for DCS failures, see [Troubleshooting on Huawei DCS](./troubleshooting.mdx).

## Verification

When `create` returns, stage 8 `Finalized` has passed and `minialauda` is deleted. Access the cluster with `<install-dir>/output/kubeconfig`, then verify the platform as described in [Validation](../../validation.mdx), including its [checks for Alauda OS](../../validation.mdx#alauda-os-checks).
