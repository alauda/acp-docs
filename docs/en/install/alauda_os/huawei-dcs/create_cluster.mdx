# Create the global Cluster on Huawei DCS

## Prerequisites \{#prerequisites}

- You completed the [common prerequisites](../prerequisites.mdx) and the [Huawei DCS prerequisites](./prerequisites.mdx).
- The Core Package is extracted on the bootstrap node, and its payload is in the external registry. See [Prepare the Core Package and the Registry](../prerequisites.mdx#prepare-core-package).
- For a disaster recovery pair, write both files as described in [Create a Global Cluster Disaster Recovery Pair](../global_dr.mdx#configure-install-config), then run this procedure on each side.

## Procedure

### 1. Write `install-config.yaml` \{#install-config}

Create an installation directory on the bootstrap node, for example `/root/global-install`, and write `install-config.yaml` in it. The commands on this page call this directory `<install-dir>`; see [Installation Directory](../reference.mdx#install-directory). Keep the file private (`chmod 600 install-config.yaml`), because it holds the passwords.

Copy the following template and fill in the placeholders. The numbered lines are specific to Huawei DCS and are described in the table below the template. For the other fields, see [Common `install-config.yaml` Fields](../reference.mdx#install-config). For the objects that `ac` renders from this file, see [Rendered Manifests](./reference/install-config-parameters.mdx).

```yaml title="install-config.yaml"

  registry:
    address: <host>:<port>
    username: <user>
    password: <password>
  platform:
    address: <platform-domain-or-ip>
    username: admin@cpaas.io
    password: <password>
    extraAddresses: []
    cert:
      certificateFile: <console-cert-file>
      privateKeyFile: <console-key-file>
      # pkcs12CertificateFile: <console-pkcs12-file>
      # pkcs12Password: <password>

cluster:
  sshKeys:
    - <ssh-public-key>
  ntpServers: []
  network:
    podCIDR: 10.199.0.0/16
    serviceCIDR: 10.96.0.0/12
    kubeOVN:
      joinCIDR: 100.64.0.0/16
    loadBalancer: # [!code callout]
      type: external
      address: <control-plane-endpoint>
      port: 6443

      # interface: <nic-name>

    # [!code callout]
    # cdRomDatastoreName: <datastore>
    # [!code callout]
    # osType: alaudaos-k
    # [!code callout]

    #   sizeGiB: <root-disk-gib>
    network: # [!code callout]
      dvSwitchName: <dv-switch-name>
      portGroupName: <port-group-name>

      datastore: # [!code callout]
        type: <datastore-type>

    #     dcs:
    #       dvSwitchName: <dv-switch-name>

  disks:

      - name: var-lib-containerd

    persistent: # [!code callout]
      - name: var-cpaas
        sizeGiB: 100
    rawDisks: [] # [!code callout]

    #   - name: data-001

    # [!code callout]

    #     type: <datastore-type>
```

### 2. Create the Cluster \{#create}

On the bootstrap node:

```bash
<extract-dir>/res/<arch>/ac adm alpha global create --dir <install-dir> --provider dcs
```

`ac` first checks the DCS sign-in, the DCS objects named in `install-config.yaml`, and the registry. If a check fails, nothing is changed, and the error names the item that failed. Make sure that an `external` load balancer is ready before you run `create`.

:::warning
Before you run `create`, make sure that the password in `install-config.yaml` is correct. DCS locks the account after repeated failed sign-ins.
:::

`create` returns when the installation is complete. If `create` stops, run the same command again. It skips the work that is already complete. See [The `create` Command](../reference.mdx#create-command).

### 3. Monitor the Installation \{#monitor}

From another terminal on the bootstrap node:

```bash
<extract-dir>/res/<arch>/ac adm alpha global status
```

For the stages and common failures, see [Troubleshooting](../troubleshooting.mdx). For Huawei DCS failures, see [Troubleshooting on Huawei DCS](./troubleshooting.mdx).

## Verification

When `create` returns, the installation is complete, but some platform components can take a few more minutes to become ready. Before you judge the result, wait for them as described in [Additional Checks for Alauda OS](../../validation.mdx#alauda-os-checks). Then verify the platform as described in [Validation](../../validation.mdx), including its [checks for Alauda OS](../../validation.mdx#alauda-os-checks).

**Applies to**: a Self-built VIP (`cluster.network.loadBalancer.type: internal`). Skip this check with an `external` load balancer.

Log in to a control plane node of the `global` cluster as the `boot` user (`ssh boot@<control-plane-node-ip>`). Use the private key that matches an SSH public key in `cluster.sshKeys`. Run `curl` with `sudo`, because only `root` can read the cluster CA file:

```bash
sudo curl --cacert /etc/kubernetes/pki/ca.crt https://<control-plane-vip>:6443/healthz
```

Continue when it prints `ok`. Otherwise, see [Troubleshooting on Huawei DCS](./troubleshooting.mdx).
