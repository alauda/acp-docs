# Delete the global Cluster on VMware vSphere

`destroy` deletes the `global` cluster and the VMware vSphere resources that it created, with the credential stored in the `global-credential` Secret. It refuses while the platform still manages another cluster; for this and the other rules every provider shares, see [The `destroy` Command](../reference.mdx#destroy).

## Before You Begin

- Delete every workload cluster that the platform manages.
- Use a machine that reaches the `global` cluster and vCenter on `TCP/443`, such as the bootstrap node.

## Procedure \{#destroy}

On that machine:

```bash
<extract-dir>/res/<arch>/ac adm alpha global destroy --kubeconfig <install-dir>/output/kubeconfig
```

`destroy` lists each item, then asks you to type the cluster name. It deletes:

- Every VM of the cluster, after powering it off, with its system, ephemeral, and attached persistent disks.
- The persistent disks left behind by released slots.

Any other disk attached to these VMs, such as a CSI volume, is detached and kept.

It keeps the folders, resource pools, datastores, networks, VM templates, IP addresses, and the control plane VIP.

If `destroy` stops, run the same command again; see [The `destroy` Command](../reference.mdx#destroy).
