# Delete the global Cluster on VMware vSphere

`destroy` deletes the cluster through vCenter, with the credential stored in the `global-credential` Secret. It refuses when the platform still manages another cluster; for this and the other rules every provider shares, see [The `destroy` Command](../reference.mdx#destroy).

## Before You Begin

Delete every workload cluster that the platform manages.

## Procedure \{#destroy}

Run `destroy` on a machine whose kubeconfig reaches the `global` cluster, such as the bootstrap node with `<install-dir>/output/kubeconfig`:

```bash
ac adm alpha global destroy --kubeconfig <install-dir>/output/kubeconfig
```

`destroy` lists each item, then asks you to type the cluster name. It deletes:

- Every VM of the cluster, after powering it off, with its system, ephemeral, and attached persistent disks.
- The persistent disks left behind by released slots.

Any other disk attached to these VMs, such as a CSI volume, is detached and kept, because the cluster did not create it.

It keeps the folders, resource pools, datastores, networks, VM templates, IP addresses, and the control plane VIP.

If the run breaks, run the same command again; see [The `destroy` Command](../reference.mdx#destroy).
