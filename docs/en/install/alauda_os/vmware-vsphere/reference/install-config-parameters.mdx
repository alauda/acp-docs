# install-config.yaml Parameters for VMware vSphere

This page lists the vSphere fields of the `global` cluster's `install-config.yaml` and the objects that `ac` renders from them. The fields that every provider shares, such as `global.platform.cert`, `cluster.encryptionProviderConfig`, and the Pod, Service, and join CIDRs, are in [Installation Reference](../../reference.mdx#install-config).

## Optional Fields \{#optional-fields}

The template in [Create the global Cluster](../create_cluster.mdx#install-config) shows every optional field, with its default value or as a commented block. [vSphere Fields](#fields) gives their rules; `deployMode` is described in [Platform Node Groups](../../reference.mdx#deploy-mode).

## vSphere Fields \{#fields}

| Field | Required | Default | Description |
|---|---|---|---|
| `cluster.network.loadBalancer.type` | No | `external` | `external` for your load balancer, `internal` for a Self-built VIP. The mode cannot be changed after the cluster exists. |
| `cluster.network.loadBalancer.vrid` | For `internal` | — | 1-255, unique in the control plane Layer 2 domain. |
| `cluster.network.loadBalancer.interface` | No | The NIC that carries the node IP | Only for `internal`. `vipMode` is not supported. |
| `provider.vsphere.server` | Yes | — | The vCenter address. |
| `provider.vsphere.credential` | Yes | — | The vCenter account. `ac` renders it into the `global-credential` Secret. `credentialRef` is rejected. |
| `provider.vsphere.datacenter`, `template`, `datastore` | Yes | — | Names or inventory paths in vCenter. A nested `datacenter` path, such as `/folder/dc`, cannot be combined with `computeResource`. Make sure that a datastore, folder, or port group given as an inventory path exists. |
| `provider.vsphere.folder` | No | The datacenter's VM folder | The VM folder. A folder of its own makes the `global` VMs easy to find. |
| `provider.vsphere.computeResource` | When the datacenter has several | — | The name of the DRS cluster or standalone host, not an inventory path. Without it, VM creation fails when the datacenter has more than one compute resource. |
| `provider.vsphere.rootDisk.sizeGiB` | No | The template's size | The system disk size, not counting the data disks. It takes effect only on a full clone, which the provider makes when the template has no snapshot; a linked clone keeps the template's size. It must not be smaller than the template's system disk. |
| `provider.vsphere.releaseDelayHours` | No | `24` | How long a released slot of a machine config pool keeps its persistent disks before they are deleted. A replacement machine takes a released slot immediately. |
| `provider.vsphere.network.name` | Yes | — | The port group of the primary NIC. An additional NIC can override it. |
| `provider.vsphere.network.deviceName` | No | `eth0`, `eth1`, ... in device order | The NIC name in the guest. |
| `controlPlane.replicas` | Yes | — | An odd number: `1`, or `3` or more. The control plane runs stacked etcd. A single control plane node cannot be upgraded. |
| `*.cpuCore`, `*.memoryGiB` | No | The template's size | The VM size of a node group. |
| `*.vsphere`, `*.disks.vsphere`, `*.network.additions[].vsphere` | No | The `provider.vsphere` values | Overrides for one node group, its data disks, or one NIC. `disks.vsphere.datastore` defaults to the group's datastore; `storagePolicy` applies to its data disks. |
| `*.network.additions[].mask` | No | `network.mask` | The prefix length of an additional NIC, 1-32. |
| `*.network.additions[].vsphere.name` | No | `provider.vsphere.network.name` | The port group of an additional NIC. |
| `*.network.gateway`, `*.network.mask`, `*.network.dns` | Yes | — | The primary NIC network. `mask` is a prefix length, 1-32. |
| `*.disks` | Yes | — | The standard disks are all required: `var-lib-containerd`, `var-lib-kubelet`, and `var-cpaas` on every group, and `var-lib-etcd` on the control plane. They are formatted as xfs. Other names are rejected; add extra volumes as `rawDisks`, which are attached unformatted at `/dev/disk/by-capv/<name>`. |
| `*.hosts` | Yes | — | One entry per node: `hostname`, `ip`, and `additionalIps` in the order of `network.additions`. Each becomes one slot of the group's machine config pool. |
| `computes[].name` | Yes | — | Unique per group. `control-plane` is reserved. |

## Rendered Manifests \{#rendered-manifests}

`ac adm alpha global manifests` writes the following objects to `manifests/`, all in `cpaas-system`. Field-level reference: [VMware vSphere Provider](../../../../workload_clusters/alauda_os/vmware-vsphere/overview.mdx).

| Object | Name | Notes |
|---|---|---|
| `Secret` | `global-credential` | The vCenter account from `provider.vsphere.credential`, referenced by `VSphereCluster.spec.identityRef`. |
| `Cluster` | `global` | |
| `VSphereCluster` | `global` | The vCenter server and certificate fingerprint, the control plane endpoint, and, for `internal`, `controlPlaneLoadBalancer`. |
| `ConfigMap`, `Secret`, `ConfigMap`, `ClusterResourceSet` | `global-vsphere-cpi-config`, `global-vsphere-cpi-secret`, `global-vsphere-cpi-manifests`, `global-vsphere-cpi` | The CPI delivery set. The `ClusterResourceSet` applies the CPI to the cluster once its API server answers. |
| `KubeadmControlPlane`, `VSphereMachineTemplate`, `VSphereMachineConfigPool` | `global-control-plane` | The pool holds one slot per host: its hostname, addresses, and disks. The encryption configuration is a kubeadm file in the `KubeadmControlPlane`. |
| `MachineDeployment`, `VSphereMachineTemplate`, `VSphereMachineConfigPool` | `global-<group>` | One set per `computes` entry. |
| `KubeadmConfigTemplate` | `global-<group>-config` | One per `computes` entry. |

Every VM is a linked clone; without a snapshot on the template, the provider makes a full clone. Every controller replaces one node at a time (`maxSurge: 0`).

Do not delete the `global-credential` Secret on the `global` cluster: the provider deletes it with the cluster.
