# Objects Rendered from install-config.yaml on VMware vSphere

This page lists the objects that `ac` renders from the `global` cluster's `install-config.yaml` on VMware vSphere. The vSphere fields are described below the template in [Write `install-config.yaml`](../create_cluster.mdx#install-config). The fields that all providers share are described in [Common `install-config.yaml` Fields](../../reference.mdx#install-config).

## Rendered Manifests \{#rendered-manifests}

`ac adm alpha global manifests` writes the following objects to `manifests/`. All of them are in the `cpaas-system` namespace. For a field-level reference, see [VMware vSphere Provider](../../../../workload_clusters/alauda_os/vmware-vsphere/overview.mdx).

| Object | Name | Notes |
|---|---|---|
| `Secret` | `global-credential` | The vCenter account from `provider.vsphere.credential`, referenced by `VSphereCluster.spec.identityRef`. |
| `Cluster` | `global` | |
| `VSphereCluster` | `global` | The vCenter server and its certificate fingerprint, the control plane endpoint, and `controlPlaneLoadBalancer` (for `internal`). |
| `ConfigMap`, `Secret`, `ConfigMap`, `ClusterResourceSet` | `global-vsphere-cpi-config`, `global-vsphere-cpi-secret`, `global-vsphere-cpi-manifests`, `global-vsphere-cpi` | The objects that deliver the CPI. The `ClusterResourceSet` applies the CPI to the cluster once the API server of the cluster answers. |
| `KubeadmControlPlane`, `VSphereMachineTemplate`, `VSphereMachineConfigPool` | `global-control-plane` | The pool holds one slot for each host, with its hostname, addresses, and disks. The encryption configuration is a kubeadm file in the `KubeadmControlPlane`. |
| `MachineDeployment`, `VSphereMachineTemplate`, `VSphereMachineConfigPool` | `global-<group>` | One set per `computes` entry. |
| `KubeadmConfigTemplate` | `global-<group>-config` | One per `computes` entry. |

Every VM is a linked clone, unless the template has no snapshot. In that case, the provider makes a full clone. Every controller replaces one node at a time (`maxSurge: 0`).

Do not delete the `global-credential` Secret on the `global` cluster. The provider deletes it with the cluster.
