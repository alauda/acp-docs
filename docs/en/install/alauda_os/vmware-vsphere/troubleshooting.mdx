# Troubleshooting the global Cluster on VMware vSphere \{#troubleshooting}

For the installation stages and the failures every provider shares, see [Troubleshooting](../troubleshooting.mdx). The following are specific to VMware vSphere. Run the commands below on the bootstrap node; they read the bootstrap cluster, which exists until the installation completes.

| Symptom | Where to look first |
|---|---|
| Preflight reports a name that was not found | The name in `install-config.yaml`. Preflight stops at the first missing object, so run `create` again after each fix. With several compute resources in the datacenter, set `computeResource` to the name of one. |
| Preflight passes, but a VM is not created because a datastore, folder, or port group is not found | The inventory path in `install-config.yaml`: preflight does not check names that contain `/`. |
| Preflight cannot sign in | `server`, `username`, and `password`, and whether vCenter answers on `443` from the bootstrap node. |
| Stage 4 does not advance | `<extract-dir>/res/<arch>/ac --kubeconfig /var/cpaas/data/alauda.kubeconfig -n cpaas-system describe vspheremachine <name>` and `<extract-dir>/res/<arch>/ac --kubeconfig /var/cpaas/data/alauda.kubeconfig -n cpaas-system describe vspherevm <name>`: the template, the datastore, and whether the machine config pool still has a free slot. |
| A VM is created but never joins | Whether the node reaches the control plane endpoint on `6443` and the registry, with the gateway and DNS from `install-config.yaml`. |
| Nodes stay uninitialized after the platform installation | Until the `global` cluster takes over, the `ClusterResourceSetBinding` of `global-vsphere-cpi` in the bootstrap cluster. Afterwards, the CPI Pods and their configuration and Secret on the `global` cluster. |
| Stage 8 waits for the credential | Whether `cpaas-system/global-credential` exists on the `global` cluster and is not terminating. |

For provider failures that also apply after installation, see [Troubleshooting VMware vSphere Workload Clusters](../../../workload_clusters/alauda_os/vmware-vsphere/troubleshooting.mdx).
