# Troubleshooting the global Cluster on VMware vSphere \{#troubleshooting}

For the installation stages and the failures every provider shares, see [Troubleshooting](../troubleshooting.mdx). The following are specific to VMware vSphere.

| Symptom | Where to look first |
|---|---|
| Preflight reports a name that was not found | The name, or the inventory path, in `install-config.yaml`. With several compute resources in the datacenter, set `computeResource`. |
| Preflight cannot sign in | `server`, `username`, and `password`, and whether vCenter answers on `443` from the bootstrap node. |
| Stage 4 does not advance | In `minialauda`, the conditions of the `VSphereMachine` and `VSphereVM`, the template and the datastore, and whether the machine config pool still has a free slot. |
| A VM is created but never joins | Whether the node reaches the control plane endpoint on `6443` and the registry, with the gateway and DNS from `install-config.yaml`. |
| Nodes stay uninitialized after the platform installation | During installation, the `ClusterResourceSetBinding` of `global-vsphere-cpi` on `minialauda`. After the migration to the `global` cluster, the CPI Pods and their configuration and Secret on `global`; the binding does not exist there. |
| Stage 8 waits for the credential | Whether `global-credential` exists on the `global` cluster or is stuck terminating. |

For provider failures that also apply after installation, see [Troubleshooting VMware vSphere Workload Clusters](../../../workload_clusters/alauda_os/vmware-vsphere/troubleshooting.mdx).
