# Create the global Cluster on VMware vSphere

## Prerequisites \{#prerequisites}

- You completed the [common prerequisites](../prerequisites.mdx) and the [VMware vSphere prerequisites](./prerequisites.mdx).
- The Core Package is extracted on the bootstrap node and its payload is in the external registry; see [Prepare the Core Package and the Registry](../prerequisites.mdx#prepare-core-package).
- For a disaster recovery pair, write both files as described in [Disaster Recovery](../disaster_recovery.mdx#configure-install-config), then run this procedure on each side.

## Procedure

### 1. Write `install-config.yaml` \{#install-config}

Create an installation directory on the bootstrap node and write `install-config.yaml` in it. The fields are described in [Parameters](./reference/install-config-parameters.mdx); the VM size, additional NICs, raw disks, data disk placement, and per-group overrides are optional and listed there.

```yaml title="install-config.yaml"
global:
  registry:
    address: <host>:<port> # [!code callout]
    username: <user> # [!code callout]
    password: <password>
  platform:
    address: <platform-domain-or-ip> # [!code callout]
    username: admin@cpaas.io # [!code callout]
    password: <password> # [!code callout]
    extraAddresses: [] # [!code callout]

cluster: # [!code callout]
  sshKeys: # [!code callout]
    - <ssh-public-key>
  ntpServers: [] # [!code callout]
  network:
    loadBalancer:
      type: external # [!code callout]
      address: <control-plane-vip> # [!code callout]
      port: 6443
      # vrid: <vrid> # [!code callout]

provider:
  vsphere:
    server: <vcenter-address> # [!code callout]
    credential: # [!code callout]
      username: <administrator@vsphere.local>
      password: <password>
    datacenter: <datacenter> # [!code callout]
    template: <template-name-or-path> # [!code callout]
    datastore: <datastore> # [!code callout]
    computeResource: <cluster-or-host> # [!code callout]
    releaseDelayHours: 24 # [!code callout]
    network: # [!code callout]
      name: <portgroup-name> # [!code callout]

controlPlane:
  replicas: 3 # [!code callout]
  network:
    gateway: <cp-gateway> # [!code callout]
    dns: [<dns-ip>] # [!code callout]
    mask: <prefix-length> # [!code callout]
  disks:
    ephemeral: # [!code callout]
      - name: var-lib-containerd
        sizeGiB: 100
      - name: var-lib-kubelet
        sizeGiB: 100
      - name: var-lib-etcd # [!code callout]
        sizeGiB: 20
    persistent: # [!code callout]
      - name: var-cpaas
        sizeGiB: 100
  hosts: # [!code callout]
    - hostname: <cp-0-hostname>
      ip: <cp-0-ip>
    - hostname: <cp-1-hostname>
      ip: <cp-1-ip>
    - hostname: <cp-2-hostname>
      ip: <cp-2-ip>

computes: # [!code callout]
  - name: worker
    replicas: 3
    network:
      gateway: <worker-gateway>
      dns: [<dns-ip>]
      mask: <prefix-length>
    disks:
      ephemeral: # [!code callout]
        - name: var-lib-containerd
          sizeGiB: 100
        - name: var-lib-kubelet
          sizeGiB: 100
      persistent:
        - name: var-cpaas
          sizeGiB: 100
    hosts:
      - hostname: <worker-0-hostname>
        ip: <worker-0-ip>
      - hostname: <worker-1-hostname>
        ip: <worker-1-ip>
      - hostname: <worker-2-hostname>
        ip: <worker-2-ip>
```

<Callouts>

1. `registry.address`: required. The external registry as `<host>[:<port>]`, without a scheme or `/v2/`.
2. `registry.username` and `registry.password`: optional. Set both or neither.
3. `platform.address`: required. The platform access address, without a scheme or port. Disaster recovery requires a domain name.
4. `platform.username`: defaults to `admin@cpaas.io`.
5. `platform.password`: required. 8 to 32 characters, mixing letters, digits, and symbols.
6. `extraAddresses`: optional. List the control plane VIP to open the console on it. Required for disaster recovery, where each side lists its own VIP.
7. Do not set `clusterName`: `ac` names the cluster `global`.
8. `sshKeys`: required. The SSH public keys installed on every node.
9. `ntpServers`: optional. Empty keeps the image's time configuration.
10. `type`: `external`, the default, or `internal`. The mode cannot be changed after the cluster exists.
11. `address`: required. The control plane VIP, or the load balancer address for `external`: an IPv4 address that is not a node address and is outside the Pod, Service, and join CIDRs.
12. `vrid`: required for `internal`, from 1 to 255. Omit it for `external`.
13. `server`: required. The vCenter address.
14. `credential`: required. The vCenter account.
15. `datacenter`: required. The datacenter name. Use an inventory path, such as `/folder/dc`, only when you do not set `computeResource`.
16. `template`: required. The VM template every node is cloned from, by name or inventory path.
17. `datastore`: required. The datastore for the VMs and, by default, their disks.
18. `computeResource`: the name of the DRS cluster or standalone host, not an inventory path. Required when the datacenter has more than one.
19. `releaseDelayHours`: optional. How many hours a released pool slot keeps its persistent disks before they are deleted.
20. `network`: the primary NIC of every node.
21. `name`: required. A port group or distributed port group.
22. `replicas`: an odd number, `1` or `3` or more. With fewer than three control plane nodes, contact technical support before you upgrade the cluster.
23. `gateway`: required.
24. `dns`: required. Every entry is used.
25. `mask`: required. A prefix length from 1 to 32.
26. `ephemeral`: disks recreated with the VM.
27. `var-lib-etcd`: control plane only.
28. `persistent`: disks kept when the VM is replaced.
29. `hosts`: required. At least `replicas` entries.
30. `computes`: optional. Without workers, the platform runs on the control plane nodes.
31. Workers have no `var-lib-etcd`.

</Callouts>

### 2. Create the Cluster \{#create}

On the bootstrap node:

```bash
<extract-dir>/res/<arch>/ac adm alpha global create --dir <install-dir> --provider vsphere
```

`ac` first checks the CPI image in the Core Package, the vCenter sign-in, and the vCenter objects named in `install-config.yaml`. If a check fails, nothing is changed and the error names the first missing item. `ac` does not check an `external` load balancer.

`create` returns when the installation is complete. If `create` stops, run the same command again; completed work is skipped. See [The `create` Command](../reference.mdx#create-command).

### 3. Monitor the Installation \{#monitor}

From another terminal on the bootstrap node:

```bash
<extract-dir>/res/<arch>/ac adm alpha global status
```

For the stages and common failures, see [Troubleshooting](../troubleshooting.mdx); for VMware vSphere failures, see [Troubleshooting on VMware vSphere](./troubleshooting.mdx).

## Verification

When `create` returns, the installation is complete. Keep `<install-dir>`: it holds `output/kubeconfig` and the logs. Verify the platform as described in [Validation](../../validation.mdx), including its [checks for Alauda OS](../../validation.mdx#alauda-os-checks).
