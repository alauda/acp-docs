# Prerequisites for VMware vSphere

Complete the [common prerequisites](../prerequisites.mdx) first. Prepare the following in vCenter. `ac` creates none of them; its preflight checks look them up before anything changes on the bootstrap node, and stop at the first one that is missing.

- **A vCenter account.** Preflight reads the certificate fingerprint that vCenter presents and signs in with the account. The same account is used by the vSphere cloud provider (CPI); you do not supply a second one. The account must be able to read the inventory, and to clone, power, reconfigure, and delete VMs and their disks. When custom attributes are in use, it also needs the privileges in [Install the VMware vSphere Provider](../../../workload_clusters/alauda_os/vmware-vsphere/reference/install_provider.mdx#prerequisites).
- **A VM template created from the Alauda OS image**, by name or inventory path. It must carry the Kubernetes version of the Core Package; see [OS Support Matrix](../../../overview/alauda_os_support_matrix.mdx) and [VM template requirements](../../../workload_clusters/alauda_os/vmware-vsphere/prerequisites.mdx#vm-template-requirements).
- **The datacenter, the datastore, and the port group** of the primary NIC, and the port group of each additional NIC if you use them.
- **The VM folder**, if you set `folder`.
- **The compute resource**: the DRS cluster or standalone host the VMs run on. It is required when the datacenter has more than one.
- **Static IPv4 addresses and hostnames** for every node, with the gateway, prefix length, and DNS servers of each network.
- **A control plane endpoint.** With `external`, the default, your load balancer forwards `TCP/443`, `TCP/6443`, and `TCP/11443` to the control plane nodes, plus `TCP/80` when users access the platform over HTTP and `TCP/2379` for disaster recovery. With `internal`, the provider runs the VIP on the control plane nodes with Alive, whose artifact is in the Core Package: reserve an unused IPv4 address in the control plane Layer 2 domain and a `vrid` that no other VRRP instance in it uses. The network must allow VRRP (IP protocol `112`, multicast `224.0.0.18`) and gratuitous ARP between the control plane nodes.
- **The bootstrap node and the `global` nodes reach vCenter on `TCP/443`.** The provider on the bootstrap node clones the VMs, and the CPI on the `global` nodes keeps talking to vCenter after installation.
