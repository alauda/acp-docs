# Prerequisites for VMware vSphere

Complete the [common prerequisites](../prerequisites.mdx) first, then prepare the following in VMware vSphere. `ac` creates none of them.

- **A vCenter account** that can read the inventory, and clone, power, reconfigure, and delete VMs and their disks. The vSphere cloud provider (CPI) uses the same account.
- **A VM template created from the Alauda OS image**, by name or inventory path. It must carry the Kubernetes version of the Core Package; see [OS Support Matrix](../../../overview/alauda_os_support_matrix.mdx) and [VM template requirements](../../../workload_clusters/alauda_os/vmware-vsphere/prerequisites.mdx#vm-template-requirements).
- **The datacenter, the datastore, and the port group** of the primary NIC, and the port group of each additional NIC if you use them.
- **The VM folder**, if you set `folder`.
- **The compute resource**: the DRS cluster or standalone host the VMs run on. It is required when the datacenter has more than one.
- **Static IPv4 addresses and hostnames** for every node, with the gateway, prefix length, and DNS servers of each network.
- **A control plane endpoint.** With `external`, the default, your load balancer forwards `TCP/443`, `TCP/6443`, and `TCP/11443` to the control plane nodes, plus `TCP/80` when users access the platform over HTTP and `TCP/2379` for disaster recovery. With `internal`, the provider runs the VIP on the control plane nodes: reserve an unused IPv4 address in the control plane Layer 2 domain and a `vrid` that no other VRRP instance in it uses. The network must allow VRRP (IP protocol `112`, multicast `224.0.0.18`) and gratuitous ARP between the control plane nodes. See [Plan the Control Plane Endpoint](../../../workload_clusters/alauda_os/prepare/control-plane-endpoint.mdx).
- **The bootstrap node and the `global` nodes reach vCenter on `TCP/443`.**
