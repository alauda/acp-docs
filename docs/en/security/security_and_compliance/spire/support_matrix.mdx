# Supported Capabilities

This page lists the ACP SPIRE capabilities available for ACP 4.4 and later.
The exact plugin version is selected from the ACP Marketplace.

## Applicability

| Item | Value |
| --- | --- |
| ACP versions | `4.4 and later` |
| Default trust domain | `demo.org` |
| StorageClass | Supplied by the target ACP environment |

Use the component set delivered by the same ACP plugin release when reproducing
a test; do not mix components from different releases.

## Supported capabilities

| Area | Supported capability |
| --- | --- |
| Delivery | Install the SPIRE Server, Controller Manager, Agent, SPIFFE CSI Driver and OIDC Discovery Provider through the ACP SPIRE ModulePlugin. |
| Registration | Register workloads with `ClusterSPIFFEID` selectors and SPIFFE ID templates. |
| Identity | Obtain X.509-SVIDs through the Workload API and a SPIFFE SDK or equivalent client. |
| CSI | Expose the Workload API socket through the `csi.spiffe.io` ephemeral CSI volume. |
| mTLS | Establish service-to-service mTLS and authorize an exact peer SPIFFE ID. |
| Negative authorization | Reject an unregistered or differently identified workload. |
| Rotation | Refresh short-lived SVIDs and establish new connections after renewal. |
| Recovery | Recover workload identity after Server, Agent and CSI Driver restarts. |
| Persistence | Store the Server datastore on a PVC and validate a tested backup/restore procedure. |
| Operations | Check component health, metrics, logs, registration status and common fault scenarios. |

## Configuration boundary

- Single ACP cluster.
- X.509-SVID as the documented workload credential.
- Kubernetes PSAT node attestation and Kubernetes workload attestation.
- Dedicated ServiceAccounts, narrow selectors and an explicit trust domain.
- Workload identity delivered through the Workload API socket.
- StorageClass selected according to the target ACP environment.
