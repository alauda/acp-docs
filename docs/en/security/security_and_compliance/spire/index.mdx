# SPIRE Workload Identity

<Overview overviewHeaders={[]} />

SPIRE provides cryptographically verifiable identities for applications running
on <Term name="productShort" /> clusters. It lets a workload obtain a
short-lived X.509-SVID through the Workload API and use that identity for mutual
TLS (mTLS), without manually copying certificates or distributing private keys
in Kubernetes Secrets.

## Recommended path

1. Read [Overview](./overview.mdx) to learn what SPIRE provides.
2. Follow [Installation](./installation.mdx) to install the ACP SPIRE plugin.
3. Follow [Workload Identity](./workload_identity.mdx) to register a workload
   and expose the Workload API socket.
4. Follow [Application mTLS](./mtls.mdx) to configure service-to-service
   authentication and peer authorization.
5. Use [Validation](./validation.mdx) to run the acceptance checks.
6. Use [Lifecycle and Recovery](./lifecycle.mdx), [Observability](./observability.mdx)
   and [Troubleshooting](./troubleshooting.mdx) for operations.

The supported ACP path is a single-cluster deployment using X.509-SVIDs. The
default trust domain is `demo.org`; the StorageClass is selected for each ACP
environment.
