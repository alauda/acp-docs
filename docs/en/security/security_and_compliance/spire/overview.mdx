# Overview

SPIRE is the runtime that verifies nodes and workloads, then issues SPIFFE
Verifiable Identity Documents (SVIDs). ACP uses X.509-SVIDs for workload
authentication. The SPIFFE ID is carried in the certificate URI Subject
Alternative Name (SAN).

## What SPIRE provides

- Automatic workload identity through the SPIFFE Workload API.
- Short-lived X.509-SVIDs and trust bundles.
- Identity renewal without manually copying certificates.
- Workload registration based on namespace, ServiceAccount and pod selectors.
- A CSI-based way to expose the Workload API socket to a pod.
- Identity-based mTLS when the application or proxy verifies the peer SPIFFE ID.

## ACP supported scope

ACP provides a single-cluster SPIRE deployment through the SPIRE ModulePlugin.
The supported application patterns are:

- An application uses a SPIFFE SDK or equivalent client to fetch an X.509-SVID
  from the Workload API.
- An application or proxy uses the CSI Driver to access the Workload API socket
  and obtain its identity.
- Two services establish mTLS and the receiving service authorizes the expected
  SPIFFE ID.
- An unauthorized service is rejected by the receiving service.

This documentation applies to ACP 4.4 and later. The exact SPIRE plugin version
is selected from the ACP Marketplace and is managed as part of the ACP release.

## Key concepts

| Term | Meaning |
| --- | --- |
| SPIFFE | The identity standard used to describe workloads. |
| SPIRE | The runtime that verifies workloads and issues SVIDs. |
| SVID | A verifiable identity document issued to a workload. |
| X.509-SVID | An X.509 certificate containing a SPIFFE ID in its URI SAN. |
| Trust domain | The root namespace of SPIFFE IDs. ACP defaults to `demo.org`. |
| Workload API | The local API used by a workload to fetch its SVID and trust bundle. |
| Workload attestation | Verification of the workload's runtime attributes before identity is issued. |

## Components

| Component | Responsibility |
| --- | --- |
| SPIRE Server | Stores registration data and issues SVIDs and trust bundles. |
| SPIRE Agent | Runs on each node, verifies workloads and serves the Workload API. |
| Controller Manager | Converts `ClusterSPIFFEID` resources into SPIRE registration entries. |
| SPIFFE CSI Driver | Exposes the Agent Workload API socket through an ephemeral CSI volume. |
| OIDC Discovery Provider | Provides the discovery component included in the chart. The documented ACP workload path uses X.509-SVID. |

## Using SPIRE with applications

SPIRE provides workload identity and trust material. The application, proxy or
gateway must still decide which peer is authorized and how traffic is routed.
SPIRE does not replace ACP user authentication, RBAC, NetworkPolicy, application
authorization, audit or image security.
